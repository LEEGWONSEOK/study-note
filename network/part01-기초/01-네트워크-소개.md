# Chapter 1. 네트워크란 무엇인가

## 1.1 네트워크의 정의

**네트워크(Network)**는 컴퓨터나 기기들이 서로 연결되어 데이터를 주고받는 시스템입니다.

### 비유: 네트워크는 도로망과 같습니다

```
집 (컴퓨터 A) ─────도로─────► 회사 (컴퓨터 B)
                 (네트워크)
```

- **도로**: 네트워크 케이블/WiFi
- **자동차**: 데이터 패킷
- **주소**: IP 주소
- **교통 규칙**: 네트워크 프로토콜

---

## 1.2 웹개발자는 왜 네트워크를 알아야 할까?

### 실제 상황들

#### 상황 1: API 호출이 느려요
```javascript
// 프론트엔드 코드
const response = await fetch('https://api.example.com/users');
// 왜 3초나 걸리지? 🤔
```

**네트워크 지식이 있다면:**
- DNS 조회 시간 확인
- HTTP 헤더의 캐시 설정 확인
- CDN 활용 여부 체크
- HTTP/2 사용 여부 확인

#### 상황 2: CORS 에러
```
Access to fetch at 'https://api.example.com' from origin
'http://localhost:3000' has been blocked by CORS policy
```

**네트워크 지식이 있다면:**
- CORS가 무엇인지 이해
- Origin, Host 헤더 이해
- Preflight 요청 이해
- 서버 설정으로 해결

#### 상황 3: 배포 후 접속 안 됨
```bash
# 로컬에서는 되는데...
curl http://localhost:3000  # ✅ OK

# 배포 후
curl http://my-server.com   # ❌ Connection refused
```

**네트워크 지식이 있다면:**
- 방화벽/보안 그룹 설정 확인
- 포트 개방 여부 확인
- DNS 설정 확인
- 네트워크 경로 추적

#### 상황 4: 데이터베이스 연결 실패
```javascript
// Lambda 함수에서 RDS 연결 시도
const connection = await mysql.createConnection({
  host: 'my-db.xxxxx.rds.amazonaws.com',
  user: 'admin',
  password: 'password'
});
// Error: Can't connect to MySQL server
```

**네트워크 지식이 있다면:**
- VPC와 서브넷 이해
- 보안 그룹 규칙 확인
- 프라이빗/퍼블릭 서브넷 구분
- 네트워크 ACL 체크

## 1.3 네트워크의 종류

### 규모에 따른 분류

```
┌─────────────────────────────────────────────────┐
│  LAN (Local Area Network)                       │
│  - 사무실, 집 안의 네트워크                        │
│  - 범위: ~1km                                    │
│  - 속도: 매우 빠름 (1Gbps~10Gbps)                 │
│  - 예: 회사 내부망, 집 WiFi                       │
│                                                 │
│  ┌─────┐   ┌─────┐   ┌─────┐                   │
│  │ PC1 │───│ PC2 │───│ PC3 │                   │
│  └─────┘   └─────┘   └─────┘                   │
└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│  WAN (Wide Area Network)                        │
│  - 도시, 국가 간 네트워크                         │
│  - 범위: 수십~수천 km                            │
│  - 속도: 상대적으로 느림                          │
│  - 예: 인터넷, 기업 본사-지사 연결                 │
│                                                 │
│  [서울 지사] ─────인터넷─────► [부산 지사]        │
└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│  Internet (인터넷)                               │
│  - 전 세계 네트워크의 네트워크                      │
│  - WAN들이 연결된 거대한 네트워크                   │
│                                                 │
│  🌐 전 세계 모든 컴퓨터가 연결                     │
└─────────────────────────────────────────────────┘
```

### 웹개발자 관점에서 중요한 것

```
개발 환경: localhost (내 PC)
         ↓
테스트 서버: 사내망 LAN
         ↓
운영 서버: 인터넷 WAN
```

## 1.4 클라이언트-서버 모델

웹은 **클라이언트-서버 모델**로 동작합니다.

### 기본 구조

```
┌──────────────┐                    ┌──────────────┐
│   클라이언트   │                    │    서버       │
│              │                    │              │
│  - 브라우저   │    요청 (Request)   │  - 웹서버     │
│  - 모바일앱   │───────────────────►│  - API서버    │
│  - Postman   │                    │  - DB서버     │
│              │    응답 (Response)  │              │
│              │◄───────────────────│              │
└──────────────┘                    └──────────────┘
```

### 실제 예시: 네이버 접속

```
1. 브라우저 주소창에 www.naver.com 입력

2. [클라이언트] DNS 서버에 "naver.com의 IP 주소가 뭐죠?" 질문
   └─► DNS 서버: "223.130.195.95 입니다"

3. [클라이언트] 223.130.195.95 서버에 요청 전송
   GET / HTTP/1.1
   Host: www.naver.com

4. [서버] HTML 파일을 응답
   HTTP/1.1 200 OK
   Content-Type: text/html

   <!DOCTYPE html>
   <html>...네이버 메인 페이지...</html>

5. [클라이언트] HTML을 렌더링하여 화면에 표시
```

### 웹개발에서의 클라이언트-서버

```javascript
// 클라이언트 (React)
const LoginPage = () => {
  const handleLogin = async () => {
    // 서버에 요청 전송
    const response = await fetch('https://api.example.com/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ email, password })
    });

    // 서버로부터 응답 받기
    const data = await response.json();
  };
};
```

```javascript
// 서버 (Node.js/Express)
app.post('/login', async (req, res) => {
  const { email, password } = req.body;

  // DB 확인
  const user = await User.findOne({ email });

  // 클라이언트에게 응답 전송
  res.json({
    token: 'jwt-token-here',
    user: { id: user.id, name: user.name }
  });
});
```

## 1.5 데이터는 어떻게 전송될까?

### 패킷(Packet) 개념

데이터는 **작은 조각(패킷)**으로 나뉘어 전송됩니다.

**비유: 택배 배송**

```
큰 짐(데이터) = 여러 개의 택배 상자(패킷)로 나눔

┌─────────────────────────────────────┐
│   전송할 데이터 (100MB 동영상)        │
└─────────────────────────────────────┘
              ↓ 분할
┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐
│패킷1│ │패킷2│ │패킷3│ │패킷4│ │패킷5│
└────┘ └────┘ └────┘ └────┘ └────┘
각 1500 bytes (일반적인 패킷 크기)
```

### 패킷의 구조

```
┌──────────────────────────────────────────┐
│              패킷 (Packet)                │
├──────────────────────────────────────────┤
│  Header (헤더)                            │
│  - 출발지 IP: 192.168.0.10               │
│  - 목적지 IP: 13.209.84.49               │
│  - 포트 번호                              │
│  - 순서 번호 등                           │
├──────────────────────────────────────────┤
│  Data (데이터)                            │
│  - 실제 전송할 내용                        │
│  - 예: JSON, HTML, 이미지 조각             │
└──────────────────────────────────────────┘
```

**비유: 편지 봉투**
- **헤더** = 봉투에 적힌 받는 사람 주소, 보내는 사람 주소
- **데이터** = 봉투 안의 편지 내용

### 패킷이 여러 경로로 전송되는 예시

```
[클라이언트]                              [서버]
    │                                      │
    ├─ 패킷1 ─► 라우터A ─► 라우터C ────────►│
    ├─ 패킷2 ─► 라우터B ─► 라우터D ────────►│
    └─ 패킷3 ─► 라우터A ─► 라우터E ────────►│
                                           │
                                  패킷 순서대로 재조립
                                     패킷3, 패킷1, 패킷2
                                           ↓
                                     원본 데이터 복원
```

## 1.6 프로토콜(Protocol)이란?

**프로토콜**은 네트워크에서 데이터를 주고받는 **규칙**입니다.

### 비유: 외교 프로토콜

```
사람들이 소통하는 규칙:
- 한국: 악수, 인사말 "안녕하세요"
- 일본: 고개 숙여 인사

컴퓨터가 소통하는 규칙:
- HTTP: 웹 페이지 전송 규칙
- TCP: 신뢰성 있는 데이터 전송 규칙
- IP: 주소 체계와 라우팅 규칙
```

### 주요 프로토콜

| 프로토콜 | 용도 | 예시 |
|---------|------|------|
| **HTTP** | 웹 페이지, API 통신 | `http://example.com` |
| **HTTPS** | 암호화된 웹 통신 | `https://example.com` |
| **TCP** | 신뢰성 있는 데이터 전송 | 파일 다운로드, 이메일 |
| **UDP** | 빠른 데이터 전송 | 실시간 스트리밍, 게임 |
| **IP** | 인터넷 주소 체계 | `192.168.0.1` |
| **DNS** | 도메인 이름 해석 | `naver.com` → IP 변환 |
| **FTP** | 파일 전송 | 서버에 파일 업로드 |
| **SMTP** | 이메일 전송 | Gmail 발송 |
| **WebSocket** | 실시간 양방향 통신 | 채팅, 알림 |

### 프로토콜 스택 (계층 구조)

```
┌─────────────────────────────────────┐
│  Application Layer (응용 계층)       │
│  - HTTP, HTTPS, DNS, FTP            │
│  - 웹개발자가 주로 다루는 영역         │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  Transport Layer (전송 계층)         │
│  - TCP, UDP                         │
│  - 데이터 전송 보장                   │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  Internet Layer (인터넷 계층)        │
│  - IP                               │
│  - 주소 지정, 라우팅                  │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  Network Access Layer (네트워크 접근) │
│  - Ethernet, WiFi                   │
│  - 물리적 데이터 전송                 │
└─────────────────────────────────────┘
```

## 1.7 웹 요청의 전체 과정

브라우저에서 `https://www.example.com/api/users` 접속 시:

```
┌──────────────────────────────────────────────────────┐
│ 1. URL 파싱                                          │
│    - 프로토콜: https                                 │
│    - 도메인: www.example.com                         │
│    - 경로: /api/users                                │
└──────────────────────────────────────────────────────┘
                      ↓
┌──────────────────────────────────────────────────────┐
│ 2. DNS 조회                                          │
│    www.example.com → 93.184.216.34                  │
│                                                      │
│    [브라우저] → [DNS 서버]                            │
│    "example.com의 IP 주소는?"                         │
│    [DNS 서버] → [브라우저]                            │
│    "93.184.216.34 입니다"                            │
└──────────────────────────────────────────────────────┘
                      ↓
┌──────────────────────────────────────────────────────┐
│ 3. TCP 연결 (3-way handshake)                        │
│                                                      │
│    [클라이언트]              [서버]                   │
│         │─── SYN ──────────►│                       │
│         │◄── SYN+ACK ───────│                       │
│         │─── ACK ──────────►│                       │
│         │                   │                       │
│        연결 수립 완료!                                │
└──────────────────────────────────────────────────────┘
                      ↓
┌──────────────────────────────────────────────────────┐
│ 4. HTTPS인 경우: TLS/SSL 핸드셰이크                    │
│    - 서버 인증서 확인                                 │
│    - 암호화 키 교환                                   │
│    - 암호화 통신 시작                                 │
└──────────────────────────────────────────────────────┘
                      ↓
┌──────────────────────────────────────────────────────┐
│ 5. HTTP 요청 전송                                     │
│                                                      │
│    GET /api/users HTTP/1.1                           │
│    Host: www.example.com                             │
│    User-Agent: Mozilla/5.0...                        │
│    Accept: application/json                          │
│    Cookie: session_id=abc123                         │
└──────────────────────────────────────────────────────┘
                      ↓
┌──────────────────────────────────────────────────────┐
│ 6. 서버 처리                                          │
│    - 라우팅: /api/users 엔드포인트 찾기                │
│    - 인증: Cookie 검증                                │
│    - 비즈니스 로직 실행                                │
│    - DB 조회: SELECT * FROM users                    │
└──────────────────────────────────────────────────────┘
                      ↓
┌──────────────────────────────────────────────────────┐
│ 7. HTTP 응답 전송                                     │
│                                                      │
│    HTTP/1.1 200 OK                                   │
│    Content-Type: application/json                    │
│    Content-Length: 1234                              │
│    Cache-Control: max-age=3600                       │
│                                                      │
│    [{"id":1,"name":"John"},{"id":2,"name":"Jane"}]   │
└──────────────────────────────────────────────────────┘
                      ↓
┌──────────────────────────────────────────────────────┐
│ 8. 브라우저 렌더링                                     │
│    - JSON 파싱                                       │
│    - JavaScript 실행                                 │
│    - DOM 업데이트                                    │
│    - 화면에 사용자 목록 표시                           │
└──────────────────────────────────────────────────────┘
```

### 각 단계별 소요 시간 예시

```
DNS 조회:        20ms
TCP 연결:        50ms
TLS 핸드셰이크:   100ms
HTTP 요청/응답:   200ms
────────────────────────
총 소요 시간:     370ms
```

**최적화 포인트:**
- DNS: DNS 캐싱, CDN 사용
- TCP: Keep-Alive 연결 재사용
- TLS: TLS 1.3 사용, 세션 재사용
- HTTP: HTTP/2, 압축, 캐싱

## 1.8 네트워크 성능 지표

### 1. 지연시간 (Latency)

데이터가 출발지에서 목적지까지 가는 데 걸리는 시간

```
[클라이언트] ──── 100ms ────► [서버]

낮을수록 좋음!
- 국내 서버: 10-50ms
- 미국 서버: 150-200ms
- 호주 서버: 250-300ms
```

**웹개발 예시:**
```javascript
// Latency가 높으면 사용자 경험 저하
console.time('API 호출');
const response = await fetch('https://api.example.com/data');
console.timeEnd('API 호출');
// Latency 높음: API 호출: 500ms  ← 느림!
// Latency 낮음: API 호출: 50ms   ← 빠름!
```

### 2. 대역폭 (Bandwidth)

단위 시간당 전송할 수 있는 데이터 양

```
좁은 대역폭 (10Mbps):   |──|
넓은 대역폭 (100Mbps):  |──────────|

높을수록 좋음!
```

**비유:**
- **Latency** = 택배가 도착하는 데 걸리는 시간 (거리와 관련)
- **Bandwidth** = 한 번에 실을 수 있는 택배 상자 개수 (트럭 크기)

### 3. 처리량 (Throughput)

실제로 전송되는 데이터 양 (현실적인 속도)

```
Bandwidth (이론):   100Mbps
Throughput (실제):  80Mbps  ← 네트워크 혼잡, 손실 등으로 감소
```

### 4. 패킷 손실 (Packet Loss)

전송 중 손실되는 패킷 비율

```
전송: 100개 패킷
도착: 98개 패킷
손실: 2% ← 낮을수록 좋음
```

## 1.9 웹개발자가 네트워크를 이해하면 좋은 점

### 1. 성능 최적화

```javascript
// Before: 네트워크 지식 부족
// 매번 API 호출 → 느림
const getUser = async (id) => {
  const response = await fetch(`/api/users/${id}`);
  return response.json();
};

// After: 캐싱 활용
const getUser = async (id) => {
  const cached = localStorage.getItem(`user_${id}`);
  if (cached) return JSON.parse(cached);

  const response = await fetch(`/api/users/${id}`, {
    headers: {
      'Cache-Control': 'max-age=3600' // 1시간 캐싱
    }
  });
  const user = await response.json();
  localStorage.setItem(`user_${id}`, JSON.stringify(user));
  return user;
};
```

### 2. 디버깅 능력 향상

```
문제: "API가 안 돼요!"

네트워크 지식 없는 개발자:
"백엔드 팀이 뭔가 잘못한 것 같은데요..."

네트워크 지식 있는 개발자:
1. Chrome DevTools Network 탭 확인
2. 상태 코드: 404 → 잘못된 URL
3. 상태 코드: 401 → 인증 토큰 문제
4. 상태 코드: 500 → 서버 에러 (백엔드 확인 필요)
5. 상태 코드: 0, ERR_CONNECTION_REFUSED → 서버 다운/방화벽
```

### 3. 보안 이슈 대응

```javascript
// 보안 취약: HTTP로 비밀번호 전송
fetch('http://api.example.com/login', {
  method: 'POST',
  body: JSON.stringify({ password: '1234' })
});
// → 네트워크에서 비밀번호가 평문으로 노출!

// 보안 강화: HTTPS 사용
fetch('https://api.example.com/login', {
  method: 'POST',
  body: JSON.stringify({ password: '1234' })
});
// → 암호화되어 안전하게 전송
```

### 4. 아키텍처 설계

```
네트워크 지식 없이 설계:
[프론트엔드] ─────► [백엔드] ─────► [DB]
                   모든 트래픽이 백엔드로 집중 → 병목!

네트워크 지식으로 개선:
[프론트엔드] ─────► [CDN] ─────► [정적 파일]
     │
     └─────────► [로드밸런서] ─────► [백엔드1]
                                   ├─► [백엔드2]
                                   └─► [백엔드3]
                                         │
                                         └─► [DB (Private 서브넷)]
```

## 1.10 실습 환경 준비

### 필수 도구

#### 1. Chrome DevTools (Network 탭)

```
Chrome 브라우저에서:
1. F12 키 또는 우클릭 → 검사
2. Network 탭 선택
3. 웹사이트 새로고침
4. 모든 네트워크 요청 확인 가능!
```

**확인 가능한 정보:**
- 요청 URL
- HTTP 메서드 (GET, POST 등)
- 상태 코드 (200, 404 등)
- 응답 시간
- 요청/응답 헤더
- 요청/응답 본문

#### 2. curl (커맨드라인 HTTP 클라이언트)

```bash
# 기본 GET 요청
curl https://api.github.com/users/github

# 헤더 포함 출력
curl -i https://api.github.com/users/github

# POST 요청
curl -X POST https://api.example.com/login \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"1234"}'
```

#### 3. ping (네트워크 연결 테스트)

```bash
# 서버 응답 시간 확인
ping google.com

# 결과:
# 64 bytes from 142.250.207.46: icmp_seq=0 time=35.2 ms
# → Latency가 35.2ms
```

#### 4. traceroute (경로 추적)

```bash
# 패킷이 지나가는 경로 확인
traceroute google.com

# 결과: 내 PC → 여러 라우터 → Google 서버까지 경로 표시
```

## 핵심 요약

### 1. 네트워크 = 컴퓨터 간 통신 시스템
도로망처럼 데이터가 이동하는 경로

### 2. 클라이언트-서버 모델
웹의 기본! 브라우저(클라이언트)가 서버에 요청 → 서버가 응답

### 3. 패킷
데이터는 작은 조각으로 나뉘어 전송 (택배 상자처럼)

### 4. 프로토콜
컴퓨터 간 통신 규칙 (HTTP, TCP, IP 등)

### 5. 웹 요청 과정
DNS 조회 → TCP 연결 → HTTP 요청 → 서버 처리 → HTTP 응답

### 6. 성능 지표
- **Latency**: 지연 시간 (낮을수록 좋음)
- **Bandwidth**: 대역폭 (높을수록 좋음)

### 7. 웹개발자에게 네트워크 지식이 중요한 이유
- 성능 최적화
- 디버깅
- 보안
- 아키텍처 설계
