# Chapter 5. 포트와 소켓

## 5.1 포트(Port)란?

**포트**는 같은 IP 주소 내에서 **서로 다른 서비스나 애플리케이션을 구분**하는 번호입니다.

### 비유: 아파트 호수

```
IP 주소 = 아파트 주소
"서울시 강남구 테헤란로 123"
    ↓
같은 주소(IP)에 여러 집(서비스)

192.168.0.10:80      ← 101호 (웹 서버)
192.168.0.10:22      ← 102호 (SSH)
192.168.0.10:3306    ← 103호 (MySQL)
192.168.0.10:6379    ← 104호 (Redis)
```

---

## 5.2 포트 번호 범위

### 전체 범위

```
0 ~ 65535 (2^16 = 65,536개)

16비트로 표현
```

### 분류

```
┌──────────────────────────────────────────────┐
│  Well-Known Ports (잘 알려진 포트)            │
│  0 ~ 1023                                    │
│  - 표준 서비스용                              │
│  - root 권한 필요                             │
│  - IANA가 관리                                │
│                                              │
│  예: 80(HTTP), 443(HTTPS), 22(SSH)           │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│  Registered Ports (등록된 포트)               │
│  1024 ~ 49151                                │
│  - 특정 서비스/애플리케이션용                  │
│  - 등록 가능                                  │
│                                              │
│  예: 3000(Node.js), 3306(MySQL), 5432(PostgreSQL) │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│  Dynamic/Private Ports (동적/사설 포트)        │
│  49152 ~ 65535                               │
│  - 클라이언트가 임시로 사용                     │
│  - 자동 할당                                  │
│                                              │
│  예: 54321, 60123 (임시 포트)                 │
└──────────────────────────────────────────────┘
```

## 5.3 주요 Well-Known 포트 ⭐ 암기 필수!

### 웹개발 필수 포트

```
┌──────┬─────────────┬──────────────────────────┐
│ 포트  │  프로토콜    │  용도                     │
├──────┼─────────────┼──────────────────────────┤
│  20  │  FTP        │  FTP 데이터 전송          │
│  21  │  FTP        │  FTP 제어                │
│  22  │  SSH        │  원격 접속 (보안)         │
│  23  │  Telnet     │  원격 접속 (비보안)       │
│  25  │  SMTP       │  이메일 전송              │
│  53  │  DNS        │  도메인 이름 해석         │
│  80  │  HTTP       │  웹 (평문)               │
│ 110  │  POP3       │  이메일 수신              │
│ 143  │  IMAP       │  이메일 수신 (고급)       │
│ 443  │  HTTPS      │  웹 (암호화)             │
│ 465  │  SMTPS      │  이메일 전송 (SSL)        │
│ 587  │  SMTP       │  이메일 전송 (TLS)        │
│ 993  │  IMAPS      │  IMAP (SSL)              │
│ 995  │  POP3S      │  POP3 (SSL)              │
│3306  │  MySQL      │  MySQL 데이터베이스       │
│5432  │  PostgreSQL │  PostgreSQL 데이터베이스  │
│6379  │  Redis      │  Redis 캐시              │
│27017 │  MongoDB    │  MongoDB 데이터베이스     │
│3000  │  Node.js    │  개발 서버 (관례)         │
│8080  │  HTTP Alt   │  대체 HTTP 포트          │
└──────┴─────────────┴──────────────────────────┘
```

### 암기 팁

```
웹 기본:
80 (HTTP) + 363 = 443 (HTTPS)

데이터베이스:
MySQL: 3306 (MySQL의 M = 3, SQL = 306)
PostgreSQL: 5432 (PostgreSQL → 5, 4, 3, 2)
MongoDB: 27017 (2+7+0+1+7 = 17)
Redis: 6379 (MERZ 키보드 배치)

개발:
3000, 8000, 8080 (관례)
```

## 5.6 소켓(Socket)이란?

**소켓**은 **네트워크 통신의 끝점(Endpoint)**입니다.

### 정의

```
소켓 = IP 주소 + 포트 번호 + 프로토콜

예:
TCP 소켓: 192.168.0.10:54321 (TCP)
UDP 소켓: 192.168.0.10:54322 (UDP)
```

### 비유: 전화기

```
전화기 = 소켓
전화번호 = IP 주소 + 포트
통화 = 데이터 전송

전화 걸기 = 소켓 연결
통화하기 = 데이터 송수신
전화 끊기 = 소켓 종료
```

## 5.7 소켓 프로그래밍 기초

### TCP 소켓 생명주기

```
[서버]                          [클라이언트]

1. socket() - 소켓 생성
   ↓
2. bind() - IP:Port에 바인딩
   ↓
3. listen() - 연결 대기
   │                            1. socket() - 소켓 생성
   │                               ↓
   │                            2. connect() - 연결 요청
   │                               │
4. accept() ◄─── 연결 수립 ─────────┘
   ↓                               ↓
5. recv()/send() ◄───────────► recv()/send()
   데이터 송수신                    데이터 송수신
   ↓                               ↓
6. close() - 소켓 종료 ◄────────► close()
```

### Node.js TCP 소켓 예시

```javascript
// TCP 서버
const net = require('net');

const server = net.createServer((socket) => {
  console.log('클라이언트 연결됨');

  // 데이터 수신
  socket.on('data', (data) => {
    console.log('받은 데이터:', data.toString());

    // 에코 (그대로 돌려보내기)
    socket.write(`Echo: ${data}`);
  });

  // 연결 종료
  socket.on('end', () => {
    console.log('클라이언트 연결 종료');
  });
});

// IP:Port에 바인딩
server.listen(8080, '0.0.0.0', () => {
  console.log('서버 시작: 0.0.0.0:8080');
});
```

```javascript
// TCP 클라이언트
const net = require('net');

const client = net.createConnection({ port: 8080 }, () => {
  console.log('서버 연결됨');

  // 데이터 전송
  client.write('Hello Server!');
});

// 데이터 수신
client.on('data', (data) => {
  console.log('서버 응답:', data.toString());
  client.end(); // 연결 종료
});

client.on('end', () => {
  console.log('서버 연결 종료');
});
```

## 5.8 WebSocket ⭐ 웹개발 필수!

### HTTP vs WebSocket

```
HTTP (단방향):
[클라이언트] ─── 요청 ───► [서버]
[클라이언트] ◄── 응답 ─── [서버]
(연결 종료)

WebSocket (양방향):
[클라이언트] ◄──────────► [서버]
        지속적인 연결 유지
        실시간 양방향 통신
```

### WebSocket 연결 과정

```
1. HTTP로 시작 (Upgrade 요청)
   GET /chat HTTP/1.1
   Upgrade: websocket
   Connection: Upgrade

2. 서버 응답 (101 Switching Protocols)
   HTTP/1.1 101 Switching Protocols
   Upgrade: websocket
   Connection: Upgrade

3. WebSocket 프로토콜로 전환
   ↓
   지속적인 양방향 통신
```

### WebSocket 클라이언트

```javascript
// 프론트엔드
const socket = new WebSocket('wss://chat.example.com');

// 연결 성공
socket.onopen = () => {
  console.log('WebSocket 연결됨');

  // 메시지 전송
  socket.send(JSON.stringify({
    type: 'join',
    user: 'Alice'
  }));
};

// 메시지 수신
socket.onmessage = (event) => {
  const data = JSON.parse(event.data);
  console.log('받은 메시지:', data);

  // 채팅 메시지 표시
  displayMessage(data.user, data.message);
};

// 에러 처리
socket.onerror = (error) => {
  console.error('WebSocket 에러:', error);
};

// 연결 종료
socket.onclose = () => {
  console.log('WebSocket 연결 종료');
};
```

### WebSocket 서버 (Node.js)

```javascript
const WebSocket = require('ws');

const wss = new WebSocket.Server({ port: 8080 });

// 연결된 모든 클라이언트
const clients = new Set();

wss.on('connection', (ws) => {
  console.log('새 클라이언트 연결');
  clients.add(ws);

  // 메시지 수신
  ws.on('message', (message) => {
    console.log('받은 메시지:', message);

    const data = JSON.parse(message);

    // 모든 클라이언트에게 브로드캐스트
    clients.forEach((client) => {
      if (client.readyState === WebSocket.OPEN) {
        client.send(JSON.stringify({
          user: data.user,
          message: data.message,
          timestamp: Date.now()
        }));
      }
    });
  });

  // 연결 종료
  ws.on('close', () => {
    console.log('클라이언트 연결 종료');
    clients.delete(ws);
  });
});

console.log('WebSocket 서버 시작: ws://localhost:8080');
```

## 5.9 포트 관련 문제 해결

### 문제 1: "Port already in use" (EADDRINUSE)

```bash
# 에러 메시지
Error: listen EADDRINUSE: address already in use :::3000

# 원인: 포트 3000이 이미 사용 중

# 해결 방법 1: 사용 중인 프로세스 찾기
# macOS/Linux
lsof -i :3000

# Windows
netstat -ano | findstr :3000

# 출력 예시:
# node    12345  user   23u  IPv6  ... TCP *:3000 (LISTEN)
#         ↑ PID

# 프로세스 종료
kill 12345  # macOS/Linux
taskkill /PID 12345 /F  # Windows
```

```javascript
// 해결 방법 2: 다른 포트 사용
const PORT = process.env.PORT || 3000;

app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
}).on('error', (err) => {
  if (err.code === 'EADDRINUSE') {
    console.log(`포트 ${PORT}이 사용 중입니다. 다른 포트를 시도합니다.`);
    app.listen(PORT + 1);
  }
});
```

### 문제 2: 방화벽에 막힌 포트

```bash
# Linux 방화벽(firewall) 포트 열기
sudo ufw allow 3000/tcp

# 특정 IP만 허용
sudo ufw allow from 192.168.0.0/24 to any port 3000

# 방화벽 상태 확인
sudo ufw status
```

## 5.11 보안: 포트 스캐닝과 방어

### 포트 스캐닝

```bash
# nmap으로 열린 포트 확인
nmap -p 1-1000 example.com

# 출력 예시:
# PORT     STATE    SERVICE
# 22/tcp   open     ssh
# 80/tcp   open     http
# 443/tcp  open     https
# 3306/tcp open     mysql  ← 위험! 외부 노출

# 특정 포트만 스캔
nmap -p 80,443,3000 example.com
```

### 방어 전략

```
1. 최소 권한 원칙
   - 필요한 포트만 열기
   - 불필요한 서비스 중지

2. 방화벽 설정
   - 화이트리스트 방식
   - 특정 IP만 허용

3. 내부 서비스는 로컬호스트만
   - DB는 127.0.0.1에만 바인딩
   - 외부 접근 차단

4. VPN/Bastion Host 사용
   - SSH는 VPN 통해서만
   - Jump Server 활용
```

### 안전한 포트 바인딩

```javascript
// 나쁜 예: 모든 인터페이스에 바인딩
app.listen(3306, '0.0.0.0');  // ❌ 외부 접근 가능!

// 좋은 예: localhost만
app.listen(3306, '127.0.0.1');  // ✅ 로컬만 접근

// 프로덕션 예시
const express = require('express');
const app = express();

if (process.env.NODE_ENV === 'production') {
  // 프로덕션: 로드밸런서와만 통신
  app.listen(3000, '127.0.0.1');
} else {
  // 개발: 외부 접근 허용 (테스트용)
  app.listen(3000, '0.0.0.0');
}
```

## 5.12 클라우드 환경에서 포트 관리

### AWS 보안 그룹

```
보안 그룹 = 가상 방화벽

인바운드 규칙:
┌──────────┬──────┬──────────┬──────────────┐
│   타입    │ 포트  │ 프로토콜  │   소스        │
├──────────┼──────┼──────────┼──────────────┤
│  HTTP    │  80  │   TCP    │ 0.0.0.0/0    │ ← 전체 공개
│  HTTPS   │ 443  │   TCP    │ 0.0.0.0/0    │ ← 전체 공개
│  SSH     │  22  │   TCP    │ 123.45.67.0/24│ ← 특정 IP만
│  MySQL   │ 3306 │   TCP    │ sg-app123     │ ← 특정 보안그룹만
└──────────┴──────┴──────────┴──────────────┘

아웃바운드 규칙:
보통 전체 허용 (0.0.0.0/0)
```

### 계층별 포트 분리

```
┌─────────────────────────────────────────┐
│  Internet                               │
└────────────┬────────────────────────────┘
             ↓ 80, 443
┌─────────────────────────────────────────┐
│  Public Subnet                          │
│  ┌──────────────────────────────────┐   │
│  │  Load Balancer                   │   │
│  │  포트: 80, 443                    │   │
│  └──────────────┬───────────────────┘   │
```

## 핵심 요약

### 포트 (Port)

```
- 같은 IP에서 서비스를 구분하는 번호
- 범위: 0 ~ 65535
- Well-Known: 0~1023 (HTTP:80, HTTPS:443)
- Registered: 1024~49151 (MySQL:3306)
- Dynamic: 49152~65535 (임시 포트)
```

### 소켓 (Socket)

```
- 네트워크 통신의 끝점
- 소켓 = IP + Port + 프로토콜
- TCP 소켓: 연결 지향, 신뢰성
- UDP 소켓: 비연결, 빠름
```

### WebSocket

```
- 실시간 양방향 통신
- HTTP로 시작 → WebSocket으로 업그레이드
- 채팅, 알림, 실시간 데이터에 사용
```

### 보안

```
- 필요한 포트만 열기
- DB는 로컬호스트 바인딩
- 방화벽/보안 그룹 설정
- 포트 스캐닝 방어
```

### 과제 2: 간단한 채팅 앱 만들기

```javascript
// WebSocket으로 실시간 채팅 구현

// 서버 (server.js)
const WebSocket = require('ws');
const wss = new WebSocket.Server({ port: 8080 });

wss.on('connection', (ws) => {
  ws.on('message', (message) => {
    // 모든 클라이언트에게 브로드캐스트
    wss.clients.forEach((client) => {
      if (client.readyState === WebSocket.OPEN) {
        client.send(message);
      }
    });
  });
});

// 클라이언트 (index.html)
// WebSocket 연결하여 메시지 주고받기
```

### 과제 3: 포트 충돌 해결

```javascript
// 여러 포트를 시도하는 서버

const app = require('express')();

function startServer(port) {
  app.listen(port)
    .on('listening', () => {
      console.log(`✅ 서버 시작: http://localhost:${port}`);
    })
    .on('error', (err) => {
      if (err.code === 'EADDRINUSE') {
        console.log(`❌ 포트 ${port} 사용 중, ${port + 1} 시도`);
        startServer(port + 1);
      }
    });
}

startServer(3000);
```
