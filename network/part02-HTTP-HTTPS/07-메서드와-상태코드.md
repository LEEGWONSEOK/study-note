# Chapter 7. HTTP 메서드와 상태코드

## 7.1 HTTP 메서드 심화

### 멱등성(Idempotent)이란?

**멱등성**: 같은 요청을 여러 번 해도 결과가 동일

```
비유: 전등 스위치

멱등성 O:
"전등을 켜라" → 몇 번을 눌러도 결과는 "켜짐"

멱등성 X:
"전등 토글" → 누를 때마다 켜짐/꺼짐 변경
```

### 안전성(Safe)이란?

**안전성**: 서버 상태를 변경하지 않음

```
안전한 메서드:
GET, HEAD, OPTIONS
→ 읽기만 함, 서버 데이터 변경 ❌

안전하지 않은 메서드:
POST, PUT, PATCH, DELETE
→ 서버 데이터 변경 ✅
```

## 7.2 GET - 조회 ⭐

### 특징

```
✅ 안전 (Safe)
✅ 멱등 (Idempotent)
✅ 캐시 가능
❌ Body 없음 (쿼리 파라미터 사용)
```

### 기본 사용

```javascript
// 단일 조회
fetch('/api/users/123')
  .then(res => res.json())
  .then(user => console.log(user));

// 목록 조회
fetch('/api/users')
  .then(res => res.json())
  .then(users => console.log(users));
```

### 쿼리 파라미터 (Query Parameters)

```javascript
// 필터링
fetch('/api/users?role=admin&status=active')

// 페이지네이션
fetch('/api/users?page=2&limit=10')

// 정렬
fetch('/api/users?sort=name&order=asc')

// 검색
fetch('/api/users?search=john&field=name')

// 복합 조건
const params = new URLSearchParams({
  role: 'admin',
  status: 'active',
  page: '1',
  limit: '20',
  sort: 'created_at',
  order: 'desc'
});

fetch(`/api/users?${params}`)
```

### GET 요청 캐싱

```javascript
// Express.js 서버에서 캐시 헤더 설정
app.get('/api/users/:id', (req, res) => {
  const user = findUser(req.params.id);

  // 1시간 캐싱
  res.set('Cache-Control', 'public, max-age=3600');
  res.json(user);
});

// 조건부 요청 (304 Not Modified)
app.get('/api/users', (req, res) => {
  const users = getAllUsers();
  const etag = generateETag(users);

  // 클라이언트가 보낸 ETag와 비교
  if (req.headers['if-none-match'] === etag) {
    return res.status(304).send(); // 캐시 사용
  }

  res.set('ETag', etag);
  res.json(users);
});
```

### GET의 한계와 주의사항

```javascript
// ❌ 나쁜 예: URL에 민감한 정보
fetch('/api/users?password=secret123')
// → URL은 브라우저 히스토리, 로그에 남음!

// ✅ 좋은 예: POST로 전송
fetch('/api/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ password: 'secret123' })
});

// ❌ 나쁜 예: GET으로 삭제
fetch('/api/users/delete/123')  // 절대 안 됨!

// ✅ 좋은 예: DELETE 메서드
fetch('/api/users/123', { method: 'DELETE' })
```

## 7.3 POST - 생성 ⭐

### 특징

```
❌ 안전하지 않음 (서버 상태 변경)
❌ 멱등 아님 (매번 새 리소스 생성)
✅ Body에 데이터 전송
❌ 캐시 불가
```

### 기본 사용

```javascript
// JSON 데이터 전송
const newUser = {
  name: 'John Doe',
  email: 'john@example.com',
  age: 30
};

fetch('/api/users', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(newUser)
})
  .then(res => {
    console.log(res.status); // 201 Created
    console.log(res.headers.get('Location')); // /api/users/123
    return res.json();
  })
  .then(user => console.log(user));
```

### 서버 구현

```javascript
app.post('/api/users', (req, res) => {
  // 1. 유효성 검증
  const { name, email, age } = req.body;

  if (!name || !email) {
    return res.status(400).json({
      error: 'Name and email are required'
    });
  }

  if (!isValidEmail(email)) {
    return res.status(400).json({
      error: 'Invalid email format'
    });
  }

  // 2. 중복 체크
  const existing = findUserByEmail(email);
  if (existing) {
    return res.status(409).json({
      error: 'Email already exists'
    });
  }

  // 3. 생성
  const user = createUser({ name, email, age });

  // 4. 201 Created + Location 헤더
  res.status(201)
     .location(`/api/users/${user.id}`)
     .json(user);
});
```

### POST 멱등성 이슈

```javascript
// 문제: 중복 클릭으로 여러 번 생성
button.addEventListener('click', () => {
  fetch('/api/orders', {
    method: 'POST',
    body: JSON.stringify({ product_id: 1, quantity: 1 })
  });
  // 사용자가 빠르게 2번 클릭 → 주문 2개 생성! ❌
});

// 해결 1: 버튼 비활성화
button.addEventListener('click', async () => {
  button.disabled = true;

  try {
    await fetch('/api/orders', {
      method: 'POST',
      body: JSON.stringify({ product_id: 1, quantity: 1 })
    });
  } finally {
    button.disabled = false;
  }
});

// 해결 2: 멱등성 키 (Idempotency Key)
const idempotencyKey = generateUUID();

fetch('/api/orders', {
  method: 'POST',
  headers: {
    'Idempotency-Key': idempotencyKey
  },
  body: JSON.stringify({ product_id: 1, quantity: 1 })
});
```

```javascript
// 서버: 멱등성 키 처리
const processedKeys = new Set();

app.post('/api/orders', (req, res) => {
  const key = req.headers['idempotency-key'];

  if (processedKeys.has(key)) {
    // 이미 처리된 요청
    return res.status(200).json({ message: 'Already processed' });
  }

  // 새 요청 처리
  const order = createOrder(req.body);
  processedKeys.add(key);

  res.status(201).json(order);
});
```

## 7.4 PUT - 전체 수정 ⭐

### 특징

```
❌ 안전하지 않음
✅ 멱등 (같은 요청 반복해도 결과 동일)
✅ 전체 리소스 교체
✅ 없으면 생성 가능 (Upsert)
```

### 기본 사용

```javascript
// 사용자 전체 정보 업데이트
const updatedUser = {
  name: 'John Updated',
  email: 'john.new@example.com',
  age: 31,
  role: 'admin'
};

fetch('/api/users/123', {
  method: 'PUT',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(updatedUser)
});
```

### PUT의 전체 교체 특성

```javascript
// 원본 데이터
{
  id: 123,
  name: 'John',
  email: 'john@example.com',
  age: 30,
  role: 'user',
  created_at: '2024-01-01'
}

// PUT 요청 (일부 필드만 전송)
fetch('/api/users/123', {
  method: 'PUT',
  body: JSON.stringify({
    name: 'John Updated',
    email: 'john.new@example.com'
  })
});

// 결과: 나머지 필드는 null/삭제됨!
{
  id: 123,
  name: 'John Updated',
  email: 'john.new@example.com',
  age: null,        // ❌ 사라짐!
  role: null,       // ❌ 사라짐!
  created_at: null  // ❌ 사라짐!
}
```

### 서버 구현

```javascript
app.put('/api/users/:id', (req, res) => {
  const id = parseInt(req.params.id);
  const user = findUser(id);

  if (!user) {
    // 없으면 생성 (Upsert)
    const newUser = createUser({ id, ...req.body });
    return res.status(201)
              .location(`/api/users/${id}`)
              .json(newUser);
  }

  // 전체 교체 (모든 필드 업데이트)
  const updated = {
    id: user.id,
    name: req.body.name,
    email: req.body.email,
    age: req.body.age,
    role: req.body.role,
    created_at: user.created_at  // 유지할 필드는 명시적으로
  };

  updateUser(id, updated);
  res.json(updated);
});
```

### PUT 멱등성

```javascript
// 같은 PUT 요청을 여러 번 해도 결과 동일

// 1번째 요청
PUT /api/users/123
{
  name: 'John Updated',
  email: 'john.new@example.com',
  age: 31
}
// 결과: name이 'John Updated'로 변경

// 2번째 요청 (동일)
PUT /api/users/123
{
  name: 'John Updated',
  email: 'john.new@example.com',
  age: 31
}
// 결과: name이 여전히 'John Updated' (변화 없음)
// → 멱등성 ✅
```

## 7.5 PATCH - 부분 수정 ⭐

### 특징

```
❌ 안전하지 않음
⚠️  멱등성 애매함 (구현에 따라 다름)
✅ 일부 필드만 수정
✅ 효율적
```

### 기본 사용

```javascript
// 이름만 수정 (나머지 필드는 그대로)
fetch('/api/users/123', {
  method: 'PATCH',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    name: 'John Updated'
  })
});

// 원본 데이터
{
  id: 123,
  name: 'John',
  email: 'john@example.com',
  age: 30,
  role: 'user'
}

// 결과: name만 변경, 나머지는 유지 ✅
{
  id: 123,
  name: 'John Updated',   // ← 변경됨
  email: 'john@example.com',  // ← 유지
  age: 30,                    // ← 유지
  role: 'user'                // ← 유지
}
```

### 서버 구현

```javascript
app.patch('/api/users/:id', (req, res) => {
  const id = parseInt(req.params.id);
  const user = findUser(id);

  if (!user) {
    return res.status(404).json({ error: 'User not found' });
  }

  // 보낸 필드만 업데이트
  const updated = { ...user };

  if (req.body.name !== undefined) {
    updated.name = req.body.name;
  }

  if (req.body.email !== undefined) {
    updated.email = req.body.email;
  }

  if (req.body.age !== undefined) {
    updated.age = req.body.age;
  }

  updateUser(id, updated);
  res.json(updated);
});
```

### JSON Patch (RFC 6902)

```javascript
// 표준 JSON Patch 형식
fetch('/api/users/123', {
  method: 'PATCH',
  headers: {
    'Content-Type': 'application/json-patch+json'
  },
  body: JSON.stringify([
    { op: 'replace', path: '/name', value: 'John Updated' },
    { op: 'add', path: '/phone', value: '010-1234-5678' },
    { op: 'remove', path: '/temp_field' }
  ])
});
```

### PUT vs PATCH 비교

```javascript
// 원본 데이터
{
  id: 123,
  name: 'John',
  email: 'john@example.com',
  age: 30
}

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// PUT: 전체 교체 (모든 필드 전송 필요)
PUT /api/users/123
{
  name: 'John Updated',
  email: 'john@example.com',  // 변경 안 해도 보내야 함
  age: 30                     // 변경 안 해도 보내야 함
}

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// PATCH: 부분 수정 (변경할 필드만 전송)
PATCH /api/users/123
{
  name: 'John Updated'  // 이것만!
}
```

## 7.6 DELETE - 삭제 ⭐

### 특징

```
❌ 안전하지 않음
✅ 멱등 (삭제된 리소스 다시 삭제해도 결과 동일)
❌ Body 보통 없음
✅ 204 No Content 반환 권장
```

### 기본 사용

```javascript
// 삭제
fetch('/api/users/123', {
  method: 'DELETE'
})
  .then(res => {
    if (res.status === 204) {
      console.log('삭제 성공');
    }
  });
```

### 서버 구현

```javascript
app.delete('/api/users/:id', (req, res) => {
  const id = parseInt(req.params.id);
  const user = findUser(id);

  if (!user) {
    // 이미 없음 → 204 (멱등성 유지)
    return res.status(204).send();
  }

  deleteUser(id);
  res.status(204).send();  // Body 없음
});

// 또는 200 OK + 삭제된 리소스 반환
app.delete('/api/users/:id', (req, res) => {
  const id = parseInt(req.params.id);
  const user = findUser(id);

  if (!user) {
    return res.status(404).json({ error: 'User not found' });
  }

  deleteUser(id);
  res.status(200).json(user);  // 삭제된 데이터 반환
});
```

### Soft Delete (논리적 삭제)

```javascript
// Hard Delete: DB에서 실제 삭제
DELETE /api/users/123
→ DB에서 완전히 삭제 (복구 불가)

// Soft Delete: deleted_at 플래그만 설정
PATCH /api/users/123
{
  deleted_at: '2024-01-15T10:00:00Z'
}
→ DB에는 남아있음 (복구 가능)
```

```javascript
// Soft Delete 구현
app.delete('/api/users/:id', (req, res) => {
  const id = parseInt(req.params.id);
  const user = findUser(id);

  if (!user) {
    return res.status(404).json({ error: 'User not found' });
  }

  // 실제 삭제 대신 deleted_at만 설정
  user.deleted_at = new Date();
  updateUser(id, user);

  res.status(204).send();
});

// 조회 시 deleted_at이 null인 것만
app.get('/api/users', (req, res) => {
  const users = getAllUsers().filter(u => !u.deleted_at);
  res.json(users);
});
```

### DELETE 멱등성

```javascript
// 1번째 DELETE
DELETE /api/users/123
→ 200 OK (삭제 성공)

// 2번째 DELETE (같은 리소스)
DELETE /api/users/123
→ 204 No Content (이미 없지만 성공)
// 또는 404 Not Found

// 결과는 동일: 리소스 없음
// → 멱등성 ✅
```

## 7.8 HTTP 상태코드 심화

### 2xx: 성공

#### 200 OK
```javascript
// 일반적인 성공
GET /api/users/123
→ 200 OK + 사용자 데이터

PUT /api/users/123
→ 200 OK + 업데이트된 데이터
```

#### 201 Created
```javascript
// 리소스 생성 성공
POST /api/users
→ 201 Created
Location: /api/users/123
```

#### 202 Accepted
```javascript
// 요청 접수, 처리 중 (비동기)
POST /api/jobs
→ 202 Accepted
{
  "job_id": "abc123",
  "status": "processing",
  "estimated_time": "5 minutes"
}

// 나중에 결과 확인
GET /api/jobs/abc123
→ 200 OK
{
  "job_id": "abc123",
  "status": "completed",
  "result": {...}
}
```

#### 204 No Content
```javascript
// 성공했지만 응답 본문 없음
DELETE /api/users/123
→ 204 No Content

PUT /api/settings
→ 204 No Content
```

#### 206 Partial Content
```javascript
// 범위 요청 (동영상 스트리밍)
GET /videos/movie.mp4
Range: bytes=0-1023

→ 206 Partial Content
Content-Range: bytes 0-1023/1000000
```

### 3xx: 리다이렉션

#### 301 Moved Permanently
```javascript
// 영구 이동 (SEO에 영향)
GET /old-page
→ 301 Moved Permanently
Location: /new-page
```

```javascript
// Express.js
app.get('/old-page', (req, res) => {
  res.redirect(301, '/new-page');
});
```

#### 302 Found
```javascript
// 임시 이동
GET /login
→ 302 Found
Location: /auth/google
```

#### 304 Not Modified
```javascript
// 캐시 유효 (재전송 불필요)
GET /api/users
If-None-Match: "abc123"

→ 304 Not Modified
// 브라우저 캐시 사용
```

#### 307 Temporary Redirect / 308 Permanent Redirect
```javascript
// 301/302와 유사하지만 메서드 유지 보장
POST /old-api
→ 307 Temporary Redirect
Location: /new-api
// POST 메서드 그대로 /new-api로 재전송
```

### 4xx: 클라이언트 에러

#### 400 Bad Request
```javascript
// 잘못된 요청
POST /api/users
{
  "name": "",  // ❌ 빈 값
  "email": "invalid-email"  // ❌ 형식 오류
}

→ 400 Bad Request
{
  "errors": [
    { "field": "name", "message": "Name is required" },
    { "field": "email", "message": "Invalid email format" }
  ]
}
```

#### 401 Unauthorized
```javascript
// 인증 필요 (로그인 안 함)
GET /api/profile

→ 401 Unauthorized
WWW-Authenticate: Bearer
{
  "error": "Authentication required"
}
```

#### 403 Forbidden
```javascript
// 권한 없음 (인증은 됐지만 접근 불가)
DELETE /api/admin/users/123

→ 403 Forbidden
{
  "error": "Admin access required"
}
```

#### 404 Not Found
```javascript
// 리소스 없음
GET /api/users/999999

→ 404 Not Found
{
  "error": "User not found"
}
```

#### 405 Method Not Allowed
```javascript
// 허용되지 않은 메서드
POST /api/users/123  // PUT이나 PATCH 사용해야 함

→ 405 Method Not Allowed
Allow: GET, PUT, DELETE
```

## 7.9 실전 패턴

### RESTful API 전체 예시

```javascript
// CRUD 전체 구현
const express = require('express');
const app = express();
app.use(express.json());

let users = [];
let nextId = 1;

// CREATE
app.post('/api/users', (req, res) => {
  const { name, email } = req.body;

  if (!name || !email) {
    return res.status(400).json({
      error: 'Name and email are required'
    });
  }

  const user = {
    id: nextId++,
    name,
    email,
    created_at: new Date()
  };

  users.push(user);

  res.status(201)
     .location(`/api/users/${user.id}`)
     .json(user);
});

// READ (목록)
app.get('/api/users', (req, res) => {
  const { page = 1, limit = 10 } = req.query;
  const start = (page - 1) * limit;
  const end = start + parseInt(limit);

  res.json({
    data: users.slice(start, end),
    page: parseInt(page),
    limit: parseInt(limit),
    total: users.length
  });
});

// READ (단일)
app.get('/api/users/:id', (req, res) => {
  const user = users.find(u => u.id === parseInt(req.params.id));

  if (!user) {
    return res.status(404).json({ error: 'User not found' });
  }

  res.json(user);
});

// UPDATE (전체)
app.put('/api/users/:id', (req, res) => {
  const id = parseInt(req.params.id);
  const index = users.findIndex(u => u.id === id);

  if (index === -1) {
    return res.status(404).json({ error: 'User not found' });
  }

  users[index] = {
    id,
    ...req.body,
    updated_at: new Date()
  };

  res.json(users[index]);
});

// UPDATE (부분)
app.patch('/api/users/:id', (req, res) => {
  const id = parseInt(req.params.id);
  const user = users.find(u => u.id === id);

  if (!user) {
    return res.status(404).json({ error: 'User not found' });
  }

  Object.assign(user, req.body, { updated_at: new Date() });
  res.json(user);
});

// DELETE
app.delete('/api/users/:id', (req, res) => {
  const id = parseInt(req.params.id);
  const index = users.findIndex(u => u.id === id);

  if (index === -1) {
    return res.status(204).send();  // 멱등성 유지
  }

  users.splice(index, 1);
  res.status(204).send();
});

app.listen(3000);
```

## 핵심 요약

### HTTP 메서드

```
GET:    조회 (안전, 멱등, 캐시 가능)
POST:   생성 (비멱등)
PUT:    전체 수정 (멱등)
PATCH:  부분 수정 (멱등*)
DELETE: 삭제 (멱등)
```

### 주요 상태코드

```
2xx: 성공
- 200 OK, 201 Created, 204 No Content

3xx: 리다이렉션
- 301 Moved Permanently, 304 Not Modified

4xx: 클라이언트 에러
- 400 Bad Request, 401 Unauthorized, 403 Forbidden
- 404 Not Found, 409 Conflict, 429 Too Many Requests

5xx: 서버 에러
- 500 Internal Server Error, 502 Bad Gateway
- 503 Service Unavailable
```
