# Chapter 28. 브라우저 렌더링 과정

## 28.1 렌더링 개요

### 정의

```
브라우저 렌더링:
HTML, CSS, JS를 화면에 그리는 과정

비유: 집 짓기
┌──────────────────────────────────┐
│ HTML → 설계도 (구조)              │
│ CSS → 인테리어 (스타일)           │
│ JS → 전기/수도 (동작)             │
│ 렌더링 → 실제 집 완성             │
└──────────────────────────────────┘
```

### 전체 흐름

```
1. HTML 파싱 → DOM 트리 생성
2. CSS 파싱 → CSSOM 트리 생성
3. DOM + CSSOM → Render 트리 생성
4. Layout (Reflow): 위치/크기 계산
5. Paint: 실제 픽셀로 그리기
6. Composite: 레이어 합성
```

---

## 28.2 Critical Rendering Path

### 단계별 상세

```
Critical Rendering Path (CRP):
첫 화면을 그리기까지의 과정

1. HTML 다운로드
   ↓
2. HTML 파싱 → DOM
   ↓
3. CSS 다운로드
   ↓
4. CSS 파싱 → CSSOM
   ↓
5. Render Tree 생성
   ↓
6. Layout (위치/크기)
   ↓
7. Paint (픽셀)
   ↓
8. Composite (합성)
   ↓
9. 화면 표시 ✅
```

### DOM 생성

```html
<!DOCTYPE html>
<html>
  <head>
    <title>Example</title>
  </head>
  <body>
    <div id="app">
      <h1>Hello</h1>
      <p>World</p>
    </div>
  </body>
</html>
```

```
DOM 트리:
html
├─ head
│  └─ title
│     └─ "Example"
└─ body
   └─ div#app
      ├─ h1
      │  └─ "Hello"
      └─ p
         └─ "World"
```

### CSSOM 생성

```css
body {
  font-size: 16px;
  color: #333;
}

#app {
  max-width: 1200px;
  margin: 0 auto;
}

h1 {
  font-size: 32px;
  color: #000;
}
```

```
CSSOM 트리:
body
├─ font-size: 16px
├─ color: #333
└─ #app
   ├─ max-width: 1200px
   ├─ margin: 0 auto
   └─ h1
      ├─ font-size: 32px (상속 덮어쓰기)
      └─ color: #000
```

## 28.3 렌더 트리 생성

### Render Tree

```
DOM + CSSOM = Render Tree

특징:
- 화면에 보이는 요소만 포함
- display: none은 제외
- head, script도 제외

예시:
<div style="display: none">숨김</div>
→ Render Tree에 포함 안 됨

<div style="visibility: hidden">투명</div>
→ Render Tree에 포함됨 (공간 차지)
```

### 예시

```html
<body>
  <div id="header">Header</div>
  <div id="hidden" style="display: none">Hidden</div>
  <div id="main">
    <p>Content</p>
  </div>
</body>
```

```
Render Tree:
body
├─ div#header
│  └─ "Header"
└─ div#main
   └─ p
      └─ "Content"

(div#hidden은 제외됨)
```

## 28.4 Layout (Reflow)

### 정의

```
Layout (Reflow):
각 요소의 위치와 크기 계산

비유: 가구 배치
┌────────────────────────────┐
│ 거실 3m × 4m               │
│ → 소파 위치: (1m, 2m)      │
│ → 소파 크기: 2m × 1m       │
└────────────────────────────┘
```

### Layout 계산

```css
.container {
  width: 1000px;
}

.sidebar {
  width: 30%;  /* → 300px */
  float: left;
}

.content {
  width: 70%;  /* → 700px */
  float: left;
}
```

```
Layout 결과:
┌─────────────────────────────┐ 1000px
│ .sidebar │ .content         │
│  300px   │   700px          │
└─────────────────────────────┘
```

### Reflow 발생 상황

```javascript
// ❌ Reflow 4번 발생
const el = document.getElementById('box');
el.style.width = '100px';    // Reflow 1
el.style.height = '100px';   // Reflow 2
el.style.margin = '10px';    // Reflow 3
el.style.padding = '5px';    // Reflow 4

// ✅ Reflow 1번
el.style.cssText = `
  width: 100px;
  height: 100px;
  margin: 10px;
  padding: 5px;
`;

// ✅ Class로 한 번에
el.className = 'box-style';
```

### Reflow 비용이 큰 속성

```javascript
// Reflow 발생 (비용 높음):
width, height
margin, padding, border
top, left, right, bottom
font-size, font-family
line-height
display
position
float

// Repaint만 발생 (비용 낮음):
color
background-color
visibility
box-shadow
opacity
```

## 28.5 Paint

### 정의

```
Paint:
Layout 정보를 실제 픽셀로 그리기

레이어별로 그림:
- Background
- Border
- Text
- Image
...
```

### Paint 최적화

```css
/* ❌ Repaint 자주 발생 */
.box {
  background: red;
}

.box:hover {
  background: blue;  /* Repaint */
}

/* ✅ Transform 사용 (Composite만 발생) */
.box {
  background: red;
  transition: transform 0.3s;
}

.box:hover {
  transform: scale(1.1);  /* Composite만 (빠름) */
}
```

## 28.6 Composite (합성)

### 레이어 합성

```
Composite:
여러 레이어를 합쳐서 최종 화면 생성

레이어 생성 조건:
- transform
- opacity
- will-change
- filter
- video, canvas
```

### GPU 가속

```css
/* ✅ GPU 가속 활용 */
.animated {
  transform: translateZ(0);  /* 레이어 생성 */
  will-change: transform;    /* 브라우저에 힌트 */
}

.slide-in {
  animation: slideIn 0.3s ease;
}

@keyframes slideIn {
  from {
    transform: translateX(-100%);
  }
  to {
    transform: translateX(0);
  }
}
```

## 28.7 JavaScript 실행 타이밍

### Blocking vs Non-blocking

```html
<!-- ❌ Render Blocking -->
<head>
  <script src="app.js"></script>
  <!-- HTML 파싱 중단 → JS 다운로드 → JS 실행 → 파싱 재개 -->
</head>

<!-- ✅ Non-blocking: defer -->
<head>
  <script src="app.js" defer></script>
  <!-- 병렬 다운로드 → HTML 파싱 완료 → DOMContentLoaded 전에 실행 -->
</head>

<!-- ✅ Non-blocking: async -->
<head>
  <script src="analytics.js" async></script>
  <!-- 병렬 다운로드 → 다운로드 완료되면 즉시 실행 -->
</head>

<!-- ✅ Body 끝 -->
<body>
  ...
  <script src="app.js"></script>
</body>
```

### defer vs async

```
<script src="a.js"></script>
┌───────┐ 파싱 중단
│ 다운로드 │
└───────┘
   ↓
┌──────┐
│ 실행  │
└──────┘
   ↓
파싱 재개


<script src="a.js" defer></script>
┌───────┐
│ 파싱   │ (계속)
└───────┘
┌───────┐ (병렬)
│다운로드│
└───────┘
   ↓
파싱 완료
   ↓
┌──────┐
│ 실행  │ (DOMContentLoaded 전)
└──────┘


<script src="a.js" async></script>
┌───────┐
│ 파싱   │ (계속)
└───────┘
┌───────┐ (병렬)
│다운로드│
└───────┘
   ↓
┌──────┐ 다운로드 완료 즉시
│ 실행  │ (파싱 중단됨)
└──────┘
```

### 실전 사용

```html
<!DOCTYPE html>
<html>
<head>
  <!-- Critical CSS: 인라인 -->
  <style>
    body { margin: 0; font-family: sans-serif; }
    .hero { min-height: 100vh; }
  </style>

  <!-- Non-critical CSS: 지연 로드 -->
  <link rel="preload" href="styles.css" as="style" onload="this.onload=null;this.rel='stylesheet'">
  <noscript><link rel="stylesheet" href="styles.css"></noscript>

  <!-- 중요한 JS: defer -->
  <script src="app.js" defer></script>

  <!-- 분석 스크립트: async -->
  <script src="analytics.js" async></script>
</head>
<body>
  <div class="hero">...</div>
</body>
</html>
```

## 28.8 리소스 우선순위

### Preload, Prefetch, Preconnect

```html
<!-- Preload: 현재 페이지에서 곧 필요 -->
<link rel="preload" href="hero.jpg" as="image">
<link rel="preload" href="font.woff2" as="font" type="font/woff2" crossorigin>

<!-- Prefetch: 다음 페이지에서 필요 (낮은 우선순위) -->
<link rel="prefetch" href="/page2.html">

<!-- Preconnect: DNS, TCP, TLS 미리 연결 -->
<link rel="preconnect" href="https://api.example.com">

<!-- DNS-prefetch: DNS만 미리 조회 -->
<link rel="dns-prefetch" href="https://cdn.example.com">
```

### 실전 예시

```html
<!DOCTYPE html>
<html>
<head>
  <!-- 1. DNS 미리 조회 -->
  <link rel="dns-prefetch" href="https://fonts.googleapis.com">
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

  <!-- 2. Critical 폰트 preload -->
  <link rel="preload" href="https://fonts.gstatic.com/s/roboto/v30/KFOmCnqEu92Fr1Me5WZLCzYlKw.woff2" as="font" type="font/woff2" crossorigin>

  <!-- 3. Hero 이미지 preload -->
  <link rel="preload" href="/hero.jpg" as="image">

  <!-- 4. CSS -->
  <link rel="stylesheet" href="styles.css">

  <!-- 5. 다음 페이지 prefetch -->
  <link rel="prefetch" href="/about.html">
</head>
<body>
  <img src="/hero.jpg" alt="Hero">
</body>
</html>
```

## 28.9 Web Vitals

### Core Web Vitals

```
1. LCP (Largest Contentful Paint)
   가장 큰 콘텐츠가 그려지는 시간
   목표: 2.5초 이내

2. FID (First Input Delay)
   첫 입력 반응 시간
   목표: 100ms 이내

3. CLS (Cumulative Layout Shift)
   레이아웃 변경 누적
   목표: 0.1 이하
```

### LCP 최적화

```html
<!-- ❌ LCP 느림 -->
<img src="hero.jpg" loading="lazy">

<!-- ✅ LCP 빠름 -->
<link rel="preload" href="hero.jpg" as="image">
<img src="hero.jpg" fetchpriority="high">
```

```javascript
// LCP 측정
new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    console.log('LCP:', entry.renderTime || entry.loadTime);
  }
}).observe({ type: 'largest-contentful-paint', buffered: true });
```

### FID 최적화

```javascript
// ❌ 메인 스레드 블로킹 (50ms 이상)
function processData(data) {
  for (let i = 0; i < 1000000; i++) {
    // 무거운 연산
  }
}

// ✅ 작업 분할
function processDataChunked(data) {
  const chunkSize = 1000;
  let index = 0;

  function processChunk() {
    const end = Math.min(index + chunkSize, data.length);

    for (let i = index; i < end; i++) {
      // 연산
    }

    index = end;

    if (index < data.length) {
      setTimeout(processChunk, 0);  // 다음 이벤트 루프에
    }
  }

  processChunk();
}

// ✅ Web Worker 사용
const worker = new Worker('worker.js');
worker.postMessage(data);
worker.onmessage = (e) => {
  console.log('결과:', e.data);
};
```

## 28.10 렌더링 최적화 기법

### 1. CSS 최적화

```css
/* ❌ 복잡한 선택자 (느림) */
body div.container ul li a.link { }

/* ✅ 간단한 선택자 */
.nav-link { }

/* ❌ Universal selector */
* { margin: 0; }

/* ✅ 필요한 요소만 */
body, h1, h2, h3, p { margin: 0; }
```

### 2. 강제 동기 레이아웃 방지

```javascript
// ❌ Forced Synchronous Layout
const boxes = document.querySelectorAll('.box');

boxes.forEach(box => {
  box.style.width = box.offsetWidth + 10 + 'px';
  // offsetWidth 읽기 → Layout 계산
  // width 쓰기 → Layout 무효화
  // 반복 → 매번 Layout 계산 (느림)
});

// ✅ Read → Write 분리
const widths = [];

// 1. 읽기 (한 번에)
boxes.forEach(box => {
  widths.push(box.offsetWidth);
});

// 2. 쓰기 (한 번에)
boxes.forEach((box, i) => {
  box.style.width = widths[i] + 10 + 'px';
});
```

### 3. DocumentFragment 사용

```javascript
// ❌ DOM 반복 조작 (Reflow 여러 번)
const list = document.getElementById('list');

for (let i = 0; i < 1000; i++) {
  const li = document.createElement('li');
  li.textContent = `Item ${i}`;
  list.appendChild(li);  // Reflow 1000번
}

// ✅ DocumentFragment (Reflow 1번)
const fragment = document.createDocumentFragment();

for (let i = 0; i < 1000; i++) {
  const li = document.createElement('li');
  li.textContent = `Item ${i}`;
  fragment.appendChild(li);
}

list.appendChild(fragment);  // Reflow 1번
```

### 4. Virtual Scrolling

```javascript
// 1000개 항목 중 화면에 보이는 것만 렌더링
class VirtualList {
  constructor(container, items, itemHeight) {
    this.container = container;
    this.items = items;
    this.itemHeight = itemHeight;
    this.visibleCount = Math.ceil(container.clientHeight / itemHeight);

    this.render();
    this.container.addEventListener('scroll', () => this.render());
  }

  render() {
    const scrollTop = this.container.scrollTop;
    const startIndex = Math.floor(scrollTop / this.itemHeight);
    const endIndex = startIndex + this.visibleCount;

    // 보이는 항목만 렌더링
    const visibleItems = this.items.slice(startIndex, endIndex);

    this.container.innerHTML = `
      <div style="height: ${this.items.length * this.itemHeight}px; position: relative;">
        ${visibleItems.map((item, i) => `
          <div style="position: absolute; top: ${(startIndex + i) * this.itemHeight}px; height: ${this.itemHeight}px;">
            ${item}
          </div>
        `).join('')}
      </div>
    `;
  }
}

// 사용
const list = new VirtualList(
  document.getElementById('container'),
  Array.from({ length: 10000 }, (_, i) => `Item ${i}`),
  50
);
```

### 5. requestAnimationFrame

```javascript
// ❌ setTimeout으로 애니메이션
function animate() {
  box.style.left = parseInt(box.style.left || 0) + 1 + 'px';
  setTimeout(animate, 16);  // 60fps 시도
}

// ✅ requestAnimationFrame
function animate() {
  box.style.left = parseInt(box.style.left || 0) + 1 + 'px';
  requestAnimationFrame(animate);
  // 브라우저가 최적 타이밍에 실행
  // 탭이 백그라운드면 중단 (배터리 절약)
}

requestAnimationFrame(animate);
```
