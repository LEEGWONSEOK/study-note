# Chapter 23. 인증과 인가

## 23.1 인증 vs 인가

### 정의

```
인증 (Authentication):
"당신이 누구인지" 확인

인가 (Authorization):
"무엇을 할 수 있는지" 확인

비유: 공항 보안
┌────────────────────────────────┐
│ 1. 신분증 확인 (인증)           │
│    "당신은 홍길동이 맞나요?"    │
│                                │
│ 2. 탑승권 확인 (인가)           │
│    "비즈니스 라운지에 갈 수     │
│     있나요?"                   │
└────────────────────────────────┘
```

### 예시

```
인증 (Authentication):
- 로그인 (아이디 + 비밀번호)
- 지문 인식
- 2FA (Two-Factor Authentication)

인가 (Authorization):
- 관리자만 사용자 삭제 가능
- 본인 글만 수정 가능
- 유료 회원만 프리미엄 기능 사용
```

## 23.2 인증 (Authentication)

### 인증 방식

```
1. 지식 기반 (Something you know)
   - 비밀번호
   - PIN
   - 보안 질문

2. 소유 기반 (Something you have)
   - OTP
   - 스마트폰
   - 보안 토큰

3. 생체 기반 (Something you are)
   - 지문
   - 얼굴 인식
   - 홍채 인식
```

### 비밀번호 기반 인증

```javascript
const bcrypt = require('bcrypt');

// 회원가입: 비밀번호 해싱
async function signup(email, password) {
  // Salt 생성 (10 rounds)
  const saltRounds = 10;
  const hashedPassword = await bcrypt.hash(password, saltRounds);

  // DB 저장
  await User.create({
    email,
    password: hashedPassword
  });
}

// 로그인: 비밀번호 검증
async function login(email, password) {
  const user = await User.findOne({ where: { email } });

  if (!user) {
    throw new Error('사용자를 찾을 수 없습니다');
  }

  // 비밀번호 비교
  const isValid = await bcrypt.compare(password, user.password);

  if (!isValid) {
    throw new Error('비밀번호가 일치하지 않습니다');
  }

  return user;
}
```

### 비밀번호 보안 Best Practices

```javascript
// 1. 최소 길이 및 복잡도
function validatePassword(password) {
  const minLength = 8;
  const hasUpperCase = /[A-Z]/.test(password);
  const hasLowerCase = /[a-z]/.test(password);
  const hasNumber = /\d/.test(password);
  const hasSpecialChar = /[!@#$%^&*]/.test(password);

  if (password.length < minLength) {
    return '비밀번호는 최소 8자 이상이어야 합니다';
  }

  if (!hasUpperCase || !hasLowerCase || !hasNumber || !hasSpecialChar) {
    return '대문자, 소문자, 숫자, 특수문자를 모두 포함해야 합니다';
  }

  return null;
}

// 2. 흔한 비밀번호 차단
const commonPasswords = ['password', '123456', 'qwerty'];

function isCommonPassword(password) {
  return commonPasswords.includes(password.toLowerCase());
}

// 3. Rate Limiting (무차별 대입 공격 방지)
const loginAttempts = new Map();

function checkRateLimit(email) {
  const attempts = loginAttempts.get(email) || 0;

  if (attempts >= 5) {
    throw new Error('너무 많은 로그인 시도. 15분 후 다시 시도하세요');
  }

  loginAttempts.set(email, attempts + 1);

  setTimeout(() => {
    loginAttempts.delete(email);
  }, 15 * 60 * 1000);  // 15분
}
```

## 23.3 2FA (Two-Factor Authentication)

### 개념

```
2단계 인증:
1. 비밀번호 (지식 기반)
2. OTP (소유 기반)

→ 비밀번호 유출되어도 안전
```

### TOTP (Time-based OTP) 구현

```javascript
const speakeasy = require('speakeasy');
const QRCode = require('qrcode');

// 1. Secret 생성 (회원가입 또는 2FA 설정 시)
function generate2FASecret(email) {
  const secret = speakeasy.generateSecret({
    name: `MyApp (${email})`,
    length: 32
  });

  return {
    secret: secret.base32,
    qrCodeUrl: secret.otpauth_url
  };
}

// 2. QR 코드 생성
async function generateQRCode(otpauth_url) {
  const qrCode = await QRCode.toDataURL(otpauth_url);
  return qrCode;  // <img src="data:image/png;base64,...">
}

// 3. OTP 검증
function verify2FA(secret, token) {
  const verified = speakeasy.totp.verify({
    secret,
    encoding: 'base32',
    token,
    window: 2  // ±2분 허용 (시간 차이 보정)
  });

  return verified;
}

// 사용 예시
app.post('/api/auth/enable-2fa', async (req, res) => {
  const user = req.user;

  const { secret, qrCodeUrl } = generate2FASecret(user.email);

  // Secret을 DB에 임시 저장
  await user.update({ twoFactorSecret: secret });

  // QR 코드 반환
  const qrCode = await generateQRCode(qrCodeUrl);

  res.json({ qrCode });
});

app.post('/api/auth/verify-2fa', async (req, res) => {
  const user = req.user;
  const { token } = req.body;

  const verified = verify2FA(user.twoFactorSecret, token);

  if (verified) {
    await user.update({ twoFactorEnabled: true });
    res.json({ message: '2FA 활성화 완료' });
  } else {
    res.status(400).json({ error: '잘못된 코드입니다' });
  }
});
```

## 23.4 인가 (Authorization)

### 인가 방식

```
1. 역할 기반 (RBAC: Role-Based Access Control)
   사용자 → 역할 → 권한

2. 속성 기반 (ABAC: Attribute-Based Access Control)
   사용자 속성, 리소스 속성, 환경 등

3. 리소스 기반
   각 리소스마다 권한 설정
```

### RBAC 구현

```javascript
// 역할 정의
const ROLES = {
  ADMIN: 'admin',
  MODERATOR: 'moderator',
  USER: 'user'
};

// 권한 정의
const PERMISSIONS = {
  USER_READ: 'user:read',
  USER_WRITE: 'user:write',
  USER_DELETE: 'user:delete',
  POST_READ: 'post:read',
  POST_WRITE: 'post:write',
  POST_DELETE: 'post:delete'
};

// 역할별 권한
const ROLE_PERMISSIONS = {
  [ROLES.ADMIN]: [
    PERMISSIONS.USER_READ,
    PERMISSIONS.USER_WRITE,
    PERMISSIONS.USER_DELETE,
    PERMISSIONS.POST_READ,
    PERMISSIONS.POST_WRITE,
    PERMISSIONS.POST_DELETE
  ],
  [ROLES.MODERATOR]: [
    PERMISSIONS.POST_READ,
    PERMISSIONS.POST_WRITE,
    PERMISSIONS.POST_DELETE
  ],
  [ROLES.USER]: [
    PERMISSIONS.POST_READ,
    PERMISSIONS.POST_WRITE  // 본인 글만
  ]
};

// 권한 확인 미들웨어
function hasPermission(permission) {
  return (req, res, next) => {
    const user = req.user;

    if (!user) {
      return res.status(401).json({ error: '인증 필요' });
    }

    const userPermissions = ROLE_PERMISSIONS[user.role] || [];

    if (!userPermissions.includes(permission)) {
      return res.status(403).json({ error: '권한 없음' });
    }

    next();
  };
}

// 역할 확인 미들웨어
function hasRole(...roles) {
  return (req, res, next) => {
    const user = req.user;

    if (!user) {
      return res.status(401).json({ error: '인증 필요' });
    }

    if (!roles.includes(user.role)) {
      return res.status(403).json({ error: '권한 없음' });
    }

    next();
  };
}

// 사용 예시
app.delete('/api/users/:id',
  hasPermission(PERMISSIONS.USER_DELETE),
  async (req, res) => {
    await User.destroy({ where: { id: req.params.id } });
    res.json({ message: '사용자 삭제 완료' });
  }
);

app.get('/api/admin/dashboard',
  hasRole(ROLES.ADMIN),
  async (req, res) => {
    // 관리자 대시보드
  }
);
```

### 리소스 소유권 확인

```javascript
// 본인 리소스만 수정/삭제 가능
function isOwner(Model, ownerField = 'userId') {
  return async (req, res, next) => {
    const resourceId = req.params.id;
    const userId = req.user.id;

    const resource = await Model.findByPk(resourceId);

    if (!resource) {
      return res.status(404).json({ error: '리소스를 찾을 수 없습니다' });
    }

    if (resource[ownerField] !== userId) {
      return res.status(403).json({ error: '권한 없음: 본인 리소스만 수정 가능' });
    }

    req.resource = resource;
    next();
  };
}

// 사용
app.put('/api/posts/:id',
  authenticate,
  isOwner(Post),
  async (req, res) => {
    const post = req.resource;
    await post.update(req.body);
    res.json(post);
  }
);
```

## 23.5 RBAC vs ABAC

### RBAC (Role-Based)

```javascript
// 간단, 명확
// 역할: admin, moderator, user

if (user.role === 'admin') {
  // 허용
}

장점: 간단, 관리 쉬움
단점: 세밀한 제어 어려움
```

### ABAC (Attribute-Based)

```javascript
// 복잡하지만 유연
// 여러 속성 조합

function canEdit(user, post) {
  // 본인 글이거나
  if (post.authorId === user.id) return true;

  // 관리자이거나
  if (user.role === 'admin') return true;

  // 모더레이터이면서 글이 신고되었고
  if (user.role === 'moderator' && post.reported) return true;

  // 작성 후 24시간 이내이고 본인이면
  const withinEditWindow = Date.now() - post.createdAt < 24 * 60 * 60 * 1000;
  if (withinEditWindow && post.authorId === user.id) return true;

  return false;
}

장점: 매우 유연, 세밀한 제어
단점: 복잡, 관리 어려움
```

```javascript
const ROLES = {
  ADMIN: 'admin',       // 전체 관리

  [ROLES.MODERATOR]: [

    PERMISSIONS.POST_UPDATE_ANY,
    PERMISSIONS.POST_DELETE_ANY,
    PERMISSIONS.COMMENT_CREATE,
    PERMISSIONS.COMMENT_UPDATE_OWN,
    PERMISSIONS.COMMENT_DELETE_ANY

  [ROLES.AUTHOR]: [
    PERMISSIONS.POST_CREATE,
    PERMISSIONS.POST_READ,
    PERMISSIONS.POST_UPDATE_OWN,
    PERMISSIONS.POST_DELETE_OWN,
    PERMISSIONS.COMMENT_CREATE,
    PERMISSIONS.COMMENT_UPDATE_OWN,
    PERMISSIONS.COMMENT_DELETE_OWN
  ],
  [ROLES.USER]: [

    PERMISSIONS.COMMENT_DELETE_OWN
  ]

```

### 권한 확인 로직

```javascript
class AuthorizationService {
  hasPermission(user, permission) {
    const userPermissions = ROLE_PERMISSIONS[user.role] || [];
    return userPermissions.includes(permission);
  }

  canUpdatePost(user, post) {
    // 본인 글이면서 update:own 권한
    if (post.authorId === user.id) {
      return this.hasPermission(user, PERMISSIONS.POST_UPDATE_OWN);
    }

    // update:any 권한
    return this.hasPermission(user, PERMISSIONS.POST_UPDATE_ANY);
  }

  canDeletePost(user, post) {
    if (post.authorId === user.id) {
      return this.hasPermission(user, PERMISSIONS.POST_DELETE_OWN);
    }

    return this.hasPermission(user, PERMISSIONS.POST_DELETE_ANY);
  }
}

const authz = new AuthorizationService();

// 미들웨어
function authorize(checkFn) {
  return async (req, res, next) => {
    const user = req.user;
    const resourceId = req.params.id;

    // 리소스 조회
    const post = await Post.findByPk(resourceId);

    if (!post) {
      return res.status(404).json({ error: '리소스 없음' });
    }

    // 권한 확인
    if (!checkFn(user, post)) {
      return res.status(403).json({ error: '권한 없음' });
    }

    req.post = post;
    next();
  };
}

// 사용
app.put('/api/posts/:id',
  authenticate,
  authorize((user, post) => authz.canUpdatePost(user, post)),
  async (req, res) => {
    await req.post.update(req.body);
    res.json(req.post);
  }
);

app.delete('/api/posts/:id',
  authenticate,
  authorize((user, post) => authz.canDeletePost(user, post)),
  async (req, res) => {
    await req.post.destroy();
    res.json({ message: '삭제 완료' });
  }
);
```

## 23.7 보안 Best Practices

### 인증

```javascript
// 1. 비밀번호 정책
const passwordPolicy = {
  minLength: 12,
  requireUppercase: true,
  requireLowercase: true,
  requireNumbers: true,
  requireSpecialChars: true,
  preventCommon: true
};

// 2. 계정 잠금
const MAX_LOGIN_ATTEMPTS = 5;
const LOCKOUT_DURATION = 30 * 60 * 1000;  // 30분

async function login(email, password) {
  const user = await User.findOne({ where: { email } });

  // 계정 잠금 확인
  if (user.lockedUntil && Date.now() < user.lockedUntil) {
    throw new Error('계정이 잠겼습니다');
  }

  const isValid = await bcrypt.compare(password, user.password);

  if (!isValid) {
    user.loginAttempts += 1;

    if (user.loginAttempts >= MAX_LOGIN_ATTEMPTS) {
      user.lockedUntil = Date.now() + LOCKOUT_DURATION;
    }

    await user.save();
    throw new Error('비밀번호 불일치');
  }

  // 성공 시 초기화
  user.loginAttempts = 0;
  user.lockedUntil = null;
  await user.save();

  return user;
}

// 3. 세션 타임아웃
const SESSION_TIMEOUT = 30 * 60 * 1000;  // 30분

async function login(email, password, req) {
```

```javascript
// 1. 최소 권한 원칙

// 2. 권한 검증 누락 방지

  await req.user.destroy();
```

## 핵심 요약

### 인증 vs 인가
```
인증: "누구인가?" (로그인)
인가: "무엇을 할 수 있나?" (권한)
```

### 인증 방식
```
비밀번호: bcrypt로 해싱
2FA: TOTP (Google Authenticator)
생체인증: 지문, 얼굴
```

### 인가 방식
```
RBAC: 역할 기반 (간단)
ABAC: 속성 기반 (유연)
리소스 소유권: 본인만
```

### Best Practices
```
비밀번호: 12자 이상, 복잡도
계정 잠금: 5회 실패 시
세션 타임아웃: 30분
최소 권한 원칙
```
