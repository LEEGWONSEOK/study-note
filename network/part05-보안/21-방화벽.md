# Chapter 21. 방화벽 기초

## 21.1 방화벽이란?

### 정의

```
방화벽 (Firewall):
네트워크 트래픽을 검사하고 허용/차단하는 보안 시스템

비유: 건물 보안 검색대
┌────────────────────────────────┐
│  외부 ──→ 보안검색대 ──→ 내부  │
│                                │
│  허가증 확인:                   │
│  - 직원: 통과 ✅               │
│  - 손님: 제한적 접근 ✅        │
│  - 불법침입: 차단 ❌            │
└────────────────────────────────┘
```

### 방화벽의 목적

```
1. 무단 접근 차단
   외부 → 내부 불법 접근 방지

2. 악성 트래픽 필터링
   바이러스, 멀웨어 차단

3. 정책 시행
   회사 보안 정책 강제 적용

4. 로깅 및 모니터링
   모든 접근 기록
```

## 21.2 방화벽 종류

### OSI 계층별 분류

```
┌─────────────────────────────────┐
│ Layer 7: Application            │
│ → WAF (Web Application Firewall)│
│    SQL Injection, XSS 차단      │
├─────────────────────────────────┤
│ Layer 4: Transport              │
│ → Stateful Firewall             │
│    TCP/UDP 연결 상태 추적       │
├─────────────────────────────────┤
│ Layer 3: Network                │
│ → Packet Filter                 │
│    IP 주소, 포트 기반 필터링     │
└─────────────────────────────────┘
```

### 1. Packet Filter (패킷 필터)

```
가장 기본적인 방화벽
IP 주소, 포트, 프로토콜로 판단

예: iptables, Network ACL

규칙:
┌─────────┬─────┬────────┬────────┐
│ 출발지   │ 포트 │ 목적지  │ 동작   │
├─────────┼─────┼────────┼────────┤
│ 0.0.0.0 │ 80  │ 10.0.1.10│ ALLOW │
│ 0.0.0.0 │ 22  │ 10.0.1.10│ DENY  │
└─────────┴─────┴────────┴────────┘

장점: 빠름
단점: 상태 추적 안 됨
```

### 2. Stateful Firewall

```
연결 상태를 기억하는 방화벽

예: AWS Security Group, pfSense

상태 테이블:
┌───────────┬─────────┬────────┐
│ 출발지     │ 목적지   │ 상태   │
├───────────┼─────────┼────────┤
│ 1.2.3.4   │10.0.1.10│ESTABLISHED│
│ 5.6.7.8   │10.0.1.10│NEW     │
└───────────┴─────────┴────────┘

장점:
- 응답 트래픽 자동 허용
- 보안성 높음

단점:
- 상태 테이블 관리 필요
```

### 3. Application Firewall (WAF)

```
HTTP/HTTPS 내용까지 검사

예: AWS WAF, Cloudflare

검사 항목:
- SQL Injection 시도
- XSS (Cross-Site Scripting)
- 악성 User-Agent
- Rate Limiting

예:
GET /api/users?id=1' OR '1'='1
                    ↑
              SQL Injection 감지 → 차단
```

## 21.3 리눅스 방화벽 (iptables)

### iptables 기본

```bash
# 현재 규칙 확인
sudo iptables -L -n -v

# 기본 정책 (모두 차단)
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

# SSH 허용 (포트 22)
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# HTTP/HTTPS 허용
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# 기존 연결 허용 (Stateful!)
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# 로컬 루프백 허용
sudo iptables -A INPUT -i lo -j ACCEPT

# 규칙 저장
sudo iptables-save > /etc/iptables/rules.v4
```

### 체인 (Chain)

```
3가지 기본 체인:

1. INPUT: 서버로 들어오는 트래픽
2. OUTPUT: 서버에서 나가는 트래픽
3. FORWARD: 서버를 통과하는 트래픽 (라우터)

┌────────────────────────────────┐
│        iptables                │
│                                │
│  INPUT ←─ 들어오는 패킷        │
│  OUTPUT ─→ 나가는 패킷         │
│  FORWARD ──→ 통과하는 패킷     │
└────────────────────────────────┘
```

### 실전 예제

```bash
#!/bin/bash
# 웹 서버 방화벽 설정

# 초기화
iptables -F

# 기본 정책: 모두 차단
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# Loopback 허용
iptables -A INPUT -i lo -j ACCEPT

# 기존 연결 허용
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# SSH (특정 IP만)
iptables -A INPUT -p tcp -s 1.2.3.4/32 --dport 22 -j ACCEPT

# HTTP/HTTPS (모든 IP)
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Ping 허용
iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT

# 로그 (차단된 패킷)
iptables -A INPUT -m limit --limit 5/min -j LOG --log-prefix "iptables DROP: "

# 나머지 모두 차단
iptables -A INPUT -j DROP

# 저장
iptables-save > /etc/iptables/rules.v4
```

## 21.4 UFW (Uncomplicated Firewall)

### UFW 기본

```bash
# UFW 활성화
sudo ufw enable

# 상태 확인
sudo ufw status verbose

# 기본 정책 설정
sudo ufw default deny incoming
sudo ufw default allow outgoing

# 규칙 추가
sudo ufw allow 22/tcp      # SSH
sudo ufw allow 80/tcp      # HTTP
sudo ufw allow 443/tcp     # HTTPS

# 특정 IP만 허용
sudo ufw allow from 1.2.3.4 to any port 22

# 서브넷 허용
sudo ufw allow from 10.0.0.0/16 to any port 3306  # MySQL

# 포트 범위 허용
sudo ufw allow 6000:6007/tcp

# 규칙 삭제
sudo ufw delete allow 80/tcp

# 번호로 삭제
sudo ufw status numbered
sudo ufw delete 2
```

### UFW vs iptables

```
┌────────────┬─────────────┬──────────────┐
│   항목      │ iptables    │ UFW          │
├────────────┼─────────────┼──────────────┤
│ 난이도      │ 높음        │ 쉬움         │
│ 명령어      │ 복잡        │ 간단         │
│ 세밀한 제어 │ ✅         │ 제한적       │
│ 초보자      │ 어려움      │ ✅ 추천      │
└────────────┴─────────────┴──────────────┘

UFW는 내부적으로 iptables 사용
```

## 21.5 AWS 방화벽

### Security Group (복습)

```
인스턴스 레벨 방화벽
Stateful

예시:
┌──────────┬──────┬─────────┬─────────┐
│ 타입      │ 포트 │ 소스     │ 설명    │
├──────────┼──────┼─────────┼─────────┤
│ SSH      │ 22   │ 1.2.3.4 │ 내 IP만 │
│ HTTP     │ 80   │ 0.0.0.0 │ 전체    │
│ MySQL    │ 3306 │ sg-app  │ 앱서버만│
└──────────┴──────┴─────────┴─────────┘

→ 응답 트래픽 자동 허용 (Stateful)
```

### Network ACL (복습)

```
서브넷 레벨 방화벽
Stateless

규칙 번호 순서대로 평가:
┌────┬──────┬──────┬──────┬─────────┐
│ 번호│ 타입 │ 포트 │ 소스 │ 동작    │
├────┼──────┼──────┼──────┼─────────┤
│ 100│ HTTP │ 80   │ All  │ ALLOW   │
│ 200│ HTTPS│ 443  │ All  │ ALLOW   │
│ *  │ All  │ All  │ All  │ DENY    │
└────┴──────┴──────┴──────┴─────────┘

→ 양방향 모두 설정 필요 (Stateless)
```

### AWS WAF

```hcl
# WAF Web ACL
resource "aws_wafv2_web_acl" "main" {
  name  = "web-acl"
  scope = "REGIONAL"

  default_action {
    allow {}
  }

  # Rule 1: Rate Limiting (DDoS 방어)
  rule {
    name     = "rate-limit"
    priority = 1

    statement {
      rate_based_statement {
        limit              = 2000  # 5분당 2000 요청
        aggregate_key_type = "IP"
      }
    }

    action {
      block {}
    }

    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "RateLimitRule"
      sampled_requests_enabled   = true
    }
  }

  # Rule 2: SQL Injection 방어
  rule {
    name     = "sql-injection"
    priority = 2

    statement {
      sqli_match_statement {
        field_to_match {
          query_string {}
        }

        text_transformation {
          priority = 0
          type     = "URL_DECODE"
        }
      }
    }

    action {
      block {}
    }

    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "SQLInjectionRule"
      sampled_requests_enabled   = true
    }
  }

  # Rule 3: XSS 방어
  rule {
    name     = "xss"
    priority = 3

    statement {
      xss_match_statement {
        field_to_match {
          body {}
        }

        text_transformation {
          priority = 0
          type     = "URL_DECODE"
        }
      }
    }

    action {
      block {}
    }

    visibility_config {
      cloudwatch_metrics_enabled = true
      metric_name                = "XSSRule"
      sampled_requests_enabled   = true
    }
  }

  visibility_config {
    cloudwatch_metrics_enabled = true
    metric_name                = "WebACL"
    sampled_requests_enabled   = true
  }
}

# ALB에 WAF 연결
resource "aws_wafv2_web_acl_association" "main" {
  resource_arn = aws_lb.main.arn
  web_acl_arn  = aws_wafv2_web_acl.main.arn
}
```

## 21.6 애플리케이션 레벨 방화벽

### Express.js Rate Limiting

```javascript
const rateLimit = require('express-rate-limit');

// Rate Limiter 설정
const limiter = rateLimit({
  windowMs: 15 * 60 * 1000,  // 15분
  max: 100,                   // 최대 100 요청
  message: '너무 많은 요청입니다. 나중에 다시 시도하세요.',
  standardHeaders: true,
  legacyHeaders: false,
});

// API에 적용
app.use('/api/', limiter);

// 로그인은 더 엄격하게
const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 5,  // 15분에 5번만
  skipSuccessfulRequests: true,
});

app.post('/api/auth/login', loginLimiter, async (req, res) => {
  // 로그인 로직
});
```

### IP 기반 접근 제어

```javascript
const ipfilter = require('express-ipfilter').IpFilter;

// Whitelist (허용 목록)
const allowedIPs = ['1.2.3.4', '5.6.7.8'];
app.use(ipfilter(allowedIPs, { mode: 'allow' }));

// Blacklist (차단 목록)
const blockedIPs = ['9.8.7.6'];
app.use(ipfilter(blockedIPs, { mode: 'deny' }));

// CIDR 지원
const allowedRanges = ['10.0.0.0/16', '192.168.1.0/24'];
app.use(ipfilter(allowedRanges, { mode: 'allow' }));
```

## 21.7 방화벽 우회 기법과 방어

### 포트 스캔 탐지 및 차단

```bash
# iptables로 포트 스캔 차단
iptables -A INPUT -p tcp --tcp-flags ALL NONE -j DROP  # NULL scan
iptables -A INPUT -p tcp --tcp-flags ALL ALL -j DROP    # XMAS scan
iptables -A INPUT -p tcp --syn -m limit --limit 1/s -j ACCEPT  # SYN flood

# fail2ban 설치 (자동 차단)
sudo apt install fail2ban

# /etc/fail2ban/jail.local
[sshd]
enabled = true
port = 22
filter = sshd
logpath = /var/log/auth.log
maxretry = 3
bantime = 3600
findtime = 600
```

### DDoS 방어

```bash
# SYN Cookie 활성화
sysctl -w net.ipv4.tcp_syncookies=1

# 연결 제한
iptables -A INPUT -p tcp --syn -m connlimit --connlimit-above 20 -j REJECT

# ICMP Flood 방어
iptables -A INPUT -p icmp -m limit --limit 1/s -j ACCEPT
iptables -A INPUT -p icmp -j DROP
```

## 21.8 실전 시나리오

### 시나리오 1: 웹 서버 방화벽

```
요구사항:
- HTTP/HTTPS: 전체 허용
- SSH: 특정 IP만
- MySQL: 앱 서버만
- Ping: 제한적 허용

보안 계층:
1. AWS Security Group
2. OS 방화벽 (UFW)
3. 애플리케이션 Rate Limiting
4. AWS WAF (선택)
```

```bash
# UFW 설정
sudo ufw default deny incoming
sudo ufw default allow outgoing

# HTTP/HTTPS
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# SSH (특정 IP)
sudo ufw allow from 1.2.3.4 to any port 22

# Ping (제한)
sudo ufw limit proto icmp

sudo ufw enable
```

### 시나리오 2: API 서버 보호

```javascript
const express = require('express');
const helmet = require('helmet');
const rateLimit = require('express-rate-limit');
const cors = require('cors');

const app = express();

// 1. 보안 헤더 (helmet)
app.use(helmet());

// 2. CORS 제한
app.use(cors({
  origin: ['https://example.com'],
  credentials: true
}));

// 3. Rate Limiting
const apiLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 100,
  message: 'Too many requests'
});

app.use('/api/', apiLimiter);

// 4. IP 필터링 (관리자 API)
const adminIPs = ['1.2.3.4'];
app.use('/api/admin', (req, res, next) => {
  const clientIP = req.ip;
  if (!adminIPs.includes(clientIP)) {
    return res.status(403).json({ error: 'Forbidden' });
  }
  next();
});

app.listen(3000);
```

## 21.9 로깅 및 모니터링

### iptables 로깅

```bash
# 로그 규칙 추가
iptables -A INPUT -m limit --limit 5/min -j LOG --log-prefix "iptables DROP: " --log-level 4

# 로그 확인
tail -f /var/log/syslog | grep "iptables"

# 특정 포트 로깅
iptables -A INPUT -p tcp --dport 22 -j LOG --log-prefix "SSH attempt: "
```

### AWS WAF 로깅

```hcl
# CloudWatch Logs로 WAF 로그 전송
resource "aws_wafv2_web_acl_logging_configuration" "main" {
  resource_arn            = aws_wafv2_web_acl.main.arn
  log_destination_configs = [aws_cloudwatch_log_group.waf.arn]

  redacted_fields {
    single_header {
      name = "authorization"
    }
  }
}

resource "aws_cloudwatch_log_group" "waf" {
  name              = "/aws/waf/web-acl"
  retention_in_days = 30
}
```

### 알람 설정

```hcl
# CloudWatch Alarm (차단된 요청 급증)
```

## 핵심 요약

### 방화벽 종류
```
Packet Filter: IP/포트 기반
Stateful: 연결 상태 추적
Application (WAF): HTTP 내용 검사
```

### 리눅스 방화벽
```
iptables: 강력, 복잡
UFW: 간단, 초보자 친화적
fail2ban: 자동 IP 차단
```

### AWS 방화벽
```
Security Group: 인스턴스 레벨, Stateful
Network ACL: 서브넷 레벨, Stateless
WAF: 애플리케이션 레벨
```

### 계층적 방어
```
1. Network (Security Group)
2. OS (UFW/iptables)
3. Application (Rate Limiting)
4. WAF (선택)
```
