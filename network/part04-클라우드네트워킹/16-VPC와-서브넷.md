# Chapter 16. VPC와 서브넷

## 16.1 VPC란?

**VPC (Virtual Private Cloud)**는 클라우드 환경에서 **논리적으로 격리된 가상 네트워크**입니다.

### 비유: 아파트 단지

```
전체 클라우드 = 도시
VPC = 당신만의 아파트 단지 (울타리로 격리)
서브넷 = 각 동

┌─────────────────────────────────────────┐
│  AWS Cloud (도시)                        │
│                                         │
│  ┌──────────────────────────────────┐   │
│  │  VPC (당신의 아파트 단지)          │   │
│  │                                  │   │
│  │  ┌──────────┐  ┌──────────┐     │   │
│  │  │Subnet A  │  │Subnet B  │     │   │
│  │  │(101동)   │  │(102동)   │     │   │
│  │  └──────────┘  └──────────┘     │   │
│  └──────────────────────────────────┘   │
│                                         │
│  다른 사람의 VPC (다른 아파트 단지)       │
└─────────────────────────────────────────┘
```

---

## 16.2 왜 VPC가 필요한가? ⭐ 중요!

### 문제: 격리 없는 환경

```
격리 없이 모든 서버가 같은 네트워크:

[내 웹서버] ─┐
[내 DB서버] ─┤
            ├─ 같은 네트워크
[남의 서버] ─┤
[해커 서버] ─┘

문제:
1. 보안 위험 (다른 사람이 내 DB 접근 가능)
2. IP 충돌
3. 관리 어려움
```

### 해결: VPC로 격리

```
VPC로 격리:

┌─────────────────┐     ┌─────────────────┐
│   내 VPC        │     │   남의 VPC      │
│                 │     │                 │
│ [웹서버]        │     │ [남의 서버]     │
│ [DB서버]        │     │                 │
│                 │     │                 │
│ 완전 격리!      │     │ 완전 격리!      │
└─────────────────┘     └─────────────────┘

장점:
✅ 보안 (내 네트워크만 접근 가능)
✅ IP 자유 선택
✅ 완전한 제어
```

## 16.4 서브넷(Subnet) ⭐ 핵심 개념!

### 정의

VPC 내의 **더 작은 네트워크 단위**

### Public vs Private 서브넷

```
┌────────────────────────────────────────┐
│  Public Subnet                         │
│  - 인터넷 직접 접근 가능                 │
│  - Internet Gateway 연결               │
│  - 공인 IP 자동 할당                    │
│                                        │
│  용도:                                 │
│  - 웹 서버                             │
│  - 로드 밸런서                          │
│  - NAT Gateway                         │
└────────────────────────────────────────┘

┌────────────────────────────────────────┐
│  Private Subnet                        │
│  - 인터넷 직접 접근 불가                 │
│  - NAT Gateway 통해서만 외부 통신       │
│  - 사설 IP만                           │
│                                        │
│  용도:                                 │
│  - 데이터베이스                         │
│  - 애플리케이션 서버                     │
│  - 내부 서비스                          │
└────────────────────────────────────────┘
```

### 실제 예시

```
회사 웹 서비스 구조:

┌──────────────────────────────────────┐
│  인터넷                               │
└────────┬─────────────────────────────┘
         ↓
┌──────────────────────────────────────┐
│  Public Subnet (10.0.1.0/24)         │
│                                      │
│  ┌────────────────────────────────┐  │
│  │ NGINX 웹 서버                   │  │
│  │ 공인 IP: 13.209.84.49          │  │
│  │ 사설 IP: 10.0.1.10             │  │
│  └─────────────┬──────────────────┘  │
└────────────────┼─────────────────────┘
                 ↓
┌──────────────────────────────────────┐
│  Private Subnet (10.0.2.0/24)        │
│                                      │
│  ┌────────────────────────────────┐  │
│  │ Node.js API 서버                │  │
│  │ 사설 IP: 10.0.2.10 (공인 IP 없음)│  │
│  └─────────────┬──────────────────┘  │
└────────────────┼─────────────────────┘
                 ↓
┌──────────────────────────────────────┐
│  Private Subnet (10.0.3.0/24)        │
│                                      │
│  ┌────────────────────────────────┐  │
│  │ MySQL 데이터베이스              │  │
│  │ 사설 IP: 10.0.3.10             │  │
│  │ 외부 접근 완전 차단!            │  │
│  └────────────────────────────────┘  │
└──────────────────────────────────────┘
```

## 16.5 VPC CIDR 블록 설계

### CIDR 선택 가이드

```
VPC CIDR 블록 권장 크기:

작은 규모: 10.0.0.0/24 (256개 IP)
→ 스타트업 초기

중간 규모: 10.0.0.0/20 (4,096개 IP)
→ 일반적인 중소 기업

큰 규모: 10.0.0.0/16 (65,536개 IP)
→ 대기업, 확장 계획 있는 경우

초대형: 10.0.0.0/8 (16,777,216개 IP)
→ 글로벌 엔터프라이즈
```

### 실전 설계 예시

```
VPC: 10.0.0.0/16 (65,536개 IP)

가용 영역 A (ap-northeast-2a):
├─ Public Subnet:  10.0.1.0/24   (256개 IP)
├─ Private Subnet: 10.0.11.0/24  (256개 IP - 앱)
└─ Private Subnet: 10.0.21.0/24  (256개 IP - DB)

가용 영역 B (ap-northeast-2b):
├─ Public Subnet:  10.0.2.0/24   (256개 IP)
├─ Private Subnet: 10.0.12.0/24  (256개 IP - 앱)
└─ Private Subnet: 10.0.22.0/24  (256개 IP - DB)

예약 (미래 확장):
└─ 10.0.64.0/18 (16,384개 IP 여유)
```

### 주의사항

```
❌ 피해야 할 CIDR:

10.0.0.0/8  ← 너무 큼 (관리 어려움)
192.168.0.0/24 ← 너무 작음 (확장 불가)
172.31.0.0/16 ← AWS 기본 VPC와 겹침

✅ 권장 CIDR:

10.0.0.0/16  ← 가장 일반적
10.1.0.0/16  ← 여러 VPC 사용 시
172.16.0.0/16 ← 온프레미스와 구분
```

## 16.6 Internet Gateway (IGW)

### 정의

VPC와 인터넷을 연결하는 **게이트웨이**

### 동작 방식

```
┌──────────────────────────────────────┐
│  인터넷                               │
└────────┬─────────────────────────────┘
         ↓
┌──────────────────────────────────────┐
│  Internet Gateway                    │
│  - 공인 IP ↔ 사설 IP 변환 (NAT)      │
│  - 라우팅                             │
└────────┬─────────────────────────────┘
         ↓
┌──────────────────────────────────────┐
│  VPC 10.0.0.0/16                     │
│                                      │
│  Public Subnet 10.0.1.0/24           │
│  ┌────────────────────────────────┐  │
│  │ EC2 인스턴스                    │  │
│  │ 사설 IP: 10.0.1.10             │  │
│  │ 공인 IP: 13.209.84.49 (IGW가   │  │
│  │          자동 매핑)             │  │
│  └────────────────────────────────┘  │
└──────────────────────────────────────┘
```

### Terraform 예시

```hcl
# VPC 생성
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"

  tags = {
    Name = "main-vpc"
  }
}

# Internet Gateway 생성
resource "aws_internet_gateway" "main" {
  vpc_id = aws_vpc.main.id

  tags = {
    Name = "main-igw"
  }
}

# Public 서브넷 생성
resource "aws_subnet" "public" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.1.0/24"
  availability_zone = "ap-northeast-2a"

  # 공인 IP 자동 할당
  map_public_ip_on_launch = true

  tags = {
    Name = "public-subnet"
  }
}

# 라우팅 테이블 (Public)
resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id

  # 인터넷으로 가는 모든 트래픽 → IGW
  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.main.id
  }

  tags = {
    Name = "public-route-table"
  }
}

# 라우팅 테이블 연결
resource "aws_route_table_association" "public" {
  subnet_id      = aws_subnet.public.id
  route_table_id = aws_route_table.public.id
}
```

## 16.7 NAT Gateway

### 정의

**Private 서브넷**의 인스턴스가 **인터넷에 접근**할 수 있게 해주는 게이트웨이

### 왜 필요한가?

```
문제:
Private 서브넷의 앱 서버가 외부 API 호출 불가
→ npm install 안 됨
→ 외부 API 호출 안 됨

해결: NAT Gateway
```

### 동작 방식

```
┌──────────────────────────────────────┐
│  인터넷 (외부 API)                    │
└────────┬─────────────────────────────┘
         ↓
┌──────────────────────────────────────┐
│  Internet Gateway                    │
└────────┬─────────────────────────────┘
         ↓
┌──────────────────────────────────────┐
│  Public Subnet 10.0.1.0/24           │
│  ┌────────────────────────────────┐  │
│  │ NAT Gateway                    │  │
│  │ 공인 IP: 13.209.84.50          │  │
│  └─────────────┬──────────────────┘  │
└────────────────┼─────────────────────┘
                 ↓
┌──────────────────────────────────────┐
│  Private Subnet 10.0.2.0/24          │
│  ┌────────────────────────────────┐  │
│  │ 앱 서버                         │  │
│  │ 사설 IP: 10.0.2.10             │  │
│  │                                │  │
│  │ npm install 성공! ✅            │  │
│  │ 외부 API 호출 가능! ✅          │  │
│  └────────────────────────────────┘  │
└──────────────────────────────────────┘

흐름:
1. Private 인스턴스 → NAT Gateway
2. NAT Gateway → Internet Gateway
3. Internet Gateway → 인터넷
```

### NAT Gateway vs NAT Instance

```
┌──────────────┬──────────────┬──────────────┐
│    항목       │ NAT Gateway  │ NAT Instance │
├──────────────┼──────────────┼──────────────┤
│  관리         │ AWS 관리     │ 직접 관리    │
│  가용성       │ 고가용성     │ 직접 구성    │
│  대역폭       │ 최대 100Gbps │ 인스턴스 한계│
│  비용         │ 시간당 과금  │ 인스턴스 비용│
│  권장         │ ✅ 운영 환경  │ 테스트 환경  │
└──────────────┴──────────────┴──────────────┘
```

### Terraform 예시

```hcl
# NAT Gateway를 위한 Elastic IP
resource "aws_eip" "nat" {
  domain = "vpc"

  tags = {
    Name = "nat-eip"
  }
}

# NAT Gateway (Public 서브넷에 위치)
resource "aws_nat_gateway" "main" {
  allocation_id = aws_eip.nat.id
  subnet_id     = aws_subnet.public.id

  tags = {
    Name = "main-nat-gateway"
  }
}

# Private 서브넷
resource "aws_subnet" "private" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.2.0/24"
  availability_zone = "ap-northeast-2a"

  tags = {
    Name = "private-subnet"
  }
}

# Private 라우팅 테이블
resource "aws_route_table" "private" {
  vpc_id = aws_vpc.main.id

  # 인터넷 트래픽 → NAT Gateway
  route {
    cidr_block     = "0.0.0.0/0"
    nat_gateway_id = aws_nat_gateway.main.id
  }

  tags = {
    Name = "private-route-table"
  }
}

# Private 서브넷에 라우팅 테이블 연결
resource "aws_route_table_association" "private" {
  subnet_id      = aws_subnet.private.id
  route_table_id = aws_route_table.private.id
}
```

## 16.8 멀티 AZ 고가용성 구성 ⭐ 실무 필수!

### 단일 AZ 문제점

```
┌──────────────────────────────────────┐
│  가용 영역 A                          │
│                                      │
│  [웹서버] [앱서버] [DB]              │
└──────────────────────────────────────┘

문제:
AZ-A 장애 시 전체 서비스 다운! ❌
```

### 멀티 AZ 해결책

```
┌──────────────────────────────────────┐
│  Load Balancer (다중 AZ)              │
└─────────┬────────────────────┬───────┘
          ↓                    ↓
┌──────────────────┐  ┌──────────────────┐
│  가용 영역 A      │  │  가용 영역 B      │
│                  │  │                  │
│  [웹서버]        │  │  [웹서버]        │
│  [앱서버]        │  │  [앱서버]        │
│  [DB Primary]    │  │  [DB Standby]    │
└──────────────────┘  └──────────────────┘

장점:
- AZ-A 장애 시 → AZ-B로 자동 전환 ✅
- 무중단 서비스 ✅
```

### 실전 멀티 AZ 설계

```
VPC: 10.0.0.0/16

┌─────────────────────────────────────────────────────┐
│  가용 영역 A (ap-northeast-2a)                       │
│                                                     │
│  Public Subnet A:  10.0.1.0/24                      │
│  ├─ ALB (Application Load Balancer)                 │
│  └─ NAT Gateway A                                   │
│                                                     │
│  Private Subnet A: 10.0.11.0/24                     │
│  ├─ 웹서버 1                                        │
│  └─ 앱서버 1                                        │
│                                                     │
│  Private Subnet DB-A: 10.0.21.0/24                  │
│  └─ RDS Primary                                     │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  가용 영역 B (ap-northeast-2b)                       │
│                                                     │
│  Public Subnet B:  10.0.2.0/24                      │
│  ├─ ALB (자동 분산)                                 │
│  └─ NAT Gateway B                                   │
│                                                     │
│  Private Subnet B: 10.0.12.0/24                     │
│  ├─ 웹서버 2                                        │
│  └─ 앱서버 2                                        │
│                                                     │
│  Private Subnet DB-B: 10.0.22.0/24                  │
│  └─ RDS Standby (자동 복제)                         │
└─────────────────────────────────────────────────────┘
```


## 핵심 요약

### VPC (Virtual Private Cloud)
```
- 클라우드의 논리적으로 격리된 가상 네트워크
- IP 범위 자유 선택 (CIDR)
- 완전한 제어와 보안
```

### 서브넷 (Subnet)
```
Public Subnet:
- 인터넷 직접 접근 가능
- Internet Gateway 연결
- 웹서버, 로드밸런서

Private Subnet:
- 인터넷 직접 접근 불가
- NAT Gateway 통한 외부 통신
- 앱서버, DB
```

### 주요 구성 요소
```
Internet Gateway: VPC ↔ 인터넷
NAT Gateway: Private → 인터넷 (단방향)
라우팅 테이블: 트래픽 경로 제어
```

### 고가용성
```
멀티 AZ 구성:
- 최소 2개 가용 영역
- 각 AZ에 동일한 서브넷 구조
- 로드 밸런서로 트래픽 분산
```

### 과제 1: AWS VPC 생성 (콘솔)

```
1. AWS 콘솔 → VPC 대시보드
2. VPC 생성:
   - 이름: my-first-vpc
   - CIDR: 10.0.0.0/16

3. 서브넷 생성:
   - Public:  10.0.1.0/24 (AZ-A)
   - Private: 10.0.2.0/24 (AZ-A)

4. Internet Gateway 생성 및 VPC 연결

5. 라우팅 테이블 설정
```

### 과제 2: Terraform으로 VPC 구성

위의 Terraform 코드를 실행:

```bash
terraform init
terraform plan
terraform apply

# 생성 확인
aws ec2 describe-vpcs
aws ec2 describe-subnets
```

### 과제 3: CIDR 계산 연습

```
질문:
1. 10.0.0.0/16 VPC에서 /24 서브넷을 몇 개 만들 수 있나요?
2. 각 /24 서브넷에서 실제 사용 가능한 IP는 몇 개인가요?
3. 10.0.0.0/20 서브넷의 IP 범위는?

힌트: 온라인 CIDR 계산기 사용
```
