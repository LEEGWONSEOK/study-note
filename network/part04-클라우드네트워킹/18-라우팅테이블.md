# Chapter 18. 라우팅 테이블

## 18.1 라우팅이란?

### 정의

```
라우팅 (Routing):
패킷을 목적지까지 전달하기 위한 경로 선택

비유: 내비게이션
┌──────────────────────────────────┐
│ 출발지: 서울                      │
│ 목적지: 부산                      │
│                                  │
│ 경로 선택:                        │
│ 1. 경부고속도로 ← 선택!          │
│ 2. 국도                          │
│ 3. 해안도로                      │
└──────────────────────────────────┘
```

### 라우팅 테이블

```
목적지와 경로를 매핑하는 표

┌──────────────┬──────────────┬──────────┐
│  목적지       │  게이트웨이   │  우선순위 │
├──────────────┼──────────────┼──────────┤
│ 10.0.0.0/16  │ local        │ 최우선   │
│ 0.0.0.0/0    │ IGW          │ 기본     │
│ 192.168.0.0/24│ VPN Gateway │ 특정     │
└──────────────┴──────────────┴──────────┘
```

## 18.2 AWS VPC 라우팅 테이블

### 구조

```
┌──────────────────────────────────────┐
│  VPC: 10.0.0.0/16                    │
│                                      │
│  ┌────────────────────────────────┐ │
│  │ Public Subnet: 10.0.1.0/24     │ │
│  │ Route Table: rtb-public        │ │
│  │                                │ │
│  │ 10.0.0.0/16 → local            │ │
│  │ 0.0.0.0/0   → igw-xxx          │ │
│  └────────────────────────────────┘ │
│                                      │
│  ┌────────────────────────────────┐ │
│  │ Private Subnet: 10.0.2.0/24    │ │
│  │ Route Table: rtb-private       │ │
│  │                                │ │
│  │ 10.0.0.0/16 → local            │ │
│  │ 0.0.0.0/0   → nat-xxx          │ │
│  └────────────────────────────────┘ │
└──────────────────────────────────────┘
```

### 라우팅 규칙 평가

```
가장 구체적인 경로 우선 (Longest Prefix Match)

예시:
┌──────────────┬──────────────┐
│  목적지       │  게이트웨이   │
├──────────────┼──────────────┤
│ 10.0.0.0/16  │ local        │ ← /16
│ 10.0.1.0/24  │ eni-123      │ ← /24 (더 구체적)
│ 0.0.0.0/0    │ igw-xxx      │ ← /0 (기본)
└──────────────┴──────────────┘

패킷 목적지: 10.0.1.50
→ 10.0.1.0/24 매칭 (가장 구체적)
→ eni-123으로 전달
```

## 18.3 로컬 라우트 (Local Route)

### 개념

```
VPC 내부 통신을 위한 기본 라우트
자동 생성, 삭제/수정 불가

VPC: 10.0.0.0/16

자동 생성:
10.0.0.0/16 → local

의미:
10.0.x.x로 가는 모든 트래픽은 VPC 내부에서 처리
```

### 동작 방식

```
시나리오:
EC2-A (10.0.1.10) → EC2-B (10.0.2.20)

┌────────────────────────────────────┐
│  EC2-A: 10.0.1.10                  │
│  Public Subnet                     │
└───────┬────────────────────────────┘
        │ 목적지: 10.0.2.20
        ↓
┌────────────────────────────────────┐
│  Route Table                       │
│  10.0.0.0/16 → local ✅            │
│  0.0.0.0/0   → igw-xxx             │
└───────┬────────────────────────────┘
        │ local 라우트 매칭
        ↓ (VPC 내부 전달)
┌────────────────────────────────────┐
│  EC2-B: 10.0.2.20                  │
│  Private Subnet                    │
└────────────────────────────────────┘

→ 인터넷 게이트웨이 거치지 않음
→ VPC 내부에서 직접 통신
```

## 18.4 Public Subnet 라우팅

### Public Subnet 정의

```
인터넷과 직접 통신 가능한 서브넷

조건:
1. 인터넷 게이트웨이(IGW) 연결
2. 라우팅 테이블에 IGW로 가는 기본 경로
3. 퍼블릭 IP 또는 EIP 할당
```

### Public 라우팅 테이블

```
┌──────────────┬──────────────┬─────────┐
│  목적지       │  대상         │  상태    │
├──────────────┼──────────────┼─────────┤
│ 10.0.0.0/16  │ local        │ Active  │
│ 0.0.0.0/0    │ igw-123abc   │ Active  │
└──────────────┴──────────────┴─────────┘

의미:
- VPC 내부 (10.0.0.0/16) → local
- 그 외 모든 트래픽 (0.0.0.0/0) → IGW
```

### 인터넷 통신 흐름

```
EC2 (Public Subnet) → Internet

┌────────────────────────────────────┐
│  EC2: 10.0.1.10                    │
│  Public IP: 13.125.1.100           │
└───────┬────────────────────────────┘
        │ GET google.com
        │ 목적지: 142.250.207.46
        ↓
┌────────────────────────────────────┐
│  Route Table                       │
│  10.0.0.0/16 → local               │
│  0.0.0.0/0   → igw-xxx ✅          │
└───────┬────────────────────────────┘
        │
        ↓
┌────────────────────────────────────┐
│  Internet Gateway                  │
│  NAT: 10.0.1.10 → 13.125.1.100    │
└───────┬────────────────────────────┘
        │
        ↓
    Internet
```

## 18.5 Private Subnet 라우팅

### Private Subnet 정의

```
인터넷과 직접 통신 불가능한 서브넷
외부 접근 차단, 보안 강화

인터넷 접근 필요 시:
→ NAT Gateway 사용
```

### Private 라우팅 테이블

```
┌──────────────┬──────────────┬─────────┐
│  목적지       │  대상         │  상태    │
├──────────────┼──────────────┼─────────┤
│ 10.0.0.0/16  │ local        │ Active  │
│ 0.0.0.0/0    │ nat-456def   │ Active  │
└──────────────┴──────────────┴─────────┘

의미:
- VPC 내부 → local
- 외부 인터넷 → NAT Gateway
```

### NAT Gateway 통신 흐름

```
EC2 (Private Subnet) → Internet

┌────────────────────────────────────┐
│  EC2: 10.0.2.10 (Private IP만)     │
└───────┬────────────────────────────┘
        │ yum update (외부 패키지)
        ↓
┌────────────────────────────────────┐
│  Route Table (Private)             │
│  0.0.0.0/0 → nat-xxx ✅            │
└───────┬────────────────────────────┘
        │
        ↓
┌────────────────────────────────────┐
│  NAT Gateway (Public Subnet)       │
│  IP: 10.0.1.50                     │
│  EIP: 13.125.1.200                 │
└───────┬────────────────────────────┘
        │ NAT: 10.0.2.10 → 13.125.1.200
        ↓
┌────────────────────────────────────┐
│  Internet Gateway                  │
└───────┬────────────────────────────┘
        │
        ↓
    Internet

응답 경로: 역순으로 돌아옴
```

## 18.6 Terraform 설정 예시

### VPC + 서브넷 + 라우팅 테이블

```hcl
# VPC
resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  enable_dns_support   = true

  tags = {
    Name = "main-vpc"
  }
}

# Internet Gateway
resource "aws_internet_gateway" "main" {
  vpc_id = aws_vpc.main.id

  tags = {
    Name = "main-igw"
  }
}

# Public Subnet
resource "aws_subnet" "public" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.1.0/24"
  availability_zone       = "ap-northeast-2a"
  map_public_ip_on_launch = true

  tags = {
    Name = "public-subnet-a"
  }
}

# Private Subnet
resource "aws_subnet" "private" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.2.0/24"
  availability_zone = "ap-northeast-2a"

  tags = {
    Name = "private-subnet-a"
  }
}

# Public Route Table
resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.main.id
  }

  tags = {
    Name = "public-route-table"
  }
}

# Public Subnet Association
resource "aws_route_table_association" "public" {
  subnet_id      = aws_subnet.public.id
  route_table_id = aws_route_table.public.id
}

# NAT Gateway용 EIP
resource "aws_eip" "nat" {
  domain = "vpc"

  tags = {
    Name = "nat-eip"
  }
}

# NAT Gateway
resource "aws_nat_gateway" "main" {
  allocation_id = aws_eip.nat.id
  subnet_id     = aws_subnet.public.id

  tags = {
    Name = "main-nat"
  }

  depends_on = [aws_internet_gateway.main]
}

# Private Route Table
resource "aws_route_table" "private" {
  vpc_id = aws_vpc.main.id

  route {
    cidr_block     = "0.0.0.0/0"
    nat_gateway_id = aws_nat_gateway.main.id
  }

  tags = {
    Name = "private-route-table"
  }
}

# Private Subnet Association
resource "aws_route_table_association" "private" {
  subnet_id      = aws_subnet.private.id
  route_table_id = aws_route_table.private.id
}
```

## 18.7 멀티 AZ 라우팅

### High Availability 구성

```
┌────────────────────────────────────────┐
│  VPC: 10.0.0.0/16                      │
│                                        │
│  ┌──────────────┐  ┌──────────────┐  │
│  │    AZ-A      │  │    AZ-C      │  │
│  ├──────────────┤  ├──────────────┤  │
│  │Public 10.0.1 │  │Public 10.0.3 │  │
│  │ → IGW        │  │ → IGW        │  │
│  ├──────────────┤  ├──────────────┤  │
│  │Private 10.0.2│  │Private 10.0.4│  │
│  │ → NAT-A      │  │ → NAT-C      │  │
│  └──────────────┘  └──────────────┘  │
│         ↓                 ↓            │
│      NAT-A             NAT-C          │
│         ↓                 ↓            │
│         └────→ IGW ←────┘             │
└────────────────────────────────────────┘

각 AZ마다 독립적인 NAT Gateway
→ 다른 AZ 장애 시에도 영향 없음
```

## 18.8 특정 목적지 라우팅

### VPC Peering

```
VPC-A (10.0.0.0/16) ↔ VPC-B (172.16.0.0/16)

VPC-A 라우팅 테이블:
┌──────────────┬──────────────┐
│ 10.0.0.0/16  │ local        │
│ 172.16.0.0/16│ pcx-123      │ ← Peering
│ 0.0.0.0/0    │ igw-xxx      │
└──────────────┴──────────────┘

VPC-B 라우팅 테이블:
┌──────────────┬──────────────┐
│ 172.16.0.0/16│ local        │
│ 10.0.0.0/16  │ pcx-123      │ ← Peering
│ 0.0.0.0/0    │ igw-yyy      │
└──────────────┴──────────────┘
```

```hcl
# VPC Peering Connection
resource "aws_vpc_peering_connection" "main" {
  vpc_id      = aws_vpc.vpc_a.id
  peer_vpc_id = aws_vpc.vpc_b.id
  auto_accept = true

  tags = { Name = "vpc-a-to-vpc-b" }
}

# VPC-A: VPC-B로 가는 라우트
resource "aws_route" "a_to_b" {
  route_table_id            = aws_route_table.vpc_a.id
  destination_cidr_block    = "172.16.0.0/16"
  vpc_peering_connection_id = aws_vpc_peering_connection.main.id
}

# VPC-B: VPC-A로 가는 라우트
resource "aws_route" "b_to_a" {
  route_table_id            = aws_route_table.vpc_b.id
  destination_cidr_block    = "10.0.0.0/16"
  vpc_peering_connection_id = aws_vpc_peering_connection.main.id
}
```

### Transit Gateway

```
Hub-and-Spoke 모델

     VPC-A ──┐
              │
     VPC-B ──┼── Transit Gateway
              │
     VPC-C ──┘

각 VPC는 Transit Gateway로만 라우팅
→ Peering 폭발 방지
```

  --network-interface-id blackhole

## 18.10 라우팅 우선순위

### Longest Prefix Match

```
목적지: 10.0.1.50

라우팅 테이블:
┌──────────────┬──────────────┬─────────┐
│ 10.0.0.0/16  │ local        │ /16     │
│ 10.0.1.0/24  │ eni-123      │ /24 ✅  │
│ 10.0.1.0/28  │ vpn-gw       │ /28 ⭐  │
│ 0.0.0.0/0    │ igw-xxx      │ /0      │
└──────────────┴──────────────┴─────────┘

매칭:
1. 10.0.1.0/28 ⭐ (가장 구체적)
2. 10.0.1.0/24 ✅
3. 10.0.0.0/16
4. 0.0.0.0/0 (기본)

→ 10.0.1.0/28로 전달 (vpn-gw)
```

### 동일 Prefix 시

```
같은 prefix 길이면 우선순위:

1. Local (가장 높음)
2. VPC Peering
3. Direct Connect / VPN
4. NAT Gateway
5. Internet Gateway
6. VPC Endpoint
```

## 18.12 라우팅 문제 해결

### 문제 1: 인터넷 연결 안 됨

```
체크리스트:
✅ Public IP 또는 EIP 할당?
✅ IGW 생성 및 VPC 연결?
✅ 라우팅 테이블에 0.0.0.0/0 → IGW?
✅ 서브넷이 라우팅 테이블에 연결?
✅ 보안 그룹에서 아웃바운드 허용?
✅ Network ACL 확인?

확인:
aws ec2 describe-route-tables --route-table-ids rtb-xxx
```

### 문제 2: VPC 간 통신 안 됨

```
VPC Peering 체크:
✅ Peering Connection 활성화?
✅ 양쪽 VPC 라우팅 테이블 설정?
✅ CIDR 중복 없음?
✅ 보안 그룹에서 상대 VPC CIDR 허용?

traceroute 활용:
traceroute 172.16.1.10
```

### 문제 3: NAT Gateway 동작 안 함

```
체크리스트:
✅ NAT Gateway가 Public Subnet에 있음?
✅ NAT Gateway에 EIP 할당?
✅ Private 라우팅 테이블에 0.0.0.0/0 → NAT?
✅ Public 라우팅 테이블에 0.0.0.0/0 → IGW?
✅ NAT Gateway 상태 available?

확인:
aws ec2 describe-nat-gateways --nat-gateway-ids nat-xxx
```

## 핵심 요약

### 라우팅 테이블이란?
```
목적지 → 경로 매핑표
패킷을 어디로 보낼지 결정
```

### 주요 라우트 타입
```
Local: VPC 내부 통신 (자동)
IGW: 인터넷 접근 (Public)
NAT: 인터넷 접근 (Private)
VPC Peering: VPC 간 통신
VPN/DX: 온프레미스 연결
```

### 우선순위
```
Longest Prefix Match
더 구체적인 경로가 우선

10.0.1.0/28 > 10.0.1.0/24 > 10.0.0.0/16 > 0.0.0.0/0
```

### Public vs Private
```
Public: 0.0.0.0/0 → IGW
Private: 0.0.0.0/0 → NAT Gateway
```
