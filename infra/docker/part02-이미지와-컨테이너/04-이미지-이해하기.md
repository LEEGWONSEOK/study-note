# Chapter 4. 이미지 이해하기

## 4.1 Docker 이미지란?

Docker 이미지는 컨테이너를 실행하기 위한 **읽기 전용 템플릿**입니다.

> **핵심**: 이미지는 실행 가능한 패키지로, 코드, 런타임, 라이브러리, 환경변수, 설정 파일을 모두 포함합니다.

**비유**: 이미지는 **클래스(Class)** 와 같습니다.
- 이미지(Class) → 컨테이너(Instance) 관계
- 하나의 이미지로 여러 컨테이너를 실행 가능

```
Docker Image (nginx:latest)
├── 운영체제 라이브러리 (Debian slim)
├── nginx 바이너리
├── 기본 설정 파일 (/etc/nginx/nginx.conf)
├── 정적 파일 위치 (/usr/share/nginx/html)
└── 실행 명령어 (nginx -g "daemon off;")
```

## 4.2 이미지 네이밍 규칙

### 전체 형식

```
[레지스트리]/[네임스페이스]/[저장소]:[태그]
```

### 예시 분석

```
docker.io/library/nginx:latest
│         │       │     │
│         │       │     └── 태그 (버전)
│         │       └─────── 저장소 (이미지 이름)
│         └─────────────── 네임스페이스 (사용자/조직)
└───────────────────────── 레지스트리 (docker.io가 기본)
```

### 실제 사용 예시

```bash
# 공식 이미지 (레지스트리/네임스페이스 생략 가능)
nginx                         # = docker.io/library/nginx:latest
nginx:1.25                    # = docker.io/library/nginx:1.25
ubuntu:22.04                  # = docker.io/library/ubuntu:22.04

# 사용자 이미지
username/myapp:1.0            # Docker Hub의 개인 이미지
mycompany/myapp:v2.3.1        # Docker Hub의 조직 이미지

# Private Registry
registry.company.com/myapp:prod   # 사내 레지스트리
123456789.dkr.ecr.ap-northeast-2.amazonaws.com/myapp:latest  # AWS ECR
```

### 태그 전략

| 태그 | 의미 | 사용 시기 |
|------|------|----------|
| `latest` | 최신 버전 | 개발 환경 (운영 비권장) |
| `1.0.0` | Semantic Versioning | 운영 환경 권장 |
| `1.0` | 마이너 버전 | 유연한 업데이트 허용 시 |
| `1` | 메이저 버전 | 호환성 보장 시 |
| `stable` | 안정 버전 | 안정성 우선 |
| `alpine` | Alpine 기반 경량 | 이미지 크기 최소화 |
| `slim` | 최소 패키지 | 이미지 크기 중간 |

> **운영 환경 권장**: `latest` 태그는 언제든 변경될 수 있으므로, 운영에서는 **정확한 버전 태그** 사용을 강력 권장합니다.

## 4.3 공식 이미지 vs 커스텀 이미지

### 공식 이미지 (Official Images)

Docker Inc. 또는 해당 프로젝트에서 직접 관리하는 이미지입니다.

**특징**:
- Docker Hub에서 `library/` 네임스페이스
- 보안 검토 및 업데이트 보장
- 문서화 잘 되어 있음
- `[Official Image]` 배지 표시

**주요 공식 이미지**:
```bash
# OS 기반
ubuntu:22.04
debian:bookworm-slim
alpine:3.18
centos:7

# 런타임
openjdk:17-jdk-slim
node:18-alpine
python:3.11-slim
golang:1.21

# 데이터베이스
mysql:8.0
postgresql:15
redis:7-alpine
mongodb:6.0

# 웹서버
nginx:1.25
httpd:2.4        # Apache

# 기타
rabbitmq:3-management
elasticsearch:8.10.0
grafana/grafana:10.0.0
```

### 커스텀 이미지

개인 또는 조직이 만든 이미지입니다.

```bash
# 빌드
docker build -t myapp:1.0 .

# 태그 추가
docker tag myapp:1.0 username/myapp:1.0

# Docker Hub에 공유
docker push username/myapp:1.0
```

### 이미지 선택 기준

| 기준 | 설명 |
|------|------|
| 공식 이미지 우선 | 검증된 보안, 안정적인 업데이트 |
| Alpine 변형 선호 | 이미지 크기 최소화 (보안 취약점 감소) |
| Slim 변형 | Alpine이 너무 가벼울 때 (glibc 필요 등) |
| 태그 고정 | `latest` 대신 정확한 버전 사용 |

## 4.4 이미지 검색

### Docker Hub에서 검색

```bash
# CLI로 검색
docker search nginx

# 결과 예시
# NAME                              DESCRIPTION                    STARS     OFFICIAL
# nginx                             Official build of Nginx.       19126     [OK]
# unit                              Official build of NGINX Unit   30        [OK]
# nginxinc/nginx-unprivileged       Unprivileged regular Nginx i   137

# 공식 이미지만 검색
docker search --filter is-official=true nginx

# 별점 100 이상
docker search --filter stars=100 node

# 출력 개수 제한
docker search --limit 5 mysql
```

### Docker Hub 웹사이트

[https://hub.docker.com](https://hub.docker.com) 에서 검색:
- 이미지 태그 목록 확인 가능
- Dockerfile 소스 링크
- 사용법 문서 (README)
- 지원 태그 목록

## 4.5 이미지 다운로드와 관리

### docker pull

```bash
# 최신 버전 다운로드
docker pull nginx

# 특정 버전
docker pull nginx:1.25.3

# 특정 플랫폼 (Apple Silicon에서 amd64 이미지 필요 시)
docker pull --platform linux/amd64 nginx

# 모든 태그 다운로드
docker pull --all-tags nginx
```

### 이미지 목록 관리

```bash
# 전체 이미지 목록
docker images
docker image ls

# 특정 이미지 필터링
docker images nginx
docker images --filter "reference=nginx:*"

# 이미지 크기 정렬
docker images --format "table {{.Repository}}\t{{.Tag}}\t{{.Size}}" | sort -k3

# JSON 형식 출력
docker images --format json

# 특정 필드만 출력
docker images --format "{{.Repository}}:{{.Tag}}\t{{.Size}}"
```

### 이미지 삭제

```bash
# 특정 이미지 삭제
docker rmi nginx:latest

# 여러 이미지 삭제
docker rmi nginx mysql redis

# 사용 중인 이미지 강제 삭제
docker rmi -f nginx

# 태그 없는(dangling) 이미지 삭제
docker image prune

# 사용하지 않는 모든 이미지 삭제
docker image prune -a

# 특정 날짜 이전 이미지 삭제
docker image prune -a --filter "until=2024-01-01"
```

## 4.6 이미지 메타데이터 확인

### docker inspect

```bash
# 이미지 전체 정보
docker inspect nginx

# 특정 정보만 추출
# 이미지 생성 날짜
docker inspect --format '{{.Created}}' nginx

# 환경변수 목록
docker inspect --format '{{range .Config.Env}}{{println .}}{{end}}' nginx

# 기본 실행 명령어
docker inspect --format '{{.Config.Cmd}}' nginx

# 노출된 포트
docker inspect --format '{{json .Config.ExposedPorts}}' nginx

# 이미지 레이어 수
docker inspect --format '{{len .RootFS.Layers}}' nginx
```

### docker history - 레이어 이력

```bash
# 이미지 레이어 이력 확인
docker history nginx

# 출력 예시
# IMAGE          CREATED       CREATED BY                                      SIZE
# a6bd71f48f68   2 weeks ago   /bin/sh -c #(nop)  CMD ["nginx" "-g" "daemon…   0B
# <missing>      2 weeks ago   /bin/sh -c #(nop)  STOPSIGNAL SIGQUIT           0B
# <missing>      2 weeks ago   /bin/sh -c #(nop)  EXPOSE 80                    0B
# ...

# 전체 명령어 표시 (축약 없이)
docker history --no-trunc nginx

# 크기 정보 표시
docker history --format "{{.Size}}\t{{.CreatedBy}}" nginx
```

## 4.7 이미지 저장/불러오기

### docker save - 이미지를 파일로 저장

오프라인 환경이나 이미지 이동 시 유용합니다:

```bash
# tar 파일로 저장
docker save nginx -o nginx.tar
docker save nginx > nginx.tar

# 여러 이미지를 하나의 파일로
docker save nginx mysql redis -o multi-images.tar

# gzip 압축 (크기 감소)
docker save nginx | gzip > nginx.tar.gz
```

### docker load - 파일에서 이미지 불러오기

```bash
# tar 파일에서 이미지 로드
docker load -i nginx.tar
docker load < nginx.tar

# gzip 파일 로드
docker load < nginx.tar.gz

# 로드 후 이미지 확인
docker images
```

### export/import (컨테이너 → 이미지)

```bash
# 컨테이너 파일시스템을 tar로 내보내기
docker export 컨테이너명 > container.tar

# tar에서 이미지 생성 (레이어 정보 없음)
docker import container.tar myimage:1.0
```

**save vs export 차이**:

| 항목 | docker save | docker export |
|------|------------|---------------|
| 대상 | 이미지 | 컨테이너 |
| 레이어 정보 | 유지 | 평탄화 (단일 레이어) |
| 용도 | 이미지 이동 | 컨테이너 스냅샷 |

## 핵심 요약

1. **이미지**: 컨테이너의 읽기 전용 템플릿 (Class와 유사)
2. **네이밍**: `레지스트리/네임스페이스/저장소:태그`
3. **태그**: 운영에서는 `latest` 대신 정확한 버전 사용
4. **공식 이미지**: 보안 검증된 이미지, 우선 사용
5. **Alpine 변형**: 이미지 크기 최소화에 효과적
6. **save/load**: 오프라인 환경에서 이미지 이동 시 사용
