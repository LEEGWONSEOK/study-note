# Chapter 5. 컨테이너 생명주기

## 5.1 컨테이너 상태

컨테이너는 다음과 같은 상태를 가집니다:

| 상태 | 설명 |
|------|------|
| `created` | 생성됨, 아직 시작되지 않음 |
| `running` | 실행 중 |
| `paused` | 일시 중지됨 (프로세스 freeze) |
| `restarting` | 재시작 중 |
| `stopped` (exited) | 중지됨 |
| `dead` | 비정상 종료 |
| `removing` | 삭제 중 |

---

## 5.2 생명주기 다이어그램

```
docker create
     │
     ▼
┌─────────┐    docker start     ┌─────────┐
│ created │──────────────────►  │ running │
└─────────┘                     └─────────┘
                                     │    ▲
                         docker stop │    │ docker start
                         (SIGTERM)   │    │
                                     ▼    │
                                ┌─────────┐
                                │ stopped │◄── 프로세스 종료
                                │(exited) │
                                └─────────┘
                                     │
                                docker rm
                                     │
                                     ▼
                                  (삭제)

docker run = docker create + docker start
```

**일시 중지 흐름**:
```
running ──docker pause──► paused ──docker unpause──► running
```

## 5.3 컨테이너 생성 vs 실행

### docker create - 컨테이너만 생성

```bash
# 컨테이너 생성 (실행은 하지 않음)
docker create --name my-nginx nginx

# 생성된 컨테이너 확인 (created 상태)
docker ps -a
# CONTAINER ID  IMAGE   COMMAND   STATUS   NAMES
# abc123        nginx   "/doc…"   Created  my-nginx

# 이후 시작
docker start my-nginx
```

**사용 시기**: 컨테이너를 미리 설정해두고 나중에 시작하고 싶을 때

### docker run - 생성과 실행을 동시에

```bash
# 가장 일반적인 방법
docker run -d --name my-nginx -p 8080:80 nginx
```

`docker run` = `docker create` + `docker start`

## 5.4 포그라운드 vs 백그라운드 실행

### 포그라운드 실행 (기본)

```bash
# 터미널이 컨테이너에 연결됨
docker run nginx

# Ctrl+C로 컨테이너 중지됨
# 터미널이 점유됨
```

### 백그라운드 실행 (-d)

```bash
# 백그라운드에서 실행
docker run -d --name my-nginx nginx

# 컨테이너 ID만 출력
# abc123def456...

# 로그는 별도 확인
docker logs my-nginx
docker logs -f my-nginx  # 실시간 추적
```

### Attach - 실행 중인 컨테이너에 연결

```bash
# 실행 중인 컨테이너의 표준 입출력에 연결
docker attach my-nginx

# 주의: Ctrl+C는 컨테이너를 종료시킴
# 분리(detach)하려면: Ctrl+P, Ctrl+Q
```

## 5.5 컨테이너 내부 접속

### docker exec (권장)

```bash
# bash 쉘 접속
docker exec -it my-nginx bash

# Alpine 기반 (bash 없음)
docker exec -it my-alpine sh

# 특정 명령어 실행
docker exec my-nginx nginx -v
docker exec my-nginx cat /etc/nginx/nginx.conf

# 환경변수와 함께 실행
docker exec -e DEBUG=true -it my-nginx bash

# 특정 사용자로 실행
docker exec -u root -it my-nginx bash
docker exec -u 1001 -it my-nginx bash
```

### 컨테이너 내부에서 작업 예시

```bash
# nginx 컨테이너 접속
docker exec -it my-nginx bash

# 컨테이너 내부에서
root@abc123:/# ls /usr/share/nginx/html
50x.html  index.html

root@abc123:/# cat /etc/nginx/conf.d/default.conf
server {
    listen       80;
    server_name  localhost;
    ...
}

root@abc123:/# nginx -t  # 설정 파일 검증
root@abc123:/# exit      # 접속 종료
```

## 5.6 파일 복사 (docker cp)

### 호스트 → 컨테이너

```bash
# 파일 복사
docker cp ./index.html my-nginx:/usr/share/nginx/html/index.html

# 디렉토리 복사
docker cp ./html/ my-nginx:/usr/share/nginx/html/

# 실행 중이지 않아도 가능
```

### 컨테이너 → 호스트

```bash
# 로그 파일 복사
docker cp my-nginx:/var/log/nginx/access.log ./access.log

# 설정 파일 가져오기
docker cp my-nginx:/etc/nginx/nginx.conf ./nginx.conf

# 디렉토리 복사
docker cp my-nginx:/etc/nginx/ ./nginx-config/
```

**활용 사례**:
```bash
# 컨테이너 로그 분석을 위해 로컬로 복사
docker cp my-app:/app/logs/ ./logs/

# 설정 파일 수정 후 컨테이너에 반영
vi nginx.conf
docker cp nginx.conf my-nginx:/etc/nginx/nginx.conf
docker restart my-nginx
```

## 5.7 컨테이너를 이미지로 (docker commit)

실행 중인 컨테이너의 현재 상태를 이미지로 저장합니다.

```bash
# 기본 사용법
docker commit 컨테이너명|ID 이미지명:태그

# 예시: nginx에 커스텀 설정 추가 후 이미지로 저장
docker run -d --name my-nginx nginx
docker exec -it my-nginx bash
# 내부에서 파일 수정...
# exit
docker commit my-nginx my-nginx-custom:1.0

# 메시지와 작성자 정보 추가
docker commit \
  --message "Add custom nginx config" \
  --author "홍길동 <hong@example.com>" \
  my-nginx my-nginx-custom:1.0

# 이미지 확인
docker images my-nginx-custom
```

> **주의**: `docker commit`은 재현 불가능한 이미지를 만듭니다.
> Dockerfile을 사용하는 것이 훨씬 권장됩니다.
> commit은 디버깅이나 임시 스냅샷 용도로만 사용하세요.

## 5.8 컨테이너 변경사항 확인 (docker diff)

컨테이너가 시작된 이후 파일시스템 변경사항을 보여줍니다:

```bash
docker diff 컨테이너명|ID
```

**출력 형식**:
```
A /usr/share/nginx/html/index.html   # Added (추가)
C /var/log/nginx                     # Changed (변경)
C /var/log/nginx/access.log          # Changed
D /tmp/test.txt                      # Deleted (삭제)
```

**실습**:
```bash
# 컨테이너 실행
docker run -d --name test-nginx nginx

# 파일 추가
docker exec test-nginx bash -c "echo 'Hello' > /usr/share/nginx/html/hello.html"

# 변경사항 확인
docker diff test-nginx
# A /usr/share/nginx/html/hello.html
```

## 5.9 컨테이너 상태 전환 실습

```bash
# 1. 컨테이너 생성
docker create --name lifecycle-test nginx
docker ps -a  # Status: Created

# 2. 시작
docker start lifecycle-test
docker ps     # Status: Up X seconds

# 3. 일시 중지
docker pause lifecycle-test
docker ps     # Status: Up X seconds (Paused)

# 4. 재개
docker unpause lifecycle-test
docker ps     # Status: Up X seconds

# 5. 재시작
docker restart lifecycle-test

# 6. 중지
docker stop lifecycle-test
docker ps -a  # Status: Exited (0) X seconds ago

# 7. 재시작
docker start lifecycle-test

# 8. 삭제 (실행 중인 경우 -f 필요)
docker stop lifecycle-test
docker rm lifecycle-test
```

## 5.10 컨테이너 종료 코드

```bash
# 종료 코드 확인
docker inspect --format '{{.State.ExitCode}}' 컨테이너명
```

| 종료 코드 | 의미 |
|-----------|------|
| 0 | 정상 종료 |
| 1 | 애플리케이션 에러 |
| 125 | Docker 명령어 실패 |
| 126 | 명령어 실행 권한 없음 |
| 127 | 명령어를 찾을 수 없음 |
| 130 | Ctrl+C (SIGINT) |
| 137 | SIGKILL (강제 종료 또는 OOM) |
| 143 | SIGTERM (정상 종료 요청) |

```bash
# 종료된 컨테이너 상태 확인
docker ps -a
# CONTAINER ID  ...  STATUS              NAMES
# abc123        ...  Exited (0) 2m ago   normal-exit
# def456        ...  Exited (137) 1m ago oom-killed
```

## 핵심 요약

1. **컨테이너 상태**: created → running → stopped → (삭제)
2. **`docker run`**: create + start를 한 번에
3. **포그라운드 vs 백그라운드**: `-d` 옵션으로 백그라운드 실행
4. **접속**: `docker exec -it` 사용 (attach보다 권장)
5. **파일 복사**: `docker cp`로 호스트 ↔ 컨테이너 간 복사
6. **commit**: 임시 스냅샷용, 운영에는 Dockerfile 사용
7. **diff**: 파일시스템 변경사항 추적에 유용
