# Chapter 9. 멀티스테이지 빌드

## 9.1 멀티스테이지 빌드란?

하나의 Dockerfile에서 **여러 빌드 단계(stage)** 를 사용하여 최종 이미지 크기를 최소화하는 기법입니다.

> **핵심**: 빌드에 필요한 도구는 최종 이미지에 포함하지 않습니다.

**비유**: 자동차 공장과 같습니다.
- 공장(빌드 스테이지): 용접기, 도장기구 등 무거운 장비 사용
- 최종 자동차(실행 스테이지): 운전에 필요한 것만 포함

---

## 9.2 싱글 스테이지의 문제점

### 예시: Java 앱 싱글 스테이지

```dockerfile
# 문제 있는 Dockerfile
FROM maven:3.9-openjdk-17
WORKDIR /app
COPY . .
RUN mvn clean package -DskipTests
EXPOSE 8080
CMD ["java", "-jar", "target/app.jar"]
```

**문제점**:
```bash
docker images myapp
# REPOSITORY   TAG       SIZE
# myapp        latest    825MB  ← Maven, JDK, 소스코드 모두 포함!
```

포함된 불필요한 것들:
- Maven (mvn 명령어)
- 전체 JDK (컴파일러, javac 등)
- 소스 코드 (.java 파일)
- 빌드 임시 파일
- Maven 로컬 저장소 캐시

## 9.3 멀티스테이지 기본 문법

```dockerfile
# 스테이지 1: 빌드
FROM maven:3.9-openjdk-17 AS build   # ← AS로 이름 지정
WORKDIR /app
COPY . .
RUN mvn clean package -DskipTests

# 스테이지 2: 실행
FROM openjdk:17-jre-slim             # ← 가벼운 JRE만 사용
WORKDIR /app
COPY --from=build /app/target/app.jar app.jar  # ← 이전 스테이지에서 복사
EXPOSE 8080
CMD ["java", "-jar", "app.jar"]
```

**결과 비교**:
```
싱글 스테이지: 825MB
멀티스테이지: 210MB   ← 4배 감소!
```

### 스테이지 참조 방법

```dockerfile
# 이름으로 참조 (권장)
COPY --from=build /app/output ./

# 인덱스로 참조 (0부터 시작)
COPY --from=0 /app/output ./

# 외부 이미지 참조
COPY --from=nginx:latest /etc/nginx/nginx.conf /etc/nginx/nginx.conf
```

## 9.4 Java/Maven 멀티스테이지 예제

### 기본 예제

```dockerfile
# =============================================================================
# Stage 1: 의존성 다운로드 (캐시 최적화)
# =============================================================================
FROM maven:3.9-openjdk-17 AS dependencies
WORKDIR /app

# pom.xml만 먼저 복사하여 의존성 캐시
COPY pom.xml .
RUN mvn dependency:go-offline -B

# =============================================================================
# Stage 2: 빌드
# =============================================================================
FROM dependencies AS build
WORKDIR /app

# 소스 코드 복사 및 빌드
COPY src ./src
RUN mvn clean package -DskipTests

# =============================================================================
# Stage 3: 실행
# =============================================================================
FROM openjdk:17-jre-slim AS runtime

# 비root 사용자 생성
RUN addgroup --system spring && adduser --system spring --ingroup spring

WORKDIR /app

# 빌드된 JAR만 복사
COPY --from=build /app/target/app.jar app.jar

# 권한 설정
RUN chown spring:spring app.jar

USER spring:spring

EXPOSE 8080

# JVM 튜닝 옵션
ENV JAVA_OPTS="-Xmx512m -Xms256m"

HEALTHCHECK \
  --interval=30s \
  --timeout=10s \
  --start-period=60s \
  CMD curl -f http://localhost:8080/actuator/health || exit 1

ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]
```

### Spring Boot Layer 최적화 버전

```dockerfile
FROM maven:3.9-openjdk-17 AS build
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline -B
COPY src ./src
RUN mvn clean package -DskipTests

# Spring Boot Layer 추출
FROM openjdk:17-jre-slim AS layers
WORKDIR /app
COPY --from=build /app/target/app.jar app.jar
RUN java -Djarmode=layertools -jar app.jar extract

# 최종 실행 이미지
FROM openjdk:17-jre-slim
WORKDIR /app

RUN addgroup --system spring && adduser --system spring --ingroup spring

# 변경 빈도 순서로 복사 (캐시 최적화)
COPY --from=layers /app/dependencies/ ./
COPY --from=layers /app/spring-boot-loader/ ./
COPY --from=layers /app/snapshot-dependencies/ ./
COPY --from=layers /app/application/ ./

USER spring:spring
ENTRYPOINT ["java", "org.springframework.boot.loader.JarLauncher"]
```

## 9.5 Node.js 멀티스테이지 예제

```dockerfile
# =============================================================================
# Stage 1: 의존성 설치
# =============================================================================
FROM node:18-alpine AS deps
WORKDIR /app

COPY package*.json ./
RUN npm ci

# =============================================================================
# Stage 2: 빌드 (TypeScript 컴파일 등)
# =============================================================================
FROM node:18-alpine AS build
WORKDIR /app

COPY --from=deps /app/node_modules ./node_modules
COPY . .

RUN npm run build

# =============================================================================
# Stage 3: 운영 의존성만 설치
# =============================================================================
FROM node:18-alpine AS prod-deps
WORKDIR /app

COPY package*.json ./
RUN npm ci --only=production

# =============================================================================
# Stage 4: 최종 실행 이미지
# =============================================================================
FROM node:18-alpine AS runtime
WORKDIR /app

# 운영 의존성 복사
COPY --from=prod-deps /app/node_modules ./node_modules

# 빌드 결과물 복사
COPY --from=build /app/dist ./dist

# 비root 사용자
USER node

EXPOSE 3000
CMD ["node", "dist/server.js"]
```

### Next.js 최적화 예제

```dockerfile
FROM node:18-alpine AS base

# 의존성 스테이지
FROM base AS deps
RUN apk add --no-cache libc6-compat
WORKDIR /app

COPY package*.json ./
RUN npm ci

# 빌드 스테이지
FROM base AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .

ENV NEXT_TELEMETRY_DISABLED 1
RUN npm run build

# 실행 스테이지
FROM base AS runner
WORKDIR /app

ENV NODE_ENV production
ENV NEXT_TELEMETRY_DISABLED 1

RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs

COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

USER nextjs
EXPOSE 3000
ENV PORT 3000

CMD ["node", "server.js"]
```

## 9.6 Go 멀티스테이지 예제

Go는 단일 바이너리를 생성하므로 `scratch` 이미지 사용이 가능합니다.

```dockerfile
# =============================================================================
# Stage 1: 빌드
# =============================================================================
FROM golang:1.21-alpine AS build

WORKDIR /app

# 의존성 캐시
COPY go.mod go.sum ./
RUN go mod download

# 소스 코드 빌드
COPY . .

# 정적 바이너리 빌드 (외부 라이브러리 의존성 없음)
RUN CGO_ENABLED=0 GOOS=linux go build \
    -ldflags='-w -s' \
    -o /app/server \
    ./cmd/server

# =============================================================================
# Stage 2: 최소 실행 이미지 (scratch 또는 distroless)
# =============================================================================
FROM scratch AS runtime

# CA 인증서 (HTTPS 요청에 필요)
COPY --from=build /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/

# 시간대 정보
COPY --from=build /usr/share/zoneinfo /usr/share/zoneinfo

# 바이너리만 복사
COPY --from=build /app/server /server

EXPOSE 8080
ENTRYPOINT ["/server"]
```

**이미지 크기**:
```
Go + 전체 OS: 800MB+
Alpine:       20MB
scratch:      8MB     ← 극한의 최적화!
```

### distroless 사용 예시 (scratch보다 편리)

```dockerfile
FROM golang:1.21-alpine AS build
WORKDIR /app
COPY . .
RUN CGO_ENABLED=0 go build -o server .

FROM gcr.io/distroless/static-debian12
COPY --from=build /app/server /server
ENTRYPOINT ["/server"]
```

## 9.8 빌드 최적화 팁

### 특정 스테이지만 빌드

```bash
# 특정 스테이지까지만 빌드 (디버깅용)
docker build --target build -t myapp:build .

# 빌드 스테이지 결과물 확인
docker run --rm -it myapp:build sh
```

### 빌드 캐시 공유 (BuildKit)

```dockerfile
# BuildKit 마운트 캐시 사용
# syntax=docker/dockerfile:1
FROM maven:3.9-openjdk-17 AS build
WORKDIR /app
COPY pom.xml .

# Maven 로컬 저장소를 캐시로 마운트 (빌드 시마다 재사용)
RUN --mount=type=cache,target=/root/.m2 \
    mvn dependency:go-offline -B

COPY src ./src
RUN --mount=type=cache,target=/root/.m2 \
    mvn clean package -DskipTests
```

### 병렬 빌드 (BuildKit)

```dockerfile
# syntax=docker/dockerfile:1

# 두 스테이지가 독립적이면 병렬 실행
FROM base AS frontend
RUN npm run build

FROM base AS backend
RUN mvn package

FROM runtime
COPY --from=frontend /app/dist ./public
COPY --from=backend /app/target/app.jar ./
```

### 멀티플랫폼 빌드

```bash
# Apple Silicon에서 AMD64 이미지 빌드
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t myapp:latest \
  --push .
```

## 핵심 요약

1. **멀티스테이지**: 빌드 도구를 최종 이미지에서 제거
2. **AS 이름 지정**: 스테이지를 이름으로 참조
3. **COPY --from**: 이전 스테이지에서 필요한 파일만 가져오기
4. **크기 절감**: Java 825MB → 210MB (4배), Go 800MB → 8MB (100배)
5. **캐시 최적화**: 의존성 파일을 소스 코드보다 먼저 복사
6. **`--target`**: 특정 스테이지까지만 빌드 가능 (디버깅)
