# Chapter 19. Docker 로깅

## 19.1 Docker 로깅 개요

Docker는 컨테이너의 stdout/stderr 출력을 캡처하여 로그로 관리합니다.

> **핵심 원칙**: 컨테이너에서는 로그를 파일에 쓰지 말고 **stdout/stderr로 출력**하세요.

```
컨테이너 프로세스
    │ stdout
    │ stderr
    ▼
Docker 로깅 드라이버
    │
    ▼
┌─────────┬──────────┬──────────┐
│json-file│  syslog  │ fluentd  │  ...
└─────────┴──────────┴──────────┘
```

---

## 19.2 Docker 로깅 드라이버 종류

| 드라이버 | 저장 위치 | 특징 |
|---------|---------|------|
| `json-file` | 호스트 JSON 파일 | 기본값, `docker logs` 지원 |
| `local` | 바이너리 형식 | 더 효율적, `docker logs` 지원 |
| `syslog` | syslog 서버 | 시스템 로그와 통합 |
| `journald` | systemd journal | Linux systemd 환경 |
| `gelf` | Graylog | GELF 프로토콜 |
| `fluentd` | Fluentd | 중앙화된 로그 수집 |
| `awslogs` | AWS CloudWatch | AWS 환경 |
| `gcplogs` | GCP Logging | GCP 환경 |
| `splunk` | Splunk | 기업용 로그 분석 |
| `none` | 없음 | 로그 비활성화 |

## 19.3 json-file 드라이버 (기본)

### 기본 설정

```bash
# 로그 드라이버 확인
docker info | grep "Logging Driver"
# Logging Driver: json-file

# 로그 파일 위치
ls /var/lib/docker/containers/<container-id>/
# <container-id>-json.log
```

### 로그 로테이션 설정

기본값은 로그 크기 제한이 없어 디스크를 가득 채울 수 있습니다!

```bash
# 컨테이너 실행 시 로그 설정
docker run \
  --log-driver json-file \
  --log-opt max-size=10m \    # 파일 최대 크기
  --log-opt max-file=3 \      # 최대 파일 수
  nginx

# 결과: 10MB x 3 = 최대 30MB 로그 유지
```

### 전역 기본 설정 (/etc/docker/daemon.json)

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3",
    "labels": "service,version",
    "env": "NODE_ENV,APP_VERSION"
  }
}
```

```bash
# 설정 적용
sudo systemctl restart docker
```

## 19.4 docker logs 옵션

```bash
# 기본 로그 출력
docker logs 컨테이너명

# 실시간 로그 추적
docker logs -f 컨테이너명

# 마지막 N줄
docker logs --tail 100 컨테이너명

# 타임스탬프 포함
docker logs -t 컨테이너명

# 특정 시간 이후 로그
docker logs --since "2024-01-01T00:00:00" 컨테이너명
docker logs --since 1h 컨테이너명    # 1시간 전부터
docker logs --since 30m 컨테이너명   # 30분 전부터

# 특정 시간 이전 로그
docker logs --until "2024-01-02T00:00:00" 컨테이너명

# 실시간 + 마지막 50줄
docker logs -f --tail 50 컨테이너명

# 에러만 필터링 (grep 활용)
docker logs 컨테이너명 2>&1 | grep ERROR
```

### Docker Compose에서 로그

```bash
# 모든 서비스 로그
docker compose logs

# 실시간 + 여러 서비스
docker compose logs -f app db

# 마지막 N줄
docker compose logs --tail 200 app
```

## 19.5 syslog 드라이버

```bash
# syslog 서버로 전송
docker run \
  --log-driver syslog \
  --log-opt syslog-address=tcp://syslog-server:514 \
  --log-opt syslog-facility=daemon \
  --log-opt tag="myapp/{{.Name}}" \
  nginx

# 로컬 syslog
docker run \
  --log-driver syslog \
  --log-opt syslog-address=unix:///dev/log \
  nginx
```

> **주의**: syslog 사용 시 `docker logs` 명령어를 사용할 수 없습니다.

## 19.6 journald 드라이버 (Linux)

```bash
# systemd journald 사용
docker run \
  --log-driver journald \
  --log-opt tag="{{.Name}}" \
  nginx

# journalctl로 확인
journalctl CONTAINER_NAME=my-nginx
journalctl -u docker.service -f
```

## 19.7 Fluentd 드라이버

```bash
# Fluentd로 로그 전송
docker run \
  --log-driver fluentd \
  --log-opt fluentd-address=localhost:24224 \
  --log-opt tag="docker.{{.Name}}" \
  nginx
```

### Fluentd 설정 예시

```xml
# fluent.conf
<source>
  @type forward
  port 24224
</source>

<match docker.**>
  @type file
  path /var/log/docker
  append true
  <format>
    @type json
  </format>
  <buffer>
    timekey 1d
    timekey_use_utc true
  </buffer>
</match>
```

## 19.8 ELK Stack 연동 소개

Elasticsearch + Logstash + Kibana로 중앙화된 로그 관리:

```yaml
# docker-compose.yml (ELK + 앱)
services:
  app:
    image: myapp
    logging:
      driver: fluentd
      options:
        fluentd-address: fluentd:24224
        tag: app.{{.Name}}

  fluentd:
    image: fluent/fluentd-kubernetes-daemonset
    volumes:
      - ./fluentd/conf:/fluentd/etc
    ports:
      - "24224:24224"

  elasticsearch:
    image: elasticsearch:8.10.0
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
    volumes:
      - es-data:/usr/share/elasticsearch/data
    ports:
      - "9200:9200"

  kibana:
    image: kibana:8.10.0
    ports:
      - "5601:5601"
    depends_on:
      - elasticsearch

volumes:
  es-data:
```

## 19.9 로깅 모범 사례

### 1. 앱에서 stdout/stderr 사용

```javascript
// Node.js - console.log → stdout, console.error → stderr
console.log('요청 처리됨:', req.path);         // stdout
console.error('오류 발생:', error.message);    // stderr
```

```java
// Java - SLF4J/Logback을 stdout으로 설정
// logback-spring.xml
// <appender name="STDOUT" class="ch.qos.logback.core.ConsoleAppender">
//   <encoder>
//     <pattern>%d{yyyy-MM-dd HH:mm:ss} [%level] %logger: %msg%n</pattern>
//   </encoder>
// </appender>
```

### 2. 구조화된 JSON 로그 사용

```javascript
// 구조화된 로그 (JSON)
console.log(JSON.stringify({
  timestamp: new Date().toISOString(),
  level: 'info',
  service: 'user-service',
  message: '사용자 생성됨',
  userId: user.id,
  duration: 125
}));
```

### 3. 로그 레벨 구분

```
ERROR: 즉시 대응 필요한 오류
WARN:  잠재적 문제
INFO:  주요 비즈니스 이벤트
DEBUG: 개발/디버깅용 상세 정보 (운영에서는 비활성화)
```

### 4. 로그 로테이션 항상 설정

```yaml
# docker-compose.yml의 모든 서비스에 적용
x-logging: &logging
  driver: json-file
  options:
    max-size: "50m"
    max-file: "5"

services:
  app:
    logging: *logging
  db:
    logging: *logging
```

### 5. 민감 정보 로그 출력 금지

```javascript
// 나쁜 예
console.log('로그인 시도:', { username, password }); // 비밀번호 노출!

// 좋은 예
console.log('로그인 시도:', { username }); // 비밀번호 제외
```

## 핵심 요약

1. **json-file**: 기본 드라이버, `docker logs` 지원
2. **로그 로테이션 필수**: `max-size` + `max-file` 설정
3. **stdout/stderr 출력**: 파일이 아닌 표준 출력 사용
4. **구조화된 로그**: JSON 형식으로 파싱 용이하게
5. **ELK/Fluentd**: 대규모 환경에서 중앙화된 로그 관리
6. **민감 정보 금지**: 비밀번호, 토큰 등 로그에 출력 금지
