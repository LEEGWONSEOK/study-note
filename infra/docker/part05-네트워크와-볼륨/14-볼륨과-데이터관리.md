# Chapter 14. 볼륨과 데이터 관리

## 14.1 데이터 지속성 문제

컨테이너는 기본적으로 **일시적(ephemeral)** 입니다.

```bash
# MySQL 컨테이너 실행 및 데이터 생성
docker run -d --name mysql-test -e MYSQL_ROOT_PASSWORD=secret mysql:8.0
docker exec -it mysql-test mysql -u root -p
# CREATE DATABASE testdb;
# CREATE TABLE users (id INT, name VARCHAR(50));
# INSERT INTO users VALUES (1, '홍길동');
# exit

# 컨테이너 삭제
docker rm -f mysql-test

# 다시 실행 → 데이터 사라짐!
docker run -d --name mysql-test -e MYSQL_ROOT_PASSWORD=secret mysql:8.0
docker exec -it mysql-test mysql -u root -p
# SHOW DATABASES;  ← testdb 없음!
```

**해결책**: 볼륨(Volume) 사용

---

## 14.2 볼륨 종류

### 1. Docker Volume (Named Volume)

Docker가 관리하는 볼륨으로 가장 권장되는 방식입니다.

```bash
# 볼륨 생성
docker volume create mysql-data

# 볼륨 사용
docker run -v mysql-data:/var/lib/mysql mysql:8.0

# 볼륨 위치 (macOS/Windows: VM 내부)
# Linux: /var/lib/docker/volumes/mysql-data/_data
```

```
Host Machine
└── /var/lib/docker/volumes/
    └── mysql-data/
        └── _data/          ← 실제 데이터 저장
            ├── mysql/
            ├── testdb/
            └── ...
```

### 2. Bind Mount

호스트의 특정 경로를 컨테이너에 마운트합니다.

```bash
# 현재 디렉토리를 컨테이너에 마운트
docker run -v $(pwd)/data:/var/lib/mysql mysql:8.0

# 절대 경로 사용
docker run -v /home/user/mysql-data:/var/lib/mysql mysql:8.0
```

```
Host Machine
└── /home/user/mysql-data/    ← 직접 접근 가능!
    ├── mysql/
    └── testdb/
```

### 3. tmpfs Mount

메모리에 임시 저장합니다. 컨테이너 종료 시 데이터 삭제됩니다.

```bash
# 메모리에 임시 마운트
docker run --tmpfs /app/cache myapp
docker run --mount type=tmpfs,destination=/app/cache,tmpfs-size=100m myapp
```

### 볼륨 종류 비교

| 항목 | Named Volume | Bind Mount | tmpfs |
|------|-------------|-----------|-------|
| 데이터 위치 | Docker 관리 영역 | 호스트 경로 | 메모리 |
| 이식성 | 높음 | 낮음 | 없음 |
| 성능 | 좋음 | 좋음 | 매우 빠름 |
| 직접 접근 | 어려움 | 쉬움 | 불가 |
| 백업 | 쉬움 | 쉬움 | 불가 |
| 권장 사용 | DB 데이터, 앱 데이터 | 개발 소스코드, 설정 | 임시 파일, 캐시 |

## 14.3 Docker Volume 명령어

```bash
# 볼륨 생성
docker volume create myvolume

# 볼륨 목록
docker volume ls

# 볼륨 상세 정보
docker volume inspect myvolume
# 출력:
# [
#   {
#     "Name": "myvolume",
#     "Driver": "local",
#     "Mountpoint": "/var/lib/docker/volumes/myvolume/_data",
#     ...
#   }
# ]

# 사용하지 않는 볼륨 삭제
docker volume prune

# 특정 볼륨 삭제
docker volume rm myvolume

# 컨테이너와 함께 볼륨 삭제
docker rm -v 컨테이너명
```

## 14.4 볼륨 백업과 복원

### 볼륨 백업

```bash
# 볼륨 데이터를 tar로 백업
docker run --rm \
  -v mysql-data:/data \
  -v $(pwd)/backup:/backup \
  alpine tar czf /backup/mysql-backup-$(date +%Y%m%d).tar.gz -C /data .

# 확인
ls -la backup/
# mysql-backup-20240101.tar.gz
```

### 볼륨 복원

```bash
# 새 볼륨에 백업 데이터 복원
docker volume create mysql-data-restored

docker run --rm \
  -v mysql-data-restored:/data \
  -v $(pwd)/backup:/backup \
  alpine tar xzf /backup/mysql-backup-20240101.tar.gz -C /data

# 복원된 볼륨으로 MySQL 실행
docker run -d \
  --name mysql-restored \
  -v mysql-data-restored:/var/lib/mysql \
  mysql:8.0
```

### MySQL 전용 백업 (mysqldump)

```bash
# MySQL 데이터 dump
docker exec mysql-container mysqldump \
  -u root -psecret \
  --all-databases \
  > backup.sql

# 복원
docker exec -i mysql-container mysql \
  -u root -psecret \
  < backup.sql
```

## 14.5 데이터베이스 데이터 관리

### MySQL 영구 데이터 저장

```bash
# Named Volume으로 MySQL 실행
docker run -d \
  --name mysql \
  -e MYSQL_ROOT_PASSWORD=secret \
  -e MYSQL_DATABASE=myapp \
  -v mysql-data:/var/lib/mysql \
  mysql:8.0

# 컨테이너 삭제해도 볼륨은 유지됨
docker rm mysql

# 동일 볼륨으로 재실행 → 데이터 복원!
docker run -d \
  --name mysql \
  -e MYSQL_ROOT_PASSWORD=secret \
  -v mysql-data:/var/lib/mysql \
  mysql:8.0
```

### PostgreSQL 영구 데이터

```bash
docker run -d \
  --name postgres \
  -e POSTGRES_PASSWORD=secret \
  -e POSTGRES_DB=myapp \
  -v postgres-data:/var/lib/postgresql/data \
  postgres:15-alpine
```

### MongoDB 영구 데이터

```bash
docker run -d \
  --name mongodb \
  -e MONGO_INITDB_ROOT_USERNAME=root \
  -e MONGO_INITDB_ROOT_PASSWORD=secret \
  -v mongodb-data:/data/db \
  mongo:6.0
```

## 14.6 Named Volume vs Anonymous Volume

### Named Volume (권장)

```bash
# 이름이 있는 볼륨
docker run -v mysql-data:/var/lib/mysql mysql:8.0

# 볼륨 목록에서 이름으로 식별 가능
docker volume ls
# DRIVER    VOLUME NAME
# local     mysql-data
```

### Anonymous Volume (비권장)

```bash
# 이름 없는 볼륨 (자동 생성)
docker run -v /var/lib/mysql mysql:8.0

# 볼륨 목록에 해시값으로 표시
docker volume ls
# DRIVER    VOLUME NAME
# local     a3f8b2c9d1e4f5a6...   ← 관리 어려움!
```

### Dockerfile의 VOLUME 지시자

```dockerfile
# 이미지에서 선언된 볼륨 → 자동 anonymous volume 생성
VOLUME /var/lib/mysql
```

```bash
# 재정의하지 않으면 anonymous volume 사용
docker run mysql:8.0

# Named volume으로 재정의 (권장)
docker run -v mysql-data:/var/lib/mysql mysql:8.0
```

## 14.7 Compose에서 볼륨 설정

```yaml
services:
  db:
    image: mysql:8.0
    volumes:
      # Named volume 사용
      - mysql-data:/var/lib/mysql

      # 초기화 SQL 파일 마운트
      - ./sql/init.sql:/docker-entrypoint-initdb.d/init.sql:ro

      # 설정 파일 마운트
      - ./mysql/my.cnf:/etc/mysql/my.cnf:ro

  app:
    image: myapp
    volumes:
      # Named volume
      - app-logs:/app/logs

      # 개발 시 소스 코드 마운트 (bind mount)
      - ./src:/app/src

      # node_modules 제외 (익명 볼륨 트릭)
      - /app/node_modules

  redis:
    image: redis:7-alpine
    volumes:
      - redis-data:/data

volumes:
  mysql-data:             # Named volume 선언
    driver: local

  app-logs:

  redis-data:

  # 외부 볼륨 참조
  external-storage:
    external: true
    name: existing-volume-name
```

## 14.8 볼륨 성능 최적화

### macOS/Windows에서 Bind Mount 성능

macOS/Windows에서는 bind mount가 느릴 수 있습니다:

```yaml
services:
  app:
    volumes:
      # 기본 (느림)
      - .:/app

      # 캐시 일관성 옵션 (개선됨)
      - type: bind
        source: .
        target: /app
        consistency: cached    # 쓰기보다 읽기 성능 우선
```

### node_modules 볼륨 트릭

```yaml
services:
  app:
    volumes:
      - .:/app                 # 소스 코드 마운트
      - /app/node_modules      # node_modules는 컨테이너 것 사용
```

```
이유: 호스트의 node_modules (macOS 빌드)를
     컨테이너 내부의 node_modules로 덮어쓰면 안 됨
     (바이너리 등이 다를 수 있음)
```

## 핵심 요약

1. **컨테이너는 일시적**: 삭제하면 데이터 사라짐
2. **Named Volume**: Docker 관리, 가장 권장
3. **Bind Mount**: 개발 환경, 소스코드 동기화에 적합
4. **tmpfs**: 임시 데이터, 메모리에 저장
5. **백업**: Alpine + tar로 볼륨 백업 가능
6. **Named vs Anonymous**: 항상 Named Volume 사용
