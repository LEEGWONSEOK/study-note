# Chapter 13. Docker 네트워크

## 13.1 Docker 네트워크 개요

Docker 네트워크는 컨테이너들이 서로 통신하는 방법을 정의합니다.

```bash
# 현재 네트워크 목록 확인
docker network ls

# 출력 예시
# NETWORK ID     NAME      DRIVER    SCOPE
# abc123def456   bridge    bridge    local
# ghi789jkl012   host      host      local
# mno345pqr678   none      null      local
```

---

## 13.2 Docker 네트워크 종류

| 드라이버 | 설명 | 사용 시기 |
|---------|------|----------|
| `bridge` | 가상 브리지 네트워크 (기본) | 단일 호스트 컨테이너 간 통신 |
| `host` | 호스트 네트워크 직접 사용 | 성능 최우선, 포트 충돌 주의 |
| `none` | 네트워크 없음 | 완전한 네트워크 격리 |
| `overlay` | 여러 Docker 호스트 간 연결 | Docker Swarm, 분산 환경 |
| `macvlan` | MAC 주소 할당, 물리 네트워크 접속 | 레거시 앱 마이그레이션 |

## 13.3 bridge 네트워크 (기본)

### 기본 bridge 네트워크

Docker 설치 시 자동으로 생성되는 `bridge` 네트워크입니다.

```bash
# 기본 bridge에서 컨테이너 실행
docker run -d --name container1 nginx
docker run -d --name container2 nginx

# 컨테이너 IP 확인
docker inspect container1 | grep IPAddress
# "IPAddress": "172.17.0.2"

docker inspect container2 | grep IPAddress
# "IPAddress": "172.17.0.3"
```

**기본 bridge의 한계**:
```bash
# 기본 bridge에서는 이름으로 통신 불가
docker exec container1 ping container2
# ping: bad address 'container2'   ← 이름 해석 안 됨!

# IP로는 통신 가능
docker exec container1 ping 172.17.0.3
```

## 13.4 사용자 정의 네트워크 (권장)

```bash
# 사용자 정의 bridge 네트워크 생성
docker network create myapp-network

# 서브넷 지정
docker network create \
  --driver bridge \
  --subnet 172.20.0.0/16 \
  --gateway 172.20.0.1 \
  myapp-network

# 네트워크에 컨테이너 연결
docker run -d --name app1 --network myapp-network nginx
docker run -d --name app2 --network myapp-network nginx

# 이름으로 통신 가능!
docker exec app1 ping app2
# PING app2 (172.20.0.3): 56 data bytes  ← 자동 DNS 해석!
```

**사용자 정의 네트워크 장점**:
1. **자동 DNS**: 컨테이너 이름으로 통신 가능
2. **격리**: 다른 네트워크의 컨테이너와 격리
3. **동적 연결/해제**: 실행 중에도 연결 변경 가능

## 13.5 컨테이너 간 통신

### 같은 네트워크

```bash
# 두 컨테이너를 같은 네트워크에 배치
docker network create mynet
docker run -d --name db --network mynet mysql:8.0 -e MYSQL_ROOT_PASSWORD=secret
docker run -d --name app --network mynet myapp

# app에서 db로 접속 (서비스명 = DNS 이름)
# jdbc:mysql://db:3306/mydb   ← "db"가 컨테이너 이름이자 호스트명
```

### 여러 네트워크에 연결

```bash
# 컨테이너를 여러 네트워크에 연결
docker network create frontend
docker network create backend

docker run -d --name nginx --network frontend nginx
docker run -d --name app --network frontend myapp

# app을 backend 네트워크에도 연결
docker network connect backend app
docker run -d --name db --network backend mysql:8.0

# app은 frontend와 backend 모두 접근 가능
# nginx는 frontend에서만 접근 가능
# db는 backend에서만 접근 가능 (보안!)
```

### 네트워크 격리 확인

```bash
# nginx에서 db로 접근 불가 확인
docker exec nginx ping db
# ping: bad address 'db'  ← 다른 네트워크라 통신 불가

# app에서 db 접근 가능
docker exec app ping db
# PING db (172.19.0.2)...  ← 통신 가능
```

## 13.6 포트 바인딩

```bash
# 기본 포트 바인딩
docker run -p 8080:80 nginx
# 호스트 8080 → 컨테이너 80

# 특정 IP에만 바인딩 (보안)
docker run -p 127.0.0.1:8080:80 nginx
# 로컬호스트에서만 접근 가능

# 모든 IP 바인딩 (기본)
docker run -p 0.0.0.0:8080:80 nginx

# UDP 포트
docker run -p 53:53/udp dns-server

# 랜덤 포트 할당
docker run -P nginx
docker port 컨테이너명   # 할당된 포트 확인
```

### 포트 매핑 정보 확인

```bash
# 포트 매핑 확인
docker port my-nginx
# 80/tcp -> 0.0.0.0:8080
# 443/tcp -> 0.0.0.0:8443

docker ps
# PORTS: 0.0.0.0:8080->80/tcp
```

## 13.7 DNS 해석

Docker의 내장 DNS 서버가 컨테이너 이름을 IP로 자동 해석합니다.

```
┌─────────────────────────────────────┐
│           Docker Network            │
│                                     │
│  ┌─────────┐  ping "db"  ┌───────┐  │
│  │   app   │────────────►│Docker │  │
│  │ (앱서버) │  172.20.0.3◄│ DNS  │  │
│  └─────────┘             │서버   │  │
│                          └───────┘  │
│  ┌─────────┐                        │
│  │   db    │ 172.20.0.3             │
│  │ (데이터)  │                        │
│  └─────────┘                        │
└─────────────────────────────────────┘
```

```bash
# 컨테이너 내부에서 DNS 확인
docker exec myapp cat /etc/resolv.conf
# nameserver 127.0.0.11   ← Docker 내장 DNS 서버
# options ndots:0
```

### 네트워크 aliases

```bash
# 컨테이너에 별칭 추가
docker network connect \
  --alias database \
  --alias primary-db \
  mynet my-mysql

# 별칭으로도 접근 가능
docker exec myapp ping database
docker exec myapp ping primary-db
```

## 13.8 host 네트워크

```bash
# 호스트 네트워크 직접 사용
docker run --network host nginx

# 포트 바인딩 없이 호스트 포트 직접 사용
# http://localhost:80  ← 바로 접근 가능
```

**주의사항**:
- Linux에서만 완전히 동작 (macOS/Windows는 VM 내부 호스트)
- 포트 충돌 가능
- 네트워크 격리 없음

**사용 사례**: 성능이 매우 중요한 경우, 네트워크 모니터링 도구

## 13.9 네트워크 명령어

```bash
# 네트워크 목록
docker network ls

# 네트워크 상세 정보
docker network inspect myapp-network

# 네트워크 생성
docker network create mynet

# 컨테이너를 네트워크에 연결
docker network connect mynet 컨테이너명

# 컨테이너를 네트워크에서 분리
docker network disconnect mynet 컨테이너명

# 사용하지 않는 네트워크 삭제
docker network prune

# 특정 네트워크 삭제
docker network rm mynet
```

## 13.10 Compose에서 네트워크 설정

```yaml
services:
  nginx:
    image: nginx
    networks:
      - frontend          # frontend만 접근

  app:
    image: myapp
    networks:
      - frontend          # nginx와 통신
      - backend           # db와 통신

  db:
    image: mysql:8.0
    networks:
      - backend           # app만 접근 가능 (nginx 직접 접근 불가)

networks:
  frontend:
    driver: bridge
  backend:
    driver: bridge
    internal: true        # 외부 인터넷 차단
```

### Compose 기본 네트워크

```yaml
# networks를 명시하지 않으면 기본 네트워크 생성
services:
  app:
    image: myapp
  db:
    image: mysql:8.0

# 자동으로 'projectname_default' 네트워크 생성
# 모든 서비스가 이 네트워크에 자동 연결
```

## 핵심 요약

1. **bridge**: 기본 네트워크, 단일 호스트 사용
2. **사용자 정의 네트워크**: 자동 DNS, 격리, 권장 방식
3. **포트 바인딩**: `-p 호스트:컨테이너`로 외부 접근 허용
4. **DNS**: 컨테이너 이름이 자동으로 IP로 해석됨
5. **internal: true**: DB 등 내부 서비스를 외부 인터넷에서 차단
6. **멀티 네트워크**: 서비스 역할에 따라 네트워크 분리
