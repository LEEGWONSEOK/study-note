# Chapter 18. 이미지 보안

## 18.1 이미지 취약점 개요

Docker 이미지는 OS 패키지, 런타임, 라이브러리를 포함하며 이 중 하나라도 취약점이 있으면 보안 위험이 됩니다.

```
이미지 취약점 경로:
┌────────────────────────────────────┐
│           Application Code         │ ← npm, Maven 의존성
├────────────────────────────────────┤
│          Language Runtime          │ ← Node.js, JVM 취약점
├────────────────────────────────────┤
│             OS Packages            │ ← apt, apk 패키지
├────────────────────────────────────┤
│             Base Image             │ ← Ubuntu, Alpine
└────────────────────────────────────┘
```

## 18.2 이미지 취약점 스캔

### Docker Scout (내장 도구)

Docker Desktop 및 Docker CLI에 통합된 취약점 스캐너입니다:

```bash
# 이미지 스캔
docker scout cves nginx:latest

# 출력 예시:
# ✓ Indexed 187 packages
#
# ... Found 3 patchable vulnerabilities ...
#
# Critical: 1
# High: 2

# 간단한 요약
docker scout quickview nginx:latest

# 추천 수정사항
docker scout recommendations nginx:latest
```

### Trivy (오픈소스, 권장)

가장 널리 사용되는 오픈소스 취약점 스캐너입니다:

```bash
# Trivy 설치 (macOS)
brew install trivy

# 이미지 스캔
trivy image nginx:latest

# JSON 형식 출력
trivy image --format json nginx:latest > scan-result.json

# 심각도 필터링
trivy image --severity CRITICAL,HIGH nginx:latest

# Dockerfile 스캔 (IaC 검사)
trivy config .

# CI/CD에서 사용
trivy image --exit-code 1 --severity CRITICAL myapp:latest
# CRITICAL 취약점 있으면 비정상 종료
```

### Trivy CI/CD 통합 (GitHub Actions)

```yaml
# .github/workflows/security-scan.yml
name: 보안 스캔

on:
  push:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - name: 이미지 빌드
        run: docker build -t myapp:${{ github.sha }} .

      - name: Trivy 취약점 스캔
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: myapp:${{ github.sha }}
          format: 'sarif'
          output: 'trivy-results.sarif'
          severity: 'CRITICAL,HIGH'
          exit-code: '1'

      - name: 결과 업로드
        uses: github/codeql-action/upload-sarif@v2
        with:
          sarif_file: 'trivy-results.sarif'
```

## 18.3 최소 기반 이미지 사용

### scratch 이미지

완전히 빈 이미지로, Go 같은 정적 컴파일 언어에 적합합니다:

```dockerfile
FROM golang:1.21-alpine AS build
WORKDIR /app
COPY . .
RUN CGO_ENABLED=0 go build -o server .

# 바이너리만 포함된 최소 이미지
FROM scratch
COPY --from=build /app/server /server
COPY --from=build /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/
ENTRYPOINT ["/server"]
```

```
이미지 크기: ~5MB
취약점: OS 패키지 없으므로 거의 없음
```

### distroless 이미지

Google이 제공하는 최소 이미지로, 쉘이나 패키지 매니저가 없습니다:

```dockerfile
FROM openjdk:17-jdk-slim AS build
COPY . .
RUN mvn package

# distroless - 쉘 없는 최소 이미지
FROM gcr.io/distroless/java17-debian12
COPY --from=build target/app.jar /app.jar
ENTRYPOINT ["java", "-jar", "/app.jar"]
```

```bash
# 쉘이 없으므로 exec 접속 불가 (보안!)
docker exec myapp sh
# OCI runtime exec failed: exec failed: no such file or directory
```

### Alpine 이미지

경량 Linux 배포판으로 쉘 접근이 필요한 경우 사용합니다:

```dockerfile
FROM node:18-alpine

# 취약점 업데이트
RUN apk update && apk upgrade && rm -rf /var/cache/apk/*

WORKDIR /app
COPY . .
RUN npm ci --only=production

USER node
CMD ["node", "server.js"]
```

### 기반 이미지별 보안 비교

| 이미지 | 크기 | 취약점 수 (대략) | 쉘 접근 |
|--------|------|----------------|---------|
| ubuntu:22.04 | 77MB | 100+ | bash |
| debian:slim | 74MB | 50+ | bash |
| alpine:3.18 | 7MB | 5~ | ash |
| distroless | 5-50MB | 0-5 | 불가 |
| scratch | 0B | 0 | 불가 |

## 18.4 이미지 서명 (Docker Content Trust)

이미지의 무결성과 신뢰성을 검증합니다:

```bash
# Docker Content Trust 활성화
export DOCKER_CONTENT_TRUST=1

# 서명된 이미지만 pull 가능
docker pull nginx
# 서명이 없으면 오류 발생

# 이미지 서명 후 push
docker push username/myapp:1.0
# 서명 키 생성 및 서명됨
```

### 서명 키 관리

```bash
# 위임 키 생성
docker trust key generate signer1

# 서명자 추가
docker trust signer add --key signer1.pub signer1 username/myapp

# 서명된 이미지 정보 확인
docker trust inspect --pretty username/myapp:1.0
```

## 18.5 빌드 시 보안 고려사항

### ARG의 보안 취약점

```dockerfile
# 위험: 빌드 히스토리에 남음!
ARG API_KEY
RUN curl -H "Authorization: ${API_KEY}" https://api.example.com/

# 확인
docker history myapp --no-trunc
# ... RUN curl -H "Authorization: secretkey123" ...  ← 노출!
```

**해결책**:
```dockerfile
# 방법 1: BuildKit 시크릿 사용 (권장)
# syntax=docker/dockerfile:1
FROM ubuntu:22.04

# 빌드 시에만 존재하고 히스토리에 안 남음
RUN --mount=type=secret,id=api_key \
    API_KEY=$(cat /run/secrets/api_key) \
    curl -H "Authorization: ${API_KEY}" https://api.example.com/
```

```bash
# BuildKit 시크릿으로 빌드
DOCKER_BUILDKIT=1 docker build \
  --secret id=api_key,src=./secrets/api_key \
  -t myapp .
```

### 민감 정보를 이미지에 포함하지 않기

```dockerfile
# 나쁜 예
COPY .env /app/.env       # .env 파일 포함!
ENV DB_PASSWORD=secret    # ENV로 비밀번호 하드코딩

# 좋은 예
# 환경변수는 런타임에 docker run -e 또는 .env로 전달
# 이미지에는 포함하지 않음
```

```
# .dockerignore - 반드시 포함할 것!
.env
.env.*
*.secret
*.key
*.pem
secrets/
```

## 18.6 패키지 버전 고정

```dockerfile
# 나쁜 예 - 버전 미고정
FROM ubuntu:22.04
RUN apt-get install -y curl

# 좋은 예 - 버전 고정
FROM ubuntu:22.04
RUN apt-get update && apt-get install -y \
    curl=7.81.0-1ubuntu1.15 \
    && rm -rf /var/lib/apt/lists/*
```

```dockerfile
# Node.js - package.json에서 버전 고정
# "express": "4.18.2"   ← 정확한 버전 (^, ~ 사용 주의)

# 빌드 시 npm ci 사용 (package-lock.json 엄격 준수)
RUN npm ci --only=production
```

## 18.7 이미지 보안 자동화

### 정기 스캔 스크립트

```bash
#!/bin/bash
# scan-images.sh

IMAGES=(
  "nginx:latest"
  "mysql:8.0"
  "redis:7-alpine"
)

for IMAGE in "${IMAGES[@]}"; do
  echo "Scanning: $IMAGE"
  trivy image \
    --severity CRITICAL,HIGH \
    --exit-code 1 \
    "$IMAGE"
  if [ $? -ne 0 ]; then
    echo "CRITICAL/HIGH vulnerabilities found in $IMAGE"
    # 알림 발송 (Slack, 이메일 등)
  fi
done
```

### 베이스 이미지 자동 업데이트

```yaml
# Renovate Bot 설정 (renovate.json)
{
  "extends": ["config:base"],
  "docker": {
    "enabled": true
  },
  "packageRules": [
    {
      "matchDatasources": ["docker"],
      "automerge": true,
      "automergeType": "pr"
    }
  ]
}
```
