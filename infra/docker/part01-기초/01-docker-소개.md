# Chapter 1. Docker 소개

## 1.1 Docker란?

**Docker**는 2013년 Solomon Hykes가 개발한 **컨테이너 기반 가상화 플랫폼**입니다.

> **핵심 철학**: "한 번 빌드하고, 어디서나 실행" (Build Once, Run Anywhere)

애플리케이션과 그 실행에 필요한 모든 것(라이브러리, 설정 파일, 환경변수 등)을 하나의 **컨테이너**로 묶어서 어떤 환경에서든 동일하게 실행할 수 있게 해줍니다.

**비유**: Docker는 **표준 컨테이너 박스**와 같습니다.
- 국제 화물 운송에서 규격화된 컨테이너 덕분에 배, 기차, 트럭 어디든 실을 수 있듯이
- Docker 컨테이너는 개발 PC, 테스트 서버, 운영 서버 어디서든 동일하게 실행됩니다

## 1.2 VM vs Container 비교

### 가상 머신 (Virtual Machine)

VM은 **하드웨어 레벨**에서 가상화합니다.

```
┌──────────────────────────────────────┐
│           Applications               │
├──────────────┬───────────────────────┤
│   Guest OS   │      Guest OS         │
│  (Ubuntu)    │    (Windows)          │
├──────────────┴───────────────────────┤
│           Hypervisor                 │
│        (VMware, VirtualBox)          │
├──────────────────────────────────────┤
│           Host OS                    │
├──────────────────────────────────────┤
│           Hardware                   │
└──────────────────────────────────────┘
```

### 컨테이너 (Container)

컨테이너는 **OS 레벨**에서 가상화합니다.

```
┌────────────┬────────────┬────────────┐
│  Container │  Container │  Container │
│   (App A)  │   (App B)  │   (App C)  │
├────────────┴────────────┴────────────┤
│           Docker Engine              │
├──────────────────────────────────────┤
│           Host OS                    │
├──────────────────────────────────────┤
│           Hardware                   │
└──────────────────────────────────────┘
```

### VM vs Container 상세 비교

| 항목 | VM | Container |
|------|-----|-----------|
| 가상화 수준 | 하드웨어 | 운영체제 |
| 부팅 시간 | 수 분 | 수 초 (보통 1초 미만) |
| 이미지 크기 | GB 단위 | MB 단위 |
| 격리 수준 | 완전 격리 (강력) | 프로세스 격리 (충분) |
| 리소스 사용 | 높음 (OS 전체) | 낮음 (공유 OS 커널) |
| 이식성 | 낮음 | 매우 높음 |
| 밀집도 | 낮음 (수십 개) | 높음 (수백 개) |
| 보안 | 강력 | 상대적으로 낮음 |
| 주 사용처 | 완전한 OS 격리 필요 시 | 앱 배포, MSA |

> **결론**: 대부분의 애플리케이션 배포 시나리오에서 컨테이너가 VM보다 가볍고 빠르며 효율적입니다.

## 1.3 Docker 핵심 개념

### 1. 이미지 (Image)

컨테이너를 만들기 위한 **읽기 전용 템플릿**입니다.

**비유**: 이미지는 **붕어빵 틀**과 같습니다.
- 틀(이미지)로 붕어빵(컨테이너)을 여러 개 만들 수 있습니다
- 틀 자체는 변하지 않습니다 (읽기 전용)

```
Docker Image
├── Layer 1: Ubuntu 22.04 베이스
├── Layer 2: Java 17 설치
├── Layer 3: Spring Boot JAR 복사
└── Layer 4: 실행 명령어 설정
```

### 2. 컨테이너 (Container)

이미지를 실행한 **인스턴스**입니다. 이미지에 **쓰기 가능한 레이어**가 추가된 것입니다.

**비유**: 컨테이너는 **붕어빵**입니다.
- 같은 틀(이미지)로 만든 붕어빵(컨테이너)들은 동일한 모양
- 각 붕어빵은 독립적으로 존재 (한 개를 먹어도 다른 것에 영향 없음)

```
Image (읽기 전용)     Container (실행 중)
┌──────────────┐      ┌──────────────┐
│ Layer 4      │  →   │ 쓰기 레이어   │ ← 로그, 임시파일
│ Layer 3      │      │ Layer 4      │
│ Layer 2      │      │ Layer 3      │
│ Layer 1      │      │ Layer 2      │
└──────────────┘      │ Layer 1      │
                      └──────────────┘
```

### 3. 레지스트리 (Registry)

Docker 이미지를 **저장하고 배포**하는 저장소입니다.

**비유**: 레지스트리는 **앱스토어**와 같습니다.
- Docker Hub = Play Store / App Store
- 누구나 이미지를 올리고(push) 내려받을 수 있음(pull)

주요 레지스트리:
- **Docker Hub**: 공식 공개 레지스트리 (hub.docker.com)
- **AWS ECR**: Amazon Elastic Container Registry
- **GCR**: Google Container Registry
- **Harbor**: 오픈소스 Private Registry

### 4. Dockerfile

이미지를 **자동으로 빌드**하기 위한 설정 파일입니다.

**비유**: Dockerfile은 **요리 레시피**와 같습니다.
- 레시피(Dockerfile)대로 만들면 항상 동일한 요리(이미지) 완성

```dockerfile
# 예시 Dockerfile
FROM ubuntu:22.04           # 베이스 이미지
RUN apt-get install -y java # 패키지 설치
COPY app.jar /app/          # 파일 복사
CMD ["java", "-jar", "/app/app.jar"]  # 실행 명령
```

## 1.4 Docker 아키텍처

Docker는 **클라이언트-서버 아키텍처**로 동작합니다.

```
┌─────────────────────────────────────────────────────┐
│                  Docker Host                         │
│                                                     │
│  ┌────────────┐    REST API    ┌──────────────────┐  │
│  │   Docker   │◄──────────────►│  Docker Daemon   │  │
│  │   Client   │                │   (dockerd)      │  │
│  │ (docker)   │                │                  │  │
│  └────────────┘                │  ┌────────────┐  │  │
│                                │  │ Containers │  │  │
│                                │  └────────────┘  │  │
│                                │  ┌────────────┐  │  │
│                                │  │  Images    │  │  │
│                                │  └────────────┘  │  │
│                                └──────────────────┘  │
└─────────────────────────────────────────────────────┘
                                        │
                                        │ pull/push
                                        ▼
                               ┌──────────────────┐
                               │  Docker Registry  │
                               │   (Docker Hub)    │
                               └──────────────────┘
```

### Docker Client
- 사용자가 직접 상호작용하는 CLI 도구
- `docker` 명령어를 통해 Docker Daemon과 통신
- REST API 방식으로 통신

### Docker Daemon (dockerd)
- 백그라운드에서 실행되는 서버 프로세스
- 컨테이너 생성, 실행, 관리 담당
- 이미지 빌드 및 관리
- 네트워크, 볼륨 관리

### Docker Registry
- 이미지 저장소
- Docker Hub가 기본 레지스트리
- `docker pull` → 레지스트리에서 다운로드
- `docker push` → 레지스트리에 업로드

## 1.5 Docker가 해결하는 문제

### "내 PC에서는 되는데..." 문제

개발자라면 누구나 한 번쯤 겪은 상황:

```
개발자 A: "서버에 배포했는데 안 돼요!"
운영팀: "로컬에서는 됐잖아요?"
개발자 A: "제 PC에서는 잘 되는데..."
```

**원인**:
- 개발자 PC: Java 17, Node.js 18, 특정 환경변수 설정
- 서버: Java 11, Node.js 16, 다른 환경변수

**Docker 해결책**:
```dockerfile
# 개발 환경과 동일한 환경을 컨테이너로 고정
FROM openjdk:17-jdk-slim
COPY . /app
WORKDIR /app
RUN ./mvnw package
CMD ["java", "-jar", "target/app.jar"]
```

이제 어디서든 동일한 Java 17 환경에서 실행됩니다.

### 환경별 설정 문제

| 환경 | 문제 | Docker 해결 |
|------|------|------------|
| 개발 PC | OS, 버전 차이 | 동일한 컨테이너 이미지 사용 |
| 테스트 서버 | 라이브러리 충돌 | 격리된 컨테이너 환경 |
| 운영 서버 | 배포 복잡성 | `docker run` 한 줄로 배포 |
| MSA 환경 | 서비스 간 의존성 | 각 서비스 독립적 컨테이너화 |

### 배포 자동화 문제

**이전 방식**:
```bash
# 수동 배포 (에러 발생 가능성 높음)
ssh server
cd /app
git pull
mvn clean package
kill $(cat app.pid)
java -jar target/app.jar &
```

**Docker 방식**:
```bash
# 자동화된 배포
docker pull myapp:latest
docker stop myapp-container
docker run -d --name myapp-container myapp:latest
```

## 1.6 Docker 사용 사례

### 1. 마이크로서비스 아키텍처 (MSA)

```
┌──────────────────────────────────────────┐
│              Docker Compose              │
│                                          │
│  ┌──────────┐  ┌──────────┐  ┌────────┐  │
│  │  User    │  │ Product  │  │ Order  │  │
│  │ Service  │  │ Service  │  │Service │  │
│  │(Node.js) │  │(Spring)  │  │  (Go)  │  │
│  └──────────┘  └──────────┘  └────────┘  │
│        │             │            │       │
│  ┌─────▼─────────────▼────────────▼────┐  │
│  │              MySQL / Redis           │  │
│  └──────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

### 2. CI/CD 파이프라인

```
코드 Push → GitHub Actions → Docker 빌드 → 레지스트리 Push → 서버 배포
```

### 3. 로컬 개발 환경

```bash
# 로컬에 MySQL 설치 없이 DB 실행
docker run -d -p 3306:3306 -e MYSQL_ROOT_PASSWORD=password mysql:8.0

# Redis 실행
docker run -d -p 6379:6379 redis:7
```

### 4. 테스트 환경 격리

각 테스트마다 새로운 DB 컨테이너를 생성하여 독립적인 테스트 환경 구성

### 5. 클라우드 배포

AWS ECS, Google Cloud Run, Azure Container Instances 등 모든 클라우드에서 Docker 지원
