# Chapter 8. 비동기 기초

## 8.1 동기 vs 비동기

> 🎯 **핵심**: JavaScript는 **싱글 스레드**지만 **비동기 처리**가 가능합니다.

**비유**: 비동기는 **레스토랑 주문**입니다.

**동기 (Synchronous)**:
- 주문 → 요리 완료까지 대기 → 음식 받음 → 다음 손님 주문
- 한 번에 하나씩 순서대로 처리
- 앞 작업이 끝나야 다음 작업 시작

**비동기 (Asynchronous)**:
- 주문 → 진동벨 받음 → 다음 손님 주문 → ... → 요리 완료 알림 → 음식 받음
- 기다리는 동안 다른 일 처리 가능
- 작업 완료 시점이 다름

---

### Java와 비교

**Java - 멀티스레드 동기**:
```java
// 동기 처리 (블로킹)
public String fetchData() {
    Thread.sleep(2000);  // 2초 대기
    return "데이터";
}

public void processData() {
    System.out.println("시작");
    String data = fetchData();  // 2초 동안 블로킹
    System.out.println(data);
    System.out.println("완료");
}
// 출력: 시작 → (2초 대기) → 데이터 → 완료
```

**Java - 멀티스레드 비동기**:
```java
// CompletableFuture로 비동기 처리
public CompletableFuture<String> fetchDataAsync() {
    return CompletableFuture.supplyAsync(() -> {
        try {
            Thread.sleep(2000);
        } catch (InterruptedException e) {}
        return "데이터";
    });
}

public void processData() {
    System.out.println("시작");
    fetchDataAsync().thenAccept(data -> {
        System.out.println(data);
    });
    System.out.println("완료");
}
// 출력: 시작 → 완료 → (2초 후) → 데이터
```

**JavaScript - 싱글스레드 비동기**:
```javascript
// 비동기 처리 (논블로킹)
function fetchData() {
    return new Promise(resolve => {
        setTimeout(() => {
            resolve("데이터");
        }, 2000);
    });
}

async function processData() {
    console.log("시작");
    const data = await fetchData();  // 다른 작업은 계속 실행
    console.log(data);
    console.log("완료");
}
// 출력: 시작 → (2초 대기) → 데이터 → 완료
```

## 8.2 이벤트 루프 (Event Loop)

> 💡 **핵심**: JavaScript가 싱글 스레드인데도 비동기를 처리하는 비밀!

### 구조

```
┌───────────────────────────┐
│     Call Stack (호출 스택)    │  ← 실행 중인 코드
└───────────────────────────┘
            ↓
┌───────────────────────────┐
│      Web APIs               │  ← setTimeout, fetch 등
└───────────────────────────┘
            ↓
┌───────────────────────────┐
│    Callback Queue (큐)      │  ← 완료된 콜백 대기
└───────────────────────────┘
            ↓
┌───────────────────────────┐
│     Event Loop (루프)       │  ← Queue → Stack 이동
└───────────────────────────┘
```

**비유**: 이벤트 루프는 **배달 시스템**입니다.
- Call Stack: 주방 (요리 중인 음식)
- Web APIs: 배달원 (배달 중)
- Callback Queue: 대기실 (배달 완료, 픽업 대기)
- Event Loop: 매니저 (주방이 비면 대기실 음식을 주방으로)

---

### 실행 순서 예제

```javascript
console.log('1');

setTimeout(() => {
    console.log('2');
}, 0);

console.log('3');

// 출력: 1 → 3 → 2
// 왜? setTimeout은 비동기이므로 Queue로!
```

**단계별 설명**:
```javascript
// 1단계: console.log('1') → Call Stack → 실행 → 출력 "1"
// 2단계: setTimeout → Web API로 이동 (0ms 후 Callback Queue로)
// 3단계: console.log('3') → Call Stack → 실행 → 출력 "3"
// 4단계: Call Stack 비어있음 → Event Loop가 Queue의 콜백을 Stack으로
// 5단계: console.log('2') → 출력 "2"
```

---

### 복잡한 예제

```javascript
console.log('시작');

setTimeout(() => {
    console.log('setTimeout 1');
}, 0);

Promise.resolve()
    .then(() => console.log('Promise 1'))
    .then(() => console.log('Promise 2'));

setTimeout(() => {
    console.log('setTimeout 2');
}, 0);

console.log('끝');

// 출력:
// 시작
// 끝
// Promise 1
// Promise 2
// setTimeout 1
// setTimeout 2
```

**왜 이 순서일까?**
- **Microtask Queue** (우선순위 높음): Promise
- **Macrotask Queue** (우선순위 낮음): setTimeout, setInterval

Event Loop는 Microtask를 먼저 처리!

## 8.3 콜백 (Callback)

> 📌 **정의**: 다른 함수에 인자로 전달되는 함수

### 기본 예제

```javascript
// 동기 콜백
function greet(name, callback) {
    const message = `안녕하세요, ${name}님!`;
    callback(message);
}

greet('홍길동', (msg) => {
    console.log(msg);  // "안녕하세요, 홍길동님!"
});

// 배열 메서드의 콜백
[1, 2, 3].forEach((num) => {
    console.log(num);
});
```

---

### 비동기 콜백

```javascript
// setTimeout
setTimeout(() => {
    console.log('3초 후 실행');
}, 3000);

// 파일 읽기 (Node.js)
const fs = require('fs');

fs.readFile('data.txt', 'utf8', (err, data) => {
    if (err) {
        console.error('에러 발생:', err);
        return;
    }
    console.log('파일 내용:', data);
});

// HTTP 요청 (예전 방식)
function fetchUser(id, callback) {
    const xhr = new XMLHttpRequest();
    xhr.open('GET', `https://api.example.com/users/${id}`);
    xhr.onload = () => {
        if (xhr.status === 200) {
            callback(null, JSON.parse(xhr.response));
        } else {
            callback(new Error('요청 실패'), null);
        }
    };
    xhr.send();
}

fetchUser(1, (err, user) => {
    if (err) {
        console.error(err);
        return;
    }
    console.log(user);
});
```

---

### 콜백 지옥 (Callback Hell)

```javascript
// ❌ 콜백 지옥 - 읽기 어려움!
fetchUser(1, (err, user) => {
    if (err) {
        console.error(err);
        return;
    }

    fetchPosts(user.id, (err, posts) => {
        if (err) {
            console.error(err);
            return;
        }

        fetchComments(posts[0].id, (err, comments) => {
            if (err) {
                console.error(err);
                return;
            }

            fetchAuthor(comments[0].userId, (err, author) => {
                if (err) {
                    console.error(err);
                    return;
                }

                console.log('작성자:', author);
            });
        });
    });
});
```

**문제점**:
1. 가독성 나쁨 (들여쓰기 지옥)
2. 에러 처리 복잡
3. 유지보수 어려움

**비유**: 콜백 지옥은 **미로**입니다.
- 점점 깊어지는 중첩
- 어디서부터 시작했는지 헷갈림
- 탈출하기 어려움

## 8.4 타이머 함수

### setTimeout - 지연 실행

```javascript
// 기본 사용
setTimeout(() => {
    console.log('3초 후 실행');
}, 3000);

// 인자 전달
setTimeout((name, age) => {
    console.log(`${name}, ${age}살`);
}, 1000, '홍길동', 25);

// 취소
const timerId = setTimeout(() => {
    console.log('실행 안 됨');
}, 5000);

clearTimeout(timerId);  // 타이머 취소
```

---

### setInterval - 반복 실행

```javascript
// 1초마다 실행
const intervalId = setInterval(() => {
    console.log('1초마다 실행');
}, 1000);

// 5초 후 정지
setTimeout(() => {
    clearInterval(intervalId);
    console.log('정지');
}, 5000);

// 실용 예제: 카운트다운
let count = 10;
const intervalId = setInterval(() => {
    console.log(count--);
    if (count < 0) {
        clearInterval(intervalId);
        console.log('발사!');
    }
}, 1000);
```

---

### setInterval의 문제점

```javascript
// ❌ setInterval 문제: 이전 실행이 끝나지 않아도 다음 실행
setInterval(() => {
    // 이 작업이 2초 걸린다면?
    heavyTask();  // 2초 소요
}, 1000);  // 1초마다 실행 시도 → 문제 발생!

// ✅ 재귀 setTimeout 사용 (권장)
function schedule() {
    setTimeout(() => {
        heavyTask();  // 작업 실행
        schedule();   // 작업 완료 후 다음 스케줄
    }, 1000);
}
schedule();
```

## 8.5 에러 처리

### 동기 코드 에러 처리

```javascript
// try-catch
function divide(a, b) {
    if (b === 0) {
        throw new Error('0으로 나눌 수 없습니다');
    }
    return a / b;
}

try {
    const result = divide(10, 0);
    console.log(result);
} catch (error) {
    console.error('에러:', error.message);
} finally {
    console.log('항상 실행');
}
```

---

### 비동기 코드 에러 처리 (콜백)

```javascript
// 에러 우선 콜백 패턴 (Error-first callback)
function fetchData(callback) {
    setTimeout(() => {
        const error = Math.random() > 0.5 ? new Error('실패') : null;
        const data = error ? null : { id: 1, name: '홍길동' };
        callback(error, data);
    }, 1000);
}

fetchData((err, data) => {
    if (err) {
        console.error('에러 발생:', err.message);
        return;
    }
    console.log('데이터:', data);
});
```

## 8.6 실전 예제

### 순차 실행 (콜백 방식)

```javascript
function step1(callback) {
    setTimeout(() => {
        console.log('Step 1 완료');
        callback(null, 'result1');
    }, 1000);
}

function step2(prevResult, callback) {
    setTimeout(() => {
        console.log('Step 2 완료, 이전 결과:', prevResult);
        callback(null, 'result2');
    }, 1000);
}

function step3(prevResult, callback) {
    setTimeout(() => {
        console.log('Step 3 완료, 이전 결과:', prevResult);
        callback(null, 'final');
    }, 1000);
}

// 실행
step1((err, result1) => {
    if (err) return console.error(err);

    step2(result1, (err, result2) => {
        if (err) return console.error(err);

        step3(result2, (err, final) => {
            if (err) return console.error(err);
            console.log('최종 결과:', final);
        });
    });
});
```

### 병렬 실행 (콜백 방식)

```javascript
function fetchUserData(callback) {
    setTimeout(() => callback(null, { name: '홍길동' }), 1000);
}

function fetchUserPosts(callback) {
    setTimeout(() => callback(null, ['post1', 'post2']), 1500);
}

function fetchUserComments(callback) {
    setTimeout(() => callback(null, ['comment1']), 800);
}

// 모든 작업 완료 후 처리
let completed = 0;
const results = {};

function checkComplete() {
    if (completed === 3) {
        console.log('모든 데이터 로딩 완료:', results);
    }
}

fetchUserData((err, data) => {
    results.user = data;
    completed++;
    checkComplete();
});

fetchUserPosts((err, data) => {
    results.posts = data;
    completed++;
    checkComplete();
});

fetchUserComments((err, data) => {
    results.comments = data;
    completed++;
    checkComplete();
});
```

### Debounce (연속 이벤트 제어)

```javascript
function debounce(func, delay) {
    let timeoutId;

    return function(...args) {
        clearTimeout(timeoutId);

        timeoutId = setTimeout(() => {
            func.apply(this, args);
        }, delay);
    };
}

// 사용 예: 검색 입력
const searchInput = document.getElementById('search');
const handleSearch = debounce((event) => {
    console.log('검색:', event.target.value);
    // API 호출
}, 500);

searchInput.addEventListener('input', handleSearch);
// 타이핑 멈춘 후 500ms 뒤에만 실행
```

---

### Throttle (주기적 실행 제한)

```javascript
function throttle(func, delay) {
    let lastCall = 0;

    return function(...args) {
        const now = Date.now();

        if (now - lastCall >= delay) {
            lastCall = now;
            func.apply(this, args);
        }
    };
}

// 사용 예: 스크롤 이벤트
const handleScroll = throttle(() => {
    console.log('스크롤 위치:', window.scrollY);
}, 200);

window.addEventListener('scroll', handleScroll);
// 200ms마다 최대 1번만 실행
```

## 8.7 Web APIs

### fetch (HTTP 요청) - 기본

```javascript
// GET 요청
fetch('https://api.example.com/users')
    .then(response => {
        if (!response.ok) {
            throw new Error(`HTTP error! status: ${response.status}`);
        }
        return response.json();
    })
    .then(data => {
        console.log('사용자:', data);
    })
    .catch(error => {
        console.error('에러:', error);
    });

// POST 요청
fetch('https://api.example.com/users', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({
        name: '홍길동',
        email: 'hong@example.com'
    })
})
    .then(response => response.json())
    .then(data => console.log('생성됨:', data))
    .catch(error => console.error('에러:', error));
```

## 📝 핵심 요약

1. **동기 vs 비동기**:
   - 동기: 순차 실행, 블로킹
   - 비동기: 병렬 처리, 논블로킹

2. **이벤트 루프**:
   - Call Stack → Web APIs → Callback Queue → Event Loop
   - Microtask (Promise) > Macrotask (setTimeout)

3. **콜백**:
   - 비동기 처리의 기본
   - 콜백 지옥 문제 → Promise로 해결

4. **타이머**:
   - setTimeout: 지연 실행
   - setInterval: 반복 실행 (재귀 setTimeout 권장)

5. **패턴**:
   - Debounce: 마지막만 실행
   - Throttle: 주기적으로 실행
