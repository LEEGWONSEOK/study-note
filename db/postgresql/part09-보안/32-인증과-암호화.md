## 1. 인증과 암호화란? (비유로 이해하기)

### 🏢 은행 보안 시스템에 비유하면

```
PostgreSQL 보안 = 은행의 다층 보안
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🚪 1단계: 인증 (Authentication)
   = 은행 출입문에서 신분증 확인
   "당신이 누구입니까?"
   ├─ 비밀번호 (password)
   ├─ 인증서 (certificate)
   └─ 생체인식 (Kerberos, LDAP)

🔐 2단계: 권한 (Authorization)
   = 금고실 접근 권한
   "당신이 무엇을 할 수 있습니까?"
   ├─ SELECT만 가능 (창구 직원)
   ├─ INSERT/UPDATE 가능 (일반 직원)
   └─ 모든 권한 (지점장)

🔒 3단계: 암호화 (Encryption)
   = 봉투에 넣어 봉인
   ├─ 전송 암호화 (SSL/TLS) - 은행까지 가는 길
   └─ 저장 암호화 (pgcrypto) - 금고 안의 자물쇠

📹 4단계: 감사 (Audit)
   = CCTV 녹화
   "누가 언제 무엇을 했습니까?"
```

## 2. pg_hba.conf: 접근 제어의 핵심

### 📋 pg_hba.conf란?

```
pg_hba.conf = PostgreSQL Host-Based Authentication
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

역할: 누가 어디서 어떻게 접속할 수 있는지 정의

형식:
TYPE  DATABASE  USER  ADDRESS      METHOD
로컬  DB       사용자  IP주소       인증방법

예시:
local   all    postgres              peer
host    mydb   app_user  10.0.1.0/24  scram-sha-256
host    all    all       0.0.0.0/0    reject
```

### 🔧 pg_hba.conf 위치 �인

```bash
# 설정 파일 위치 확인
psql -U postgres -c "SHOW hba_file;"
#  /etc/postgresql/14/main/pg_hba.conf

# 또는
sudo -u postgres psql -c "SHOW hba_file;"

# 파일 열기
sudo nano /etc/postgresql/14/main/pg_hba.conf
```

### 📝 pg_hba.conf 구조

```ini
# TYPE  DATABASE        USER            ADDRESS                 METHOD

# 로컬 연결 (Unix 소켓)
local   all             postgres                                peer
local   all             all                                     md5

# IPv4 로컬 연결
host    all             all             127.0.0.1/32            scram-sha-256

# IPv6 로컬 연결
host    all             all             ::1/128                 scram-sha-256

# 원격 연결
host    all             all             0.0.0.0/0               reject
```

#### 각 필드 설명

```
1️⃣ TYPE (연결 타입):
   - local: Unix 소켓 (로컬만)
   - host:  TCP/IP (로컬 + 원격)
   - hostssl: SSL/TLS 필수
   - hostnossl: 암호화 안 함 (비권장)

2️⃣ DATABASE (데이터베이스):
   - all: 모든 DB
   - mydb: 특정 DB
   - mydb,otherdb: 여러 DB
   - sameuser: 사용자명과 같은 DB
   - @filename: 파일에 나열된 DB

3️⃣ USER (사용자):
   - all: 모든 사용자
   - postgres: 특정 사용자
   - @filename: 파일에 나열된 사용자
   - +groupname: 그룹 멤버

4️⃣ ADDRESS (주소):
   - 0.0.0.0/0: 모든 IP (위험!)
   - 127.0.0.1/32: localhost만
   - 10.0.1.0/24: 특정 서브넷
   - 192.168.1.100: 특정 IP
   - samenet: 같은 네트워크
   - samehost: 같은 호스트

5️⃣ METHOD (인증 방법):
   - trust: 인증 없음 (위험!)
   - reject: 거부
   - md5: MD5 해시 비밀번호 (레거시)
   - scram-sha-256: 강력한 비밀번호 (권장) ⭐
   - peer: OS 사용자명 매칭
   - ident: ident 서버 사용
   - password: 평문 비밀번호 (절대 사용 금지!)
   - cert: SSL 인증서
   - ldap: LDAP 인증
   - pam: PAM 인증
```

## 3. 실전 pg_hba.conf 설정

### 🎯 시나리오 1: 개발 환경 (로컬만)

```ini
# /etc/postgresql/14/main/pg_hba.conf

# TYPE  DATABASE  USER      ADDRESS       METHOD

# 로컬: postgres는 peer 인증 (OS 사용자 일치)
local   all       postgres                peer

# 로컬: 다른 사용자는 비밀번호
local   all       all                     scram-sha-256

# localhost (IPv4): 비밀번호 필수
host    all       all       127.0.0.1/32  scram-sha-256

# localhost (IPv6)
host    all       all       ::1/128       scram-sha-256

# 외부 접속 거부
host    all       all       0.0.0.0/0     reject
```

```bash
# 설정 적용
sudo systemctl reload postgresql

# 테스트
psql -U postgres  # ✅ 로컬에서 peer 인증
psql -U app_user -h 127.0.0.1  # ✅ 비밀번호 입력
psql -U app_user -h 192.168.1.100  # ❌ reject
```

### 🎯 시나리오 2: 프로덕션 환경 (네트워크 분리)

```ini
# /etc/postgresql/14/main/pg_hba.conf

# TYPE    DATABASE  USER          ADDRESS           METHOD

# 로컬 관리자
local     all       postgres                        peer

# 애플리케이션 서버 (사설 네트워크)
hostssl   myapp     app_user      10.0.1.0/24       scram-sha-256
hostssl   myapp     app_user      10.0.2.0/24       scram-sha-256

# 백업 서버 (특정 IP)
hostssl   all       backup_user   10.0.10.100/32    cert

# 모니터링 서버
host      all       monitoring    10.0.20.50/32     scram-sha-256

# VPN 네트워크 (개발자)
hostssl   all       +developers   172.16.0.0/16     scram-sha-256

# 읽기 전용 복제본
hostssl   replication  replication_user  10.0.30.0/24  scram-sha-256

# 나머지 모두 거부
host      all       all           0.0.0.0/0         reject
```

### 🎯 시나리오 3: 멀티 테넌트 SaaS

```ini
# TYPE    DATABASE    USER              ADDRESS         METHOD

# 로컬 관리
local     all         postgres                          peer

# 테넌트 A 전용 DB (SSL 필수)
hostssl   tenant_a    tenant_a_user     0.0.0.0/0       scram-sha-256

# 테넌트 B 전용 DB
hostssl   tenant_b    tenant_b_user     0.0.0.0/0       scram-sha-256

# 공유 서비스
hostssl   shared      shared_user       10.0.0.0/8      scram-sha-256

# 관리자 (특정 IP만)
hostssl   all         admin             203.0.113.0/24  cert

# 거부
host      all         all               0.0.0.0/0       reject
```

## 4. 인증 방법 비교

### 🔐 scram-sha-256 (권장) ⭐

```
가장 안전한 비밀번호 기반 인증
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ 장점:
   - Salt + 반복 해싱 (무차별 대입 공격 방어)
   - 재생 공격(replay attack) 방어
   - PostgreSQL 10+ 권장 방식

❌ 단점:
   - 구버전 클라이언트 호환성 이슈
```

#### 설정 방법
```sql
-- 1. postgresql.conf에서 기본 인증 방식 설정
-- password_encryption = scram-sha-256  (PostgreSQL 14+ 기본값)

-- 2. 기존 사용자 비밀번호 업그레이드
ALTER ROLE app_user WITH PASSWORD 'new_password';
-- 자동으로 scram-sha-256로 저장됨

-- 3. 사용자의 비밀번호 타입 확인
SELECT rolname, rolpassword FROM pg_authid WHERE rolname = 'app_user';
--  rolname  | rolpassword
-- ----------+---------------------------------------------------
--  app_user | SCRAM-SHA-256$4096:...
```

#### 클라이언트 연결
```bash
# psql
psql -U app_user -h db.example.com mydb
# Password: (입력)

# Node.js
const { Client } = require('pg');
const client = new Client({
  host: 'db.example.com',
  database: 'mydb',
  user: 'app_user',
  password: 'secure_password',
  ssl: { rejectUnauthorized: false }  // 프로덕션에서는 true
});
```

### 🔑 cert (인증서 기반)

```
SSL 클라이언트 인증서로 인증
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ 장점:
   - 비밀번호 불필요 (인증서가 신원 증명)
   - 매우 안전 (비밀번호 유출 걱정 없음)
   - 자동화에 적합 (백업, 모니터링)

❌ 단점:
   - 설정 복잡
   - 인증서 관리 필요
```

#### 설정 방법 (다음 섹션에서 상세 설명)

### 🔓 peer (로컬 전용)

```
OS 사용자명과 PostgreSQL 사용자명 일치 확인
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ 장점:
   - 비밀번호 불필요
   - 로컬 관리 편리

❌ 단점:
   - Unix 소켓만 (원격 불가)
   - OS 사용자와 DB 사용자명 일치 필요
```

```bash
# 사용 예:
# OS 사용자 postgres로 로그인 시
sudo -u postgres psql  # ✅ peer 인증으로 자동 로그인

# OS 사용자 ubuntu일 때
psql -U postgres  # ❌ peer authentication failed
```

### ❌ trust (절대 사용 금지!)

```
인증 없이 접속 허용
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

⚠️  매우 위험!
   - 누구나 접속 가능
   - 개발 환경에서도 비권장
   - 실수로 설정되면 보안 사고
```

## 5. SSL/TLS 암호화 연결

### 🔒 왜 SSL/TLS가 필요한가?

```
암호화 없는 연결 = 엽서로 비밀번호 보내기
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

❌ 평문 전송:
   클라이언트 ──[비밀번호: abc123]──> 서버
                  ↑ 중간에서 누구나 볼 수 있음!

✅ SSL/TLS 암호화:
   클라이언트 ──[암호화된 데이터]──> 서버
                  ↑ 해독 불가능!
```

### 🛠️ SSL 인증서 생성

#### 1단계: 서버 인증서 생성
```bash
# 1. 인증서 디렉토리 생성
sudo mkdir -p /etc/postgresql/14/main/certs
cd /etc/postgresql/14/main/certs

# 2. Private Key 생성
sudo openssl genrsa -out server.key 2048
sudo chmod 600 server.key
sudo chown postgres:postgres server.key

# 3. 인증서 서명 요청 (CSR) 생성
sudo openssl req -new -key server.key -out server.csr
# 입력 예:
# Country Name: KR
# State: Seoul
# Organization: MyCompany
# Common Name: db.example.com  (중요: 서버 도메인명)

# 4. 자체 서명 인증서 생성 (테스트용)
sudo openssl x509 -req -days 365 -in server.csr \
  -signkey server.key -out server.crt

# 또는 CA에서 서명받은 인증서 사용 (프로덕션)
# (Let's Encrypt, DigiCert 등)

# 5. 권한 설정
sudo chmod 600 server.key
sudo chmod 644 server.crt
sudo chown postgres:postgres server.key server.crt
```

#### 2단계: PostgreSQL 설정
```bash
# postgresql.conf 수정
sudo nano /etc/postgresql/14/main/postgresql.conf
```

```ini
# postgresql.conf

# SSL 활성화
ssl = on
ssl_cert_file = '/etc/postgresql/14/main/certs/server.crt'
ssl_key_file = '/etc/postgresql/14/main/certs/server.key'

# 강력한 암호화 스위트만 허용
ssl_ciphers = 'HIGH:MEDIUM:+3DES:!aNULL'
ssl_prefer_server_ciphers = on
ssl_min_protocol_version = 'TLSv1.2'
```

```bash
# PostgreSQL 재시작
sudo systemctl restart postgresql

# SSL 활성화 확인
psql -U postgres -c "SHOW ssl;"
#  on
```

#### 3단계: 클라이언트 인증서 생성 (cert 인증용)
```bash
# 클라이언트 인증서 생성 (백업 사용자용)
cd /etc/postgresql/14/main/certs

# 1. 클라이언트 Private Key
sudo openssl genrsa -out backup_user.key 2048

# 2. 클라이언트 CSR
sudo openssl req -new -key backup_user.key -out backup_user.csr
# Common Name: backup_user  (PostgreSQL 사용자명과 일치!)

# 3. 서버 키로 서명
sudo openssl x509 -req -in backup_user.csr \
  -CA server.crt -CAkey server.key -CAcreateserial \
  -out backup_user.crt -days 365

# 4. 클라이언트로 복사
sudo cp backup_user.crt backup_user.key /home/backup/
sudo chown backup:backup /home/backup/backup_user.*
```

#### 4단계: pg_hba.conf 설정
```ini
# /etc/postgresql/14/main/pg_hba.conf

# TYPE    DATABASE  USER          ADDRESS        METHOD

# SSL 필수, 인증서 인증
hostssl   all       backup_user   0.0.0.0/0      cert

# SSL 필수, 비밀번호 인증
hostssl   all       app_user      0.0.0.0/0      scram-sha-256

# SSL 없는 연결 거부
hostnossl all       all           0.0.0.0/0      reject
```

```bash
sudo systemctl reload postgresql
```

### 🔌 클라이언트 연결

#### psql (SSL)
```bash
# 1. SSL 연결 (서버 인증서 검증 안 함)
psql "host=db.example.com dbname=mydb user=app_user sslmode=require"

# 2. SSL 연결 (서버 인증서 검증)
psql "host=db.example.com dbname=mydb user=app_user \
  sslmode=verify-full sslrootcert=/path/to/server.crt"

# 3. 클라이언트 인증서 사용
psql "host=db.example.com dbname=mydb user=backup_user \
  sslmode=require \
  sslcert=/home/backup/backup_user.crt \
  sslkey=/home/backup/backup_user.key"
```

#### Node.js (SSL)
```javascript
const { Pool } = require('pg');

// 1. SSL 연결 (기본)
const pool = new Pool({
  host: 'db.example.com',
  database: 'mydb',
  user: 'app_user',
  password: 'secure_password',
  ssl: {
    rejectUnauthorized: false  // 개발 환경
  }
});

// 2. SSL 연결 (인증서 검증)
const fs = require('fs');
const pool2 = new Pool({
  host: 'db.example.com',
  database: 'mydb',
  user: 'app_user',
  password: 'secure_password',
  ssl: {
    rejectUnauthorized: true,
    ca: fs.readFileSync('/path/to/server.crt').toString()
  }
});

// 3. 클라이언트 인증서
const pool3 = new Pool({
  host: 'db.example.com',
  database: 'mydb',
  user: 'backup_user',
  ssl: {
    rejectUnauthorized: true,
    ca: fs.readFileSync('/path/to/server.crt').toString(),
    cert: fs.readFileSync('/path/to/backup_user.crt').toString(),
    key: fs.readFileSync('/path/to/backup_user.key').toString()
  }
});
```

#### sslmode 옵션 비교

```
sslmode 값별 보안 수준
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

disable:
  ❌ SSL 사용 안 함 (평문 전송)
  사용 사례: localhost만

allow:
  ⚠️  서버가 요구하면 SSL, 아니면 평문
  사용 사례: 없음 (비권장)

prefer (기본값):
  ⚠️  SSL 시도, 실패 시 평문
  사용 사례: 없음 (비권장)

require:
  ✅ SSL 필수, 인증서 검증 안 함
  사용 사례: 개발 환경, 자체 서명 인증서

verify-ca:
  ✅ SSL 필수, CA 검증
  사용 사례: 내부 CA 사용

verify-full: ⭐
  ✅ SSL 필수, CA + 호스트명 검증
  사용 사례: 프로덕션 (강력 권장)
```

### 📝 컬럼 암호화 실습

#### 시나리오: 사용자 개인정보 암호화

```sql
-- 1. 사용자 테이블 (암호화 적용)
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  phone_encrypted BYTEA,        -- 암호화된 전화번호
  ssn_encrypted BYTEA,           -- 암호화된 주민번호
  created_at TIMESTAMPTZ DEFAULT now()
);

-- 2. 암호화 키 (환경변수나 별도 관리, 여기서는 예시)
-- 실제로는 애플리케이션 환경변수로 관리!
DO $$
DECLARE
  encryption_key TEXT := 'my-secret-encryption-key-2024';
BEGIN
  -- 세션 변수로 설정
  PERFORM set_config('app.encryption_key', encryption_key, false);
END $$;

-- 3. 데이터 삽입 (암호화)
INSERT INTO users (name, email, phone_encrypted, ssn_encrypted)
VALUES (
  'Alice',
  'alice@example.com',
  pgp_sym_encrypt('010-1234-5678', current_setting('app.encryption_key')),
  pgp_sym_encrypt('123456-1234567', current_setting('app.encryption_key'))
);

INSERT INTO users (name, email, phone_encrypted, ssn_encrypted)
VALUES (
  'Bob',
  'bob@example.com',
  pgp_sym_encrypt('010-9876-5432', current_setting('app.encryption_key')),
  pgp_sym_encrypt('654321-7654321', current_setting('app.encryption_key'))
);

-- 4. 암호화된 데이터 조회
SELECT id, name, email, phone_encrypted FROM users;
--  id | name  | email               | phone_encrypted
-- ----+-------+---------------------+------------------
--   1 | Alice | alice@example.com   | \xc30d04070302...
--   2 | Bob   | bob@example.com     | \xc30d04070302...
-- (읽을 수 없음!)

-- 5. 복호화하여 조회
SELECT
  id,
  name,
  email,
  pgp_sym_decrypt(phone_encrypted, current_setting('app.encryption_key')) AS phone,
  pgp_sym_decrypt(ssn_encrypted, current_setting('app.encryption_key')) AS ssn
FROM users;
--  id | name  | email               | phone          | ssn
-- ----+-------+---------------------+----------------+----------------
--   1 | Alice | alice@example.com   | 010-1234-5678  | 123456-1234567
--   2 | Bob   | bob@example.com     | 010-9876-5432  | 654321-7654321

-- 6. 특정 전화번호 검색 (복호화 후 비교)
SELECT *
FROM users
WHERE pgp_sym_decrypt(phone_encrypted, current_setting('app.encryption_key')) = '010-1234-5678';
-- 주의: 성능 이슈 (인덱스 사용 불가)
```

### 🔧 암호화 함수 비교

```sql
-- 1. 대칭 암호화 (pgp_sym_encrypt) - 일반적으로 사용
SELECT pgp_sym_encrypt('sensitive data', 'my_key');
-- 복호화:
SELECT pgp_sym_decrypt(encrypted_data, 'my_key');

-- 2. 비대칭 암호화 (pgp_pub_encrypt) - 공개키/개인키
-- (고급 사용, 여기서는 생략)

-- 3. 해시 (단방향, 비밀번호용)
SELECT crypt('my_password', gen_salt('bf'));  -- Blowfish
-- 검증:
SELECT crypt('user_input', stored_hash) = stored_hash;

-- 4. HMAC (메시지 인증 코드)
SELECT encode(hmac('message', 'secret_key', 'sha256'), 'hex');
```

### 🚀 애플리케이션에서 암호화

#### Node.js 예시
```javascript
// db.js
const { Pool } = require('pg');

const pool = new Pool({
  host: 'localhost',
  database: 'mydb',
  user: 'app_user',
  password: 'app_password'
});

// 암호화 키 (환경변수로 관리!)
const ENCRYPTION_KEY = process.env.DB_ENCRYPTION_KEY || 'fallback-key';

// 사용자 생성 (암호화)
async function createUser(name, email, phone, ssn) {
  const result = await pool.query(`
    INSERT INTO users (name, email, phone_encrypted, ssn_encrypted)
    VALUES ($1, $2, pgp_sym_encrypt($3, $4), pgp_sym_encrypt($5, $4))
    RETURNING id, name, email
  `, [name, email, phone, ENCRYPTION_KEY, ssn, ENCRYPTION_KEY]);

  return result.rows[0];
}

// 사용자 조회 (복호화)
async function getUser(id) {
  const result = await pool.query(`
    SELECT
      id,
      name,
      email,
      pgp_sym_decrypt(phone_encrypted, $2) AS phone,
      pgp_sym_decrypt(ssn_encrypted, $2) AS ssn
    FROM users
    WHERE id = $1
  `, [id, ENCRYPTION_KEY]);

  return result.rows[0];
}

// 사용 예:
const user = await createUser('Alice', 'alice@example.com', '010-1234-5678', '123456-1234567');
console.log(user);
// { id: 1, name: 'Alice', email: 'alice@example.com' }

const fullUser = await getUser(1);
console.log(fullUser);
// { id: 1, name: 'Alice', email: 'alice@example.com',
//   phone: '010-1234-5678', ssn: '123456-1234567' }
```

### ⚠️ 암호화 성능 고려사항

```sql
-- ❌ 나쁜 예: WHERE 절에서 복호화 (Full Table Scan)
SELECT *
FROM users
WHERE pgp_sym_decrypt(phone_encrypted, 'key') = '010-1234-5678';

-- ✅ 좋은 예: 이메일은 암호화 안 함 (검색 가능)
SELECT *
FROM users
WHERE email = 'alice@example.com';  -- 인덱스 사용 가능

-- 💡 대안: 해시 인덱스 (검색용)
ALTER TABLE users ADD COLUMN phone_hash VARCHAR(64);

-- 삽입 시 해시도 저장
INSERT INTO users (name, email, phone_encrypted, phone_hash)
VALUES (
  'Alice',
  'alice@example.com',
  pgp_sym_encrypt('010-1234-5678', 'key'),
  encode(digest('010-1234-5678', 'sha256'), 'hex')
);

-- 검색 시 해시로 검색 (빠름!)
CREATE INDEX idx_users_phone_hash ON users(phone_hash);

SELECT *
FROM users
WHERE phone_hash = encode(digest('010-1234-5678', 'sha256'), 'hex');
```

## 7. 감사 로깅 (pgAudit)

### 📹 pgAudit 설치 및 설정

```bash
# 1. pgAudit 설치 (Ubuntu/Debian)
sudo apt install postgresql-14-pgaudit

# 2. postgresql.conf 수정
sudo nano /etc/postgresql/14/main/postgresql.conf
```

```ini
# postgresql.conf

# pgAudit 로드
shared_preload_libraries = 'pgaudit'

# 로깅할 명령어
pgaudit.log = 'write, ddl'  # INSERT, UPDATE, DELETE, CREATE, ALTER, DROP
# 또는
# pgaudit.log = 'all'  # 모든 명령어 (성능 주의)

# 특정 역할만 감사
pgaudit.role = 'audit_role'

# 로그 형식
pgaudit.log_catalog = off  # 시스템 카탈로그 제외
pgaudit.log_parameter = on  # 파라미터 값 포함
```

```bash
# 3. PostgreSQL 재시작
sudo systemctl restart postgresql

# 4. Extension 활성화
psql -U postgres -c "CREATE EXTENSION pgaudit;"
```

## 8. 보안 체크리스트

### ✅ 프로덕션 보안 체크리스트

```
[ ] 인증 및 접근 제어
    [ ] pg_hba.conf에서 0.0.0.0/0 trust 없음
    [ ] scram-sha-256 인증 사용
    [ ] 불필요한 원격 접속 차단
    [ ] 슈퍼유저는 로컬에서만 접속

[ ] SSL/TLS
    [ ] ssl = on
    [ ] 유효한 인증서 사용 (자체 서명 아님)
    [ ] TLS 1.2 이상만 허용
    [ ] 클라이언트는 sslmode=verify-full 사용

[ ] 비밀번호 정책
    [ ] 12자 이상 강력한 비밀번호
    [ ] 정기적 비밀번호 변경
    [ ] 비밀번호 재사용 금지
    [ ] VALID UNTIL 설정

[ ] 권한 관리
    [ ] 최소 권한 원칙 적용
    [ ] 애플리케이션 사용자는 슈퍼유저 아님
    [ ] DDL 권한 분리 (마이그레이션 전용 사용자)
    [ ] 프로덕션 DB에 개발자 직접 접속 금지

[ ] 데이터 암호화
    [ ] 민감한 컬럼 암호화 (pgcrypto)
    [ ] 암호화 키는 환경변수나 시크릿 관리 도구
    [ ] 백업 파일 암호화

[ ] 감사 로깅
    [ ] pgAudit 활성화
    [ ] 로그 정기 검토
    [ ] 로그 백업 및 장기 보관
    [ ] 이상 접근 알림 설정

[ ] 네트워크 보안
    [ ] 방화벽 설정 (PostgreSQL 포트 제한)
    [ ] VPN 사용 (원격 접속 시)
    [ ] Private Subnet 배치
    [ ] 공용 IP 노출 최소화

[ ] 기타
    [ ] PostgreSQL 최신 버전 사용
    [ ] 정기적 보안 패치
    [ ] 취약점 스캔
    [ ] 침해 사고 대응 계획
```
