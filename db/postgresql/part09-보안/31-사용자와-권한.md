## 1. PostgreSQL 역할(Role) 시스템 (비유로 이해하기)

### 🏢 회사 조직도에 비유하면

```
PostgreSQL Role = 회사의 직책과 권한
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

👔 CEO (슈퍼유저)
   ├─ 모든 권한
   ├─ 데이터베이스 생성/삭제
   ├─ 다른 사용자 관리
   └─ 예: postgres (기본 슈퍼유저)

👨‍💼 부서장 (관리자 역할)
   ├─ 특정 데이터베이스 관리
   ├─ 팀원에게 권한 부여
   └─ 예: app_admin

👨‍💻 개발자 (일반 사용자)
   ├─ 테이블 읽기/쓰기
   ├─ 제한된 권한
   └─ 예: app_user

👀 인턴 (읽기 전용)
   ├─ 데이터 조회만
   ├─ 수정 불가
   └─ 예: readonly_user

🤖 시스템 (서비스 계정)
   ├─ 특정 작업 전용
   ├─ 사람이 사용 안 함
   └─ 예: backup_user, monitoring_user
```

### 🔑 Role vs User vs Group

```
PostgreSQL의 핵심: Role = User + Group
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📌 Role (역할):
   - PostgreSQL의 유일한 사용자 개념
   - LOGIN 속성이 있으면 = User
   - LOGIN 속성이 없으면 = Group

예시:
  ┌─────────────────────────────────────┐
  │ Role: developers (GROUP)            │
  │ ├─ LOGIN 권한 없음                  │
  │ ├─ 개발자들의 공통 권한 정의        │
  │ └─ 멤버: alice, bob                 │
  └─────────────────────────────────────┘
          ↓ 권한 상속
  ┌─────────────────────────────────────┐
  │ Role: alice (USER)                  │
  │ ├─ LOGIN 권한 있음                  │
  │ ├─ developers 그룹의 권한 상속      │
  │ └─ 실제로 로그인 가능               │
  └─────────────────────────────────────┘
```

## 2. 사용자(Role) 생성과 관리

### 🔧 기본 사용자 생성

#### 가장 간단한 사용자
```sql
-- 1. 로그인 가능한 사용자 생성
CREATE ROLE alice WITH LOGIN PASSWORD 'secure_password';

-- 또는 (동일)
CREATE USER alice WITH PASSWORD 'secure_password';
-- CREATE USER는 CREATE ROLE ... WITH LOGIN의 별칭

-- 2. 사용자 목록 확인
\du
-- 또는
SELECT rolname, rolsuper, rolinherit, rolcreatedb, rolcreaterole
FROM pg_roles;

-- 결과:
--  rolname  | rolsuper | rolinherit | rolcreatedb | rolcreaterole
-- ----------+----------+------------+-------------+---------------
--  postgres | t        | t          | t           | t
--  alice    | f        | t          | f           | f
```

#### 다양한 속성을 가진 사용자
```sql
-- 개발자 사용자 (DB 생성 가능)
CREATE ROLE developer WITH
  LOGIN
  PASSWORD 'dev_password'
  CREATEDB           -- 데이터베이스 생성 가능
  VALID UNTIL '2025-12-31';  -- 유효기간

-- 백업 전용 사용자 (복제 권한)
CREATE ROLE backup_user WITH
  LOGIN
  PASSWORD 'backup_password'
  REPLICATION;       -- Streaming Replication 가능

-- 슈퍼유저 (주의! 모든 권한)
CREATE ROLE admin WITH
  LOGIN
  PASSWORD 'admin_password'
  SUPERUSER          -- 슈퍼유저 권한
  CREATEDB
  CREATEROLE;        -- 다른 역할 생성 가능

-- 읽기 전용 사용자 (비밀번호 없음, 로컬에서만)
CREATE ROLE readonly WITH
  LOGIN
  CONNECTION LIMIT 5;  -- 최대 5개 동시 연결
```

### 🛠️ 사용자 수정

```sql
-- 비밀번호 변경
ALTER ROLE alice WITH PASSWORD 'new_secure_password';

-- 유효기간 연장
ALTER ROLE alice VALID UNTIL '2026-12-31';

-- 연결 제한 추가
ALTER ROLE alice CONNECTION LIMIT 10;

-- 슈퍼유저 권한 부여 (주의!)
ALTER ROLE alice WITH SUPERUSER;

-- 슈퍼유저 권한 회수
ALTER ROLE alice WITH NOSUPERUSER;

-- 데이터베이스 생성 권한 부여
ALTER ROLE alice WITH CREATEDB;

-- 로그인 비활성화 (계정 잠금)
ALTER ROLE alice WITH NOLOGIN;

-- 로그인 재활성화
ALTER ROLE alice WITH LOGIN;
```

### 🗑️ 사용자 삭제

```sql
-- 1. 사용자 소유 객체 확인
SELECT
  schemaname,
  tablename,
  tableowner
FROM pg_tables
WHERE tableowner = 'alice';

-- 2. 소유권 이전
REASSIGN OWNED BY alice TO postgres;

-- 3. 남은 권한 삭제
DROP OWNED BY alice;

-- 4. 사용자 삭제
DROP ROLE alice;

-- 또는 한 번에 (주의! 복구 불가)
DROP ROLE IF EXISTS alice;
```

## 3. 권한 부여와 회수 (GRANT / REVOKE)

### 📊 데이터베이스 권한

```sql
-- 데이터베이스 생성
CREATE DATABASE myapp;

-- 1. 데이터베이스 연결 권한 부여
GRANT CONNECT ON DATABASE myapp TO alice;

-- 2. 데이터베이스의 모든 권한 부여
GRANT ALL PRIVILEGES ON DATABASE myapp TO alice;

-- 3. 특정 권한만 부여
GRANT CREATE ON DATABASE myapp TO alice;
-- CREATE: 스키마 생성 가능

-- 4. 권한 회수
REVOKE CREATE ON DATABASE myapp FROM alice;

-- 5. 모든 권한 회수
REVOKE ALL PRIVILEGES ON DATABASE myapp FROM alice;
```

### 🗂️ 스키마 권한

```sql
-- myapp 데이터베이스에 접속
\c myapp

-- 1. 스키마 사용 권한
GRANT USAGE ON SCHEMA public TO alice;
-- USAGE: 스키마 내 객체 접근 가능

-- 2. 스키마 내 테이블 생성 권한
GRANT CREATE ON SCHEMA public TO alice;

-- 3. 모든 권한
GRANT ALL PRIVILEGES ON SCHEMA public TO alice;
```

### 📋 테이블 권한

```sql
-- 테스트 테이블 생성
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100),
  email VARCHAR(100)
);

-- 1. SELECT 권한 (읽기)
GRANT SELECT ON TABLE users TO alice;

-- 이제 alice는:
-- SELECT * FROM users;  ✅ 가능
-- INSERT INTO users ... ❌ 불가
-- UPDATE users ...      ❌ 불가
-- DELETE FROM users ... ❌ 불가

-- 2. INSERT 권한 (삽입)
GRANT INSERT ON TABLE users TO alice;

-- 3. UPDATE 권한 (수정)
GRANT UPDATE ON TABLE users TO alice;

-- 4. DELETE 권한 (삭제)
GRANT DELETE ON TABLE users TO alice;

-- 5. 특정 컬럼만 SELECT 권한
GRANT SELECT (id, name) ON TABLE users TO alice;
-- email 컬럼은 볼 수 없음

-- 6. 특정 컬럼만 UPDATE 권한
GRANT UPDATE (name) ON TABLE users TO alice;
-- id, email은 수정 불가

-- 7. 모든 권한
GRANT ALL PRIVILEGES ON TABLE users TO alice;

-- 8. WITH GRANT OPTION (권한 위임 가능)
GRANT SELECT ON TABLE users TO alice WITH GRANT OPTION;
-- alice가 다른 사용자에게 SELECT 권한 부여 가능
```

### 🔢 시퀀스 권한

```sql
-- SERIAL 컬럼은 내부적으로 SEQUENCE 사용
-- INSERT 시 SEQUENCE USAGE 권한 필요

-- 1. 시퀀스 사용 권한
GRANT USAGE ON SEQUENCE users_id_seq TO alice;

-- 2. 모든 시퀀스에 권한 부여
GRANT USAGE ON ALL SEQUENCES IN SCHEMA public TO alice;
```

### 📦 한 번에 권한 부여

```sql
-- 1. 현재 존재하는 모든 테이블에 SELECT 권한
GRANT SELECT ON ALL TABLES IN SCHEMA public TO alice;

-- 2. 앞으로 생성될 테이블에도 자동으로 권한 부여 ⭐
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT ON TABLES TO alice;

-- 예시: postgres가 public 스키마에 테이블 생성 시
-- alice에게 자동으로 SELECT 권한 부여됨

-- 3. 특정 사용자가 생성하는 테이블에만 적용
ALTER DEFAULT PRIVILEGES FOR ROLE app_owner IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_user;
```

## 4. 역할 그룹과 권한 상속

### 👥 그룹 역할 만들기

```sql
-- 1. 읽기 전용 그룹
CREATE ROLE readonly NOLOGIN;  -- 로그인 불가 (그룹용)

GRANT CONNECT ON DATABASE myapp TO readonly;
GRANT USAGE ON SCHEMA public TO readonly;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO readonly;
GRANT SELECT ON ALL SEQUENCES IN SCHEMA public TO readonly;

-- 미래 테이블에도 적용
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT ON TABLES TO readonly;

-- 2. 읽기/쓰기 그룹
CREATE ROLE readwrite NOLOGIN;

GRANT CONNECT ON DATABASE myapp TO readwrite;
GRANT USAGE ON SCHEMA public TO readwrite;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO readwrite;
GRANT USAGE ON ALL SEQUENCES IN SCHEMA public TO readwrite;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO readwrite;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT USAGE ON SEQUENCES TO readwrite;

-- 3. 관리자 그룹
CREATE ROLE admin_group NOLOGIN;

GRANT ALL PRIVILEGES ON DATABASE myapp TO admin_group;
GRANT ALL PRIVILEGES ON SCHEMA public TO admin_group;
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO admin_group;
GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO admin_group;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT ALL PRIVILEGES ON TABLES TO admin_group;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT ALL PRIVILEGES ON SEQUENCES TO admin_group;
```

### 👤 사용자를 그룹에 추가

```sql
-- 1. 사용자 생성
CREATE ROLE alice WITH LOGIN PASSWORD 'alice_password';
CREATE ROLE bob WITH LOGIN PASSWORD 'bob_password';
CREATE ROLE charlie WITH LOGIN PASSWORD 'charlie_password';

-- 2. 그룹에 추가
GRANT readonly TO alice;       -- alice는 읽기 전용
GRANT readwrite TO bob;        -- bob은 읽기/쓰기
GRANT admin_group TO charlie;  -- charlie는 관리자

-- 3. 그룹 멤버 확인
\du alice
--              List of roles
--  Role name |  Attributes  | Member of
-- -----------+--------------+-------------
--  alice     |              | {readonly}

-- 4. 권한 테스트
-- alice로 로그인
SET ROLE alice;

SELECT * FROM users;  -- ✅ 가능 (readonly 그룹 권한)
INSERT INTO users (name, email) VALUES ('Test', 'test@example.com');
-- ❌ ERROR: permission denied for table users

-- 5. 그룹에서 제거
REVOKE readonly FROM alice;

-- 6. 여러 그룹에 동시 소속
GRANT readonly, readwrite TO alice;  -- alice는 두 그룹 권한 모두 상속
```

## 5. 실전 시나리오: 애플리케이션 사용자 설정

### 🚀 Node.js 애플리케이션 사용자

```sql
-- 1. 애플리케이션 전용 사용자 생성
CREATE ROLE app_user WITH
  LOGIN
  PASSWORD 'strong_app_password'
  CONNECTION LIMIT 50;  -- 최대 50개 연결 (connection pool 고려)

-- 2. 데이터베이스 접속 권한
GRANT CONNECT ON DATABASE myapp TO app_user;

-- 3. 스키마 사용 권한
GRANT USAGE ON SCHEMA public TO app_user;

-- 4. 테이블 권한 (읽기/쓰기)
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_user;

-- 5. 시퀀스 권한 (SERIAL 사용 시 필수)
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO app_user;

-- 6. 함수 실행 권한
GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA public TO app_user;

-- 7. 미래 객체에도 권한 부여
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_user;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT USAGE, SELECT ON SEQUENCES TO app_user;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT EXECUTE ON FUNCTIONS TO app_user;

-- 8. 금지: DDL 작업 불가
-- app_user는 CREATE, ALTER, DROP 권한 없음
-- 테이블 구조 변경 불가 (마이그레이션은 별도 사용자)
```

#### Node.js 연결 예시
```javascript
// app.js
const { Pool } = require('pg');

const pool = new Pool({
  host: 'localhost',
  port: 5432,
  database: 'myapp',
  user: 'app_user',
  password: 'strong_app_password',
  max: 50,  // CONNECTION LIMIT와 맞춤
});

// ✅ 가능한 작업
await pool.query('SELECT * FROM users');
await pool.query('INSERT INTO users (name) VALUES ($1)', ['Alice']);

// ❌ 불가능한 작업
await pool.query('DROP TABLE users');
// ERROR: must be owner of table users
```

## 6. Row Level Security (RLS)

### 🔒 행 수준 보안이란?

```
RLS = 테이블의 특정 행만 보이게 제어
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

예: 사용자는 자신의 데이터만 조회 가능

users 테이블:
  id | name  | email               | owner
  ---+-------+---------------------+-------
   1 | Alice | alice@example.com   | alice
   2 | Bob   | bob@example.com     | bob
   3 | Carol | carol@example.com   | carol

alice로 로그인 후 SELECT:
  → id=1 행만 보임 (owner='alice')

bob으로 로그인 후 SELECT:
  → id=2 행만 보임 (owner='bob')
```

### 실습: 멀티 테넌트 시스템

```sql
-- 1. 테넌트별 데이터 테이블
CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200),
  content TEXT,
  tenant_id VARCHAR(50) NOT NULL,  -- 테넌트 식별자
  created_at TIMESTAMPTZ DEFAULT now()
);

-- 샘플 데이터
INSERT INTO posts (title, content, tenant_id) VALUES
  ('Post 1', 'Content 1', 'company_a'),
  ('Post 2', 'Content 2', 'company_a'),
  ('Post 3', 'Content 3', 'company_b'),
  ('Post 4', 'Content 4', 'company_b');

-- 2. RLS 활성화
ALTER TABLE posts ENABLE ROW LEVEL SECURITY;

-- 3. 정책 생성: 자신의 테넌트 데이터만 조회
CREATE POLICY tenant_isolation ON posts
  FOR SELECT
  USING (tenant_id = current_setting('app.tenant_id', true));

-- 4. 정책: 자신의 테넌트에만 삽입
CREATE POLICY tenant_insert ON posts
  FOR INSERT
  WITH CHECK (tenant_id = current_setting('app.tenant_id', true));

-- 5. 정책: 자신의 테넌트 데이터만 수정
CREATE POLICY tenant_update ON posts
  FOR UPDATE
  USING (tenant_id = current_setting('app.tenant_id', true));

-- 6. 정책: 자신의 테넌트 데이터만 삭제
CREATE POLICY tenant_delete ON posts
  FOR DELETE
  USING (tenant_id = current_setting('app.tenant_id', true));

-- 7. 사용자 생성
CREATE ROLE tenant_user WITH LOGIN PASSWORD 'tenant_password';
GRANT CONNECT ON DATABASE myapp TO tenant_user;
GRANT USAGE ON SCHEMA public TO tenant_user;
GRANT SELECT, INSERT, UPDATE, DELETE ON posts TO tenant_user;
GRANT USAGE ON SEQUENCE posts_id_seq TO tenant_user;
```

#### 애플리케이션에서 RLS 사용
```javascript
// Node.js 예시
const { Pool } = require('pg');

async function queryAsTenant(tenantId, sql, params) {
  const client = await pool.connect();

  try {
    // 세션 변수 설정
    await client.query(`SET app.tenant_id = '${tenantId}'`);

    // 쿼리 실행 (RLS 자동 적용)
    const result = await client.query(sql, params);

    return result.rows;
  } finally {
    client.release();
  }
}

// 사용 예:
// Company A 사용자로 조회
const companyAPosts = await queryAsTenant('company_a', 'SELECT * FROM posts');
// → Post 1, Post 2만 반환

// Company B 사용자로 조회
const companyBPosts = await queryAsTenant('company_b', 'SELECT * FROM posts');
// → Post 3, Post 4만 반환
```

### 🎯 고급 RLS: 역할 기반

```sql
-- 1. 소셜 미디어 게시물 테이블
CREATE TABLE social_posts (
  id SERIAL PRIMARY KEY,
  user_id INT NOT NULL,
  content TEXT,
  is_public BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT now()
);

INSERT INTO social_posts (user_id, content, is_public) VALUES
  (1, 'Alice public post', true),
  (1, 'Alice private post', false),
  (2, 'Bob public post', true),
  (2, 'Bob private post', false);

-- 2. RLS 활성화
ALTER TABLE social_posts ENABLE ROW LEVEL SECURITY;

-- 3. 정책: 공개 게시물은 모두 볼 수 있음
CREATE POLICY public_posts_visible ON social_posts
  FOR SELECT
  USING (is_public = true);

-- 4. 정책: 자신의 게시물은 모두 볼 수 있음
CREATE POLICY own_posts_visible ON social_posts
  FOR SELECT
  USING (user_id = current_setting('app.user_id', true)::INT);

-- 5. 정책: 자신의 게시물만 수정/삭제 가능
CREATE POLICY own_posts_modify ON social_posts
  FOR ALL
  USING (user_id = current_setting('app.user_id', true)::INT);

-- 테스트:
CREATE ROLE social_user WITH LOGIN PASSWORD 'social_password';
GRANT CONNECT ON DATABASE myapp TO social_user;
GRANT SELECT, INSERT, UPDATE, DELETE ON social_posts TO social_user;

-- 사용자 1로 조회 (app.user_id = 1)
SET app.user_id = '1';
SELECT * FROM social_posts;
-- 결과:
--  id | user_id | content              | is_public
-- ----+---------+----------------------+-----------
--   1 |       1 | Alice public post    | t
--   2 |       1 | Alice private post   | f
--   3 |       2 | Bob public post      | t
-- (자신의 모든 게시물 + 다른 사람의 공개 게시물)

-- 사용자 2로 조회 (app.user_id = 2)
SET app.user_id = '2';
SELECT * FROM social_posts;
-- 결과:
--  id | user_id | content              | is_public
-- ----+---------+----------------------+-----------
--   1 |       1 | Alice public post    | t
--   3 |       2 | Bob public post      | t
--   4 |       2 | Bob private post     | f
```

## 7. 최소 권한 원칙 (Principle of Least Privilege)

### 🎯 실전 체크리스트

```
✅ 애플리케이션 사용자
  [ ] 슈퍼유저 권한 없음
  [ ] CREATEDB, CREATEROLE 권한 없음
  [ ] 필요한 테이블/스키마만 접근
  [ ] DDL 작업 불가 (CREATE, ALTER, DROP)
  [ ] SELECT, INSERT, UPDATE, DELETE만 허용

✅ 읽기 전용 사용자
  [ ] SELECT만 가능
  [ ] 민감한 테이블 제외
  [ ] 뷰를 통한 제한된 데이터 제공

✅ 백업 사용자
  [ ] REPLICATION 권한만
  [ ] 또는 모든 테이블 SELECT 권한
  [ ] 데이터 수정 불가

✅ 모니터링 사용자
  [ ] pg_stat_* 뷰 접근
  [ ] 시스템 카탈로그 읽기
  [ ] 데이터 테이블 접근 불가

✅ 비밀번호 정책
  [ ] 강력한 비밀번호 (12자 이상, 특수문자)
  [ ] 정기적 비밀번호 변경
  [ ] VALID UNTIL 설정 (만료일)
  [ ] 서비스 계정은 환경변수/시크릿 관리
```

### 실전 예시: 완전한 권한 분리

```sql
-- 1. 스키마 소유자 (DDL 전용)
CREATE ROLE schema_owner WITH
  LOGIN
  PASSWORD 'schema_owner_password'
  CREATEDB;

CREATE DATABASE myapp OWNER schema_owner;

\c myapp schema_owner

CREATE SCHEMA app AUTHORIZATION schema_owner;

CREATE TABLE app.users (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100),
  email VARCHAR(100) UNIQUE
);

CREATE TABLE app.posts (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES app.users(id),
  title VARCHAR(200),
  content TEXT
);

-- 2. 애플리케이션 사용자 (DML 전용)
\c myapp postgres

CREATE ROLE app_user WITH
  LOGIN
  PASSWORD 'app_user_password'
  CONNECTION LIMIT 50;

GRANT CONNECT ON DATABASE myapp TO app_user;
GRANT USAGE ON SCHEMA app TO app_user;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA app TO app_user;
GRANT USAGE ON ALL SEQUENCES IN SCHEMA app TO app_user;

ALTER DEFAULT PRIVILEGES FOR ROLE schema_owner IN SCHEMA app
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_user;
ALTER DEFAULT PRIVILEGES FOR ROLE schema_owner IN SCHEMA app
  GRANT USAGE ON SEQUENCES TO app_user;

-- 3. 읽기 전용 사용자
CREATE ROLE readonly_user WITH
  LOGIN
  PASSWORD 'readonly_password'
  CONNECTION LIMIT 10;

GRANT CONNECT ON DATABASE myapp TO readonly_user;
GRANT USAGE ON SCHEMA app TO readonly_user;
GRANT SELECT ON ALL TABLES IN SCHEMA app TO readonly_user;

ALTER DEFAULT PRIVILEGES FOR ROLE schema_owner IN SCHEMA app
  GRANT SELECT ON TABLES TO readonly_user;

-- 4. 백업 사용자
CREATE ROLE backup_user WITH
  LOGIN
  PASSWORD 'backup_password'
  REPLICATION
  CONNECTION LIMIT 5;

-- 5. 모니터링 사용자
CREATE ROLE monitoring_user WITH
  LOGIN
  PASSWORD 'monitoring_password';

GRANT pg_monitor TO monitoring_user;  -- PostgreSQL 10+
-- pg_stat_*, pg_database_size() 등 접근 가능

-- 권한 검증:
-- app_user로 로그인
\c myapp app_user

SELECT * FROM app.users;  -- ✅ 가능
INSERT INTO app.users (name, email) VALUES ('Test', 'test@example.com');  -- ✅ 가능
CREATE TABLE app.test (id INT);  -- ❌ ERROR: permission denied for schema app

-- readonly_user로 로그인
\c myapp readonly_user

SELECT * FROM app.users;  -- ✅ 가능
INSERT INTO app.users (name, email) VALUES ('Test', 'test@example.com');  -- ❌ ERROR
```

## 8. 권한 감사 (Audit)

### 🔍 현재 권한 확인

```sql
-- 1. 특정 사용자의 모든 권한 확인
SELECT
  grantee,
  table_schema,
  table_name,
  privilege_type
FROM information_schema.table_privileges
WHERE grantee = 'app_user'
ORDER BY table_schema, table_name;

-- 2. 특정 테이블의 권한 확인
SELECT
  grantee,
  privilege_type,
  is_grantable
FROM information_schema.table_privileges
WHERE table_name = 'users'
ORDER BY grantee;

-- 3. 스키마 권한 확인
SELECT
  nspname AS schema_name,
  nspowner::regrole AS owner,
  nspacl AS acl
FROM pg_namespace
WHERE nspname NOT LIKE 'pg_%' AND nspname != 'information_schema';

-- 4. 데이터베이스 권한 확인
SELECT
  datname,
  datacl
FROM pg_database
WHERE datname = 'myapp';

-- 5. 역할 멤버십 확인
SELECT
  r.rolname AS role_name,
  m.rolname AS member_of
FROM pg_roles r
LEFT JOIN pg_auth_members am ON r.oid = am.member
LEFT JOIN pg_roles m ON am.roleid = m.oid
WHERE r.rolname = 'alice';
```

### 📊 권한 감사 뷰 생성

```sql
-- 종합 권한 리포트 뷰
CREATE OR REPLACE VIEW v_user_permissions AS
SELECT
  grantee AS user_name,
  table_schema AS schema,
  table_name,
  string_agg(privilege_type, ', ' ORDER BY privilege_type) AS privileges
FROM information_schema.table_privileges
WHERE grantee NOT IN ('postgres', 'PUBLIC')
  AND table_schema NOT IN ('pg_catalog', 'information_schema')
GROUP BY grantee, table_schema, table_name
ORDER BY grantee, table_schema, table_name;

-- 사용:
SELECT * FROM v_user_permissions WHERE user_name = 'app_user';
```

## 📖 정리

이번 챕터에서 배운 내용:

| 개념 | 핵심 내용 |
|------|----------|
| **Role** | User + Group, PostgreSQL의 유일한 사용자 개념 |
| **GRANT** | 권한 부여 (DB, 스키마, 테이블, 컬럼) |
| **REVOKE** | 권한 회수 |
| **권한 상속** | 그룹 역할로 공통 권한 관리 |
| **RLS** | Row Level Security, 행 수준 보안 |
| **최소 권한** | 필요한 최소한의 권한만 부여 |

### 핵심 명령어

```sql
-- 사용자 생성
CREATE ROLE alice WITH LOGIN PASSWORD 'password';

-- 권한 부여
GRANT SELECT ON TABLE users TO alice;
GRANT ALL PRIVILEGES ON DATABASE mydb TO alice;

-- 그룹 생성 및 멤버 추가
CREATE ROLE readonly NOLOGIN;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO readonly;
GRANT readonly TO alice;

-- RLS 설정
ALTER TABLE posts ENABLE ROW LEVEL SECURITY;
CREATE POLICY own_posts ON posts
  FOR ALL
  USING (user_id = current_user);

-- 권한 확인
\du  -- 사용자 목록
SELECT * FROM information_schema.table_privileges WHERE grantee = 'alice';
```
