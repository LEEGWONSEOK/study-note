# Chapter 26. 파티셔닝

## 26.1 파티셔닝이란?

### 정의

```
파티셔닝 (Partitioning):
큰 테이블을 작은 물리적 조각으로 나누는 기술

비유: 서랍장
┌─────────────────────────────────┐
│ ❌ 큰 서랍 하나:                │
│ [2020|2021|2022|2023|2024]      │
│ → 찾기 어려움                   │
│                                 │
│ ✅ 여러 서랍으로 나누기:        │
│ [2020] [2021] [2022]...         │
│ → 필요한 서랍만 열기            │
└─────────────────────────────────┘

파티셔닝 = 데이터를 논리적으로 분할
```

### 파티셔닝 장점

```
✅ 장점:
- 쿼리 성능 향상 (파티션 프루닝)
- 관리 용이 (파티션별 백업/삭제)
- 인덱스 크기 감소
- 병렬 처리 가능

❌ 단점:
- 복잡성 증가
- 파티션 키 선택 중요
- 추가 오버헤드
```

## 26.2 파티셔닝 방법

### Range Partitioning (범위)

```sql
-- 날짜별 파티셔닝 (가장 일반적)
CREATE TABLE logs (
  id BIGSERIAL,
  user_id INT,
  action VARCHAR(100),
  created_at TIMESTAMPTZ NOT NULL
) PARTITION BY RANGE (created_at);

-- 파티션 생성
CREATE TABLE logs_2024_01 PARTITION OF logs
FOR VALUES FROM ('2024-01-01') TO ('2024-02-01');

CREATE TABLE logs_2024_02 PARTITION OF logs
FOR VALUES FROM ('2024-02-01') TO ('2024-03-01');

CREATE TABLE logs_2024_03 PARTITION OF logs
FOR VALUES FROM ('2024-03-01') TO ('2024-04-01');

-- 데이터 삽입
INSERT INTO logs (user_id, action, created_at)
VALUES (1, 'login', '2024-01-15 10:00:00');
-- 자동으로 logs_2024_01에 삽입!

-- 조회
SELECT * FROM logs WHERE created_at >= '2024-01-01' AND created_at < '2024-02-01';
-- logs_2024_01만 스캔! (파티션 프루닝)
```

### List Partitioning (목록)

```sql
-- 국가별 파티셔닝
CREATE TABLE users (
  id SERIAL,
  name VARCHAR(100),
  email VARCHAR(255),
  country VARCHAR(50) NOT NULL
) PARTITION BY LIST (country);

-- 파티션 생성
CREATE TABLE users_korea PARTITION OF users
FOR VALUES IN ('Korea', 'KR');

CREATE TABLE users_usa PARTITION OF users
FOR VALUES IN ('USA', 'US');

CREATE TABLE users_japan PARTITION OF users
FOR VALUES IN ('Japan', 'JP');

CREATE TABLE users_others PARTITION OF users
DEFAULT;  -- 나머지

-- 데이터 삽입
INSERT INTO users (name, email, country)
VALUES ('Alice', 'alice@ex.com', 'Korea');
-- users_korea에 삽입!
```

### Hash Partitioning (해시)

```sql
-- user_id 해시 파티셔닝
CREATE TABLE events (
  id BIGSERIAL,
  user_id INT NOT NULL,
  event_type VARCHAR(50),
  created_at TIMESTAMPTZ
) PARTITION BY HASH (user_id);

-- 4개 파티션
CREATE TABLE events_p0 PARTITION OF events
FOR VALUES WITH (MODULUS 4, REMAINDER 0);

CREATE TABLE events_p1 PARTITION OF events
FOR VALUES WITH (MODULUS 4, REMAINDER 1);

CREATE TABLE events_p2 PARTITION OF events
FOR VALUES WITH (MODULUS 4, REMAINDER 2);

CREATE TABLE events_p3 PARTITION OF events
FOR VALUES WITH (MODULUS 4, REMAINDER 3);

-- user_id에 따라 자동 분산!
INSERT INTO events (user_id, event_type, created_at)
VALUES (100, 'page_view', NOW());
-- user_id % 4에 따라 파티션 선택
```

## 26.3 파티션 프루닝

### 파티션 프루닝이란?

```sql
-- 파티션 프루닝 (Partition Pruning)
-- 필요한 파티션만 스캔

EXPLAIN SELECT * FROM logs
WHERE created_at >= '2024-01-01' AND created_at < '2024-02-01';

-- Seq Scan on logs_2024_01 logs
-- → logs_2024_02, logs_2024_03은 스캔 안 함!

-- 파티션 프루닝 확인
SET enable_partition_pruning = on;  -- 기본값

EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM logs
WHERE created_at >= '2024-01-15';

-- Append (actual time=...)
--   -> Seq Scan on logs_2024_01
--   -> Seq Scan on logs_2024_02
--   -> Seq Scan on logs_2024_03
-- → 2024-01-15 이후 파티션만 스캔!
```

### 동적 파티션 프루닝

```sql
-- 런타임에 파티션 결정
PREPARE stmt AS
SELECT * FROM logs WHERE created_at >= $1 AND created_at < $2;

EXECUTE stmt('2024-01-01', '2024-02-01');
-- logs_2024_01만 스캔

EXECUTE stmt('2024-02-01', '2024-03-01');
-- logs_2024_02만 스캔
```

## 26.4 인덱스와 파티셔닝

### 로컬 인덱스

```sql
-- 각 파티션에 인덱스
CREATE TABLE logs (
  id BIGSERIAL,
  user_id INT,
  action VARCHAR(100),
  created_at TIMESTAMPTZ NOT NULL
) PARTITION BY RANGE (created_at);

CREATE TABLE logs_2024_01 PARTITION OF logs
FOR VALUES FROM ('2024-01-01') TO ('2024-02-01');

-- 파티션에 인덱스
CREATE INDEX idx_logs_2024_01_user_id ON logs_2024_01(user_id);
CREATE INDEX idx_logs_2024_01_action ON logs_2024_01(action);

-- 또는 부모 테이블에 인덱스 (자동으로 모든 파티션에 적용)
CREATE INDEX idx_logs_user_id ON logs(user_id);
-- logs_2024_01, logs_2024_02, ... 모두에 인덱스 생성!
```

### 글로벌 인덱스

```sql
-- PRIMARY KEY (모든 파티션에 걸쳐 고유)
CREATE TABLE orders (
  id BIGSERIAL,
  user_id INT,
  total_amount NUMERIC,
  created_at DATE NOT NULL,
  PRIMARY KEY (id, created_at)  -- 파티션 키 포함 필수!
) PARTITION BY RANGE (created_at);

-- ⚠️ 주의: 파티션 키 없는 PRIMARY KEY는 불가
-- PRIMARY KEY (id)  -- ERROR!
```

## 26.5 파티션 관리

### 파티션 추가

```sql
-- 새로운 파티션 추가
CREATE TABLE logs_2024_04 PARTITION OF logs
FOR VALUES FROM ('2024-04-01') TO ('2024-05-01');

-- 자동으로 부모 테이블의 인덱스도 생성됨
```

### 파티션 삭제

```sql
-- 파티션 분리 (데이터 유지)
ALTER TABLE logs DETACH PARTITION logs_2024_01;
-- logs_2024_01은 이제 독립된 테이블

-- 백업 후 삭제
pg_dump -t logs_2024_01 mydb > logs_2024_01.sql

-- 파티션 삭제
DROP TABLE logs_2024_01;

-- 또는 직접 삭제 (데이터도 삭제)
-- ALTER TABLE logs DROP PARTITION logs_2024_01;  -- PostgreSQL 11-
-- 12+에서는 DETACH 후 DROP
```

### 파티션 연결

```sql
-- 기존 테이블을 파티션으로 연결
CREATE TABLE logs_2024_05 (LIKE logs INCLUDING ALL);

INSERT INTO logs_2024_05 SELECT * FROM old_logs
WHERE created_at >= '2024-05-01' AND created_at < '2024-06-01';

ALTER TABLE logs ATTACH PARTITION logs_2024_05
FOR VALUES FROM ('2024-05-01') TO ('2024-06-01');
```

## 26.6 실전 파티셔닝 예제

### 예제 1: 로그 테이블 (월별)

```sql
-- 로그 테이블 (월별 파티셔닝)
CREATE TABLE event_logs (
  id BIGSERIAL,
  user_id INT,
  event_type VARCHAR(50),
  event_data JSONB,
  ip_address INET,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
) PARTITION BY RANGE (created_at);

-- 2024년 파티션 생성 함수
CREATE OR REPLACE FUNCTION create_monthly_partitions(
  table_name TEXT,
  start_date DATE,
  end_date DATE
) RETURNS VOID AS $$
DECLARE
  partition_date DATE;
  partition_name TEXT;
  start_range TEXT;
  end_range TEXT;
BEGIN
  partition_date := DATE_TRUNC('month', start_date);

  WHILE partition_date < end_date LOOP
    partition_name := table_name || '_' || TO_CHAR(partition_date, 'YYYY_MM');
    start_range := partition_date::TEXT;
    end_range := (partition_date + INTERVAL '1 month')::TEXT;

    EXECUTE format(
      'CREATE TABLE IF NOT EXISTS %I PARTITION OF %I FOR VALUES FROM (%L) TO (%L)',
      partition_name, table_name, start_range, end_range
    );

    partition_date := partition_date + INTERVAL '1 month';
  END LOOP;
END;
$$ LANGUAGE plpgsql;

-- 2024년 파티션 생성
SELECT create_monthly_partitions('event_logs', '2024-01-01', '2025-01-01');

-- 인덱스 추가
CREATE INDEX ON event_logs(user_id);
CREATE INDEX ON event_logs(event_type);
CREATE INDEX ON event_logs USING GIN(event_data);

-- 조회
SELECT * FROM event_logs
WHERE created_at >= '2024-03-01' AND created_at < '2024-04-01'
  AND event_type = 'purchase';
-- event_logs_2024_03만 스캔!
```

### 예제 2: 주문 테이블 (연도별)

```sql
-- 주문 테이블 (연도별 파티셔닝)
CREATE TABLE orders (
  id BIGSERIAL,
  user_id INT NOT NULL,
  total_amount NUMERIC(10, 2) NOT NULL,
  status VARCHAR(20) NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (id, created_at)
) PARTITION BY RANGE (created_at);

-- 연도별 파티션
CREATE TABLE orders_2022 PARTITION OF orders
FOR VALUES FROM ('2022-01-01') TO ('2023-01-01');

CREATE TABLE orders_2023 PARTITION OF orders
FOR VALUES FROM ('2023-01-01') TO ('2024-01-01');

CREATE TABLE orders_2024 PARTITION OF orders
FOR VALUES FROM ('2024-01-01') TO ('2025-01-01');

-- 인덱스
CREATE INDEX ON orders(user_id);
CREATE INDEX ON orders(status);

-- 오래된 데이터 아카이빙
ALTER TABLE orders DETACH PARTITION orders_2022;

-- 백업
pg_dump -t orders_2022 mydb | gzip > orders_2022.sql.gz

-- 삭제
DROP TABLE orders_2022;
```

### 예제 3: 센서 데이터 (시간별)

```sql
-- 센서 데이터 (일별 파티셔닝)
CREATE TABLE sensor_data (
  id BIGSERIAL,
  sensor_id INT NOT NULL,
  temperature NUMERIC(5, 2),
  humidity NUMERIC(5, 2),
  measured_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
) PARTITION BY RANGE (measured_at);

-- 일별 파티션 자동 생성 (pg_cron)
CREATE OR REPLACE FUNCTION create_tomorrow_partition()
RETURNS VOID AS $$
DECLARE
  tomorrow DATE := CURRENT_DATE + 1;
  partition_name TEXT;
BEGIN
  partition_name := 'sensor_data_' || TO_CHAR(tomorrow, 'YYYY_MM_DD');

  EXECUTE format(
    'CREATE TABLE IF NOT EXISTS %I PARTITION OF sensor_data FOR VALUES FROM (%L) TO (%L)',
    partition_name,
    tomorrow,
    tomorrow + 1
  );
END;
$$ LANGUAGE plpgsql;

-- 매일 자정에 다음 날 파티션 생성
SELECT cron.schedule('create-daily-partition', '0 0 * * *',
  'SELECT create_tomorrow_partition()');

-- 오래된 파티션 삭제 (30일 이상)
CREATE OR REPLACE FUNCTION delete_old_partitions(days_to_keep INT)
RETURNS VOID AS $$
DECLARE
  partition_record RECORD;
  cutoff_date DATE := CURRENT_DATE - days_to_keep;
BEGIN
  FOR partition_record IN
    SELECT tablename FROM pg_tables
    WHERE tablename LIKE 'sensor_data_%'
      AND tablename < 'sensor_data_' || TO_CHAR(cutoff_date, 'YYYY_MM_DD')
  LOOP
    EXECUTE format('DROP TABLE IF EXISTS %I', partition_record.tablename);
    RAISE NOTICE 'Dropped partition: %', partition_record.tablename;
  END LOOP;
END;
$$ LANGUAGE plpgsql;

-- 매일 오전 1시에 30일 이상 된 파티션 삭제
SELECT cron.schedule('delete-old-partitions', '0 1 * * *',
  'SELECT delete_old_partitions(30)');
```

## 26.7 서브파티셔닝

### 다단계 파티셔닝

```sql
-- 연도별 → 월별 서브파티셔닝
CREATE TABLE sales (
  id BIGSERIAL,
  product_id INT,
  amount NUMERIC,
  region VARCHAR(50),
  sale_date DATE NOT NULL
) PARTITION BY RANGE (sale_date);

-- 2024년 파티션
CREATE TABLE sales_2024 PARTITION OF sales
FOR VALUES FROM ('2024-01-01') TO ('2025-01-01')
PARTITION BY LIST (region);

-- 2024년 지역별 서브파티션
CREATE TABLE sales_2024_korea PARTITION OF sales_2024
FOR VALUES IN ('Korea');

CREATE TABLE sales_2024_usa PARTITION OF sales_2024
FOR VALUES IN ('USA');

CREATE TABLE sales_2024_others PARTITION OF sales_2024
DEFAULT;

-- 데이터 삽입
INSERT INTO sales (product_id, amount, region, sale_date)
VALUES (100, 50000, 'Korea', '2024-03-15');
-- sales_2024_korea에 삽입!
```

## 26.8 파티셔닝 성능

### 성능 비교

```sql
-- 비파티션 테이블 (1억 건)
CREATE TABLE logs_normal (
  id BIGSERIAL PRIMARY KEY,
  user_id INT,
  action VARCHAR(100),
  created_at TIMESTAMPTZ
);

CREATE INDEX idx_logs_normal_created ON logs_normal(created_at);

-- 조회
EXPLAIN ANALYZE
SELECT * FROM logs_normal
WHERE created_at >= '2024-01-01' AND created_at < '2024-02-01';
-- Execution Time: 850 ms


-- 파티션 테이블 (1억 건, 월별 파티션)
CREATE TABLE logs_partitioned (
  id BIGSERIAL,
  user_id INT,
  action VARCHAR(100),
  created_at TIMESTAMPTZ NOT NULL
) PARTITION BY RANGE (created_at);

-- 12개 파티션 생성 (월별)
-- ...

CREATE INDEX ON logs_partitioned(created_at);

-- 조회
EXPLAIN ANALYZE
SELECT * FROM logs_partitioned
WHERE created_at >= '2024-01-01' AND created_at < '2024-02-01';
-- Execution Time: 70 ms
-- 12배 빠름!
```

### 인덱스 크기 비교

```sql
-- 비파티션 테이블
SELECT pg_size_pretty(pg_total_relation_size('logs_normal'));
-- 15 GB

SELECT pg_size_pretty(pg_relation_size('idx_logs_normal_created'));
-- 3 GB


-- 파티션 테이블
SELECT pg_size_pretty(pg_total_relation_size('logs_partitioned'));
-- 15 GB (데이터 크기 동일)

-- 파티션별 인덱스 크기
SELECT
  tablename,
  pg_size_pretty(pg_relation_size(indexrelid)) AS index_size
FROM pg_stat_user_indexes
WHERE tablename LIKE 'logs_partitioned_%'
ORDER BY tablename;
-- 각 파티션: 250 MB
-- 총합: 3 GB (동일하지만 각각 작음)
```

## 26.9 파티셔닝 제약사항

### 제약사항

```sql
-- ⚠️ PRIMARY KEY는 파티션 키 포함 필수
CREATE TABLE orders (
  id BIGSERIAL,
  created_at DATE NOT NULL,
  PRIMARY KEY (id, created_at)  -- 파티션 키 포함!
) PARTITION BY RANGE (created_at);

-- ❌ 불가
-- PRIMARY KEY (id)  -- ERROR


-- ⚠️ UNIQUE도 파티션 키 포함 필수
CREATE TABLE users (
  id SERIAL,
  email VARCHAR(255),
  country VARCHAR(50),
  UNIQUE (email, country)  -- 파티션 키 포함!
) PARTITION BY LIST (country);


-- ⚠️ FOREIGN KEY 제약
-- 파티션 테이블에서 다른 테이블로: 가능
-- 다른 테이블에서 파티션 테이블로: 불가 (PostgreSQL 15까지)
```

## 26.10 파티셔닝 vs 샤딩

### 차이점

```
파티셔닝 (Partitioning):
- 단일 서버
- 수직 분할 (같은 DB 내)
- PostgreSQL 내장 기능
- 관리 쉬움

샤딩 (Sharding):
- 여러 서버
- 수평 분할 (다른 DB로)
- 애플리케이션 레벨
- 관리 복잡
- 확장성 높음
```

## 핵심 요약

### 파티셔닝 방법

```sql
-- Range (범위): 날짜, 숫자
PARTITION BY RANGE (created_at)

-- List (목록): 국가, 카테고리
PARTITION BY LIST (country)

-- Hash (해시): 균등 분산
PARTITION BY HASH (user_id)
```

### 파티션 생성

```sql
-- Range
CREATE TABLE logs_2024_01 PARTITION OF logs
FOR VALUES FROM ('2024-01-01') TO ('2024-02-01');

-- List
CREATE TABLE users_korea PARTITION OF users
FOR VALUES IN ('Korea');

-- Hash
CREATE TABLE events_p0 PARTITION OF events
FOR VALUES WITH (MODULUS 4, REMAINDER 0);
```

### 파티션 관리

```sql
-- 추가
CREATE TABLE logs_2024_04 PARTITION OF logs
FOR VALUES FROM ('2024-04-01') TO ('2024-05-01');

-- 분리
ALTER TABLE logs DETACH PARTITION logs_2024_01;

-- 삭제
DROP TABLE logs_2024_01;

-- 연결
ALTER TABLE logs ATTACH PARTITION logs_2024_05
FOR VALUES FROM ('2024-05-01') TO ('2024-06-01');
```

### 사용 시나리오

```
✅ 파티셔닝 적합:
- 시계열 데이터 (로그, 이벤트)
- 대용량 테이블 (수억 건)
- 정기적 삭제/아카이빙
- 날짜 범위 쿼리

❌ 파티셔닝 부적합:
- 작은 테이블
- 파티션 키 없는 쿼리
- 복잡한 JOIN
```
