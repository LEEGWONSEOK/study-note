# Chapter 27. 커넥션 풀링

## 27.1 커넥션 풀링이란?

### 정의

```
커넥션 풀링 (Connection Pooling):
데이터베이스 연결을 미리 생성하고 재사용하는 기술

비유: 택시 vs 버스
┌─────────────────────────────────┐
│ ❌ 커넥션 풀링 없음 (택시):     │
│ - 요청마다 새 연결 생성         │
│ - 느림 (연결 비용 큼)           │
│ - 자원 낭비                     │
│                                 │
│ ✅ 커넥션 풀링 (버스):          │
│ - 미리 생성된 연결 재사용       │
│ - 빠름                          │
│ - 자원 효율적                   │
└─────────────────────────────────┘

커넥션 풀 = 연결 재사용으로 성능 향상
```

### 커넥션 생성 비용

```sql
-- 커넥션 생성 과정 (비용이 큼!)
1. TCP 연결 (3-way handshake)
2. PostgreSQL 인증
3. 세션 초기화
4. 메모리 할당

-- 시간: 10-50ms (네트워크에 따라)

-- 요청당 새 연결 생성 시:
-- 1000 TPS × 20ms = 20초 (커넥션 생성만!)
-- → 심각한 성능 저하

-- 커넥션 풀 사용 시:
-- 연결 재사용 → 커넥션 생성 시간 0ms
-- → 성능 대폭 향상!
```

## 27.2 PgBouncer

### PgBouncer란?

```
PgBouncer:
PostgreSQL을 위한 경량 커넥션 풀러

특징:
- 매우 가볍고 빠름
- 메모리 사용량 적음 (연결당 2KB)
- 3가지 풀링 모드
- 프로덕션 표준
```

### 설치

```bash
# Ubuntu/Debian
sudo apt-get install pgbouncer

# macOS
brew install pgbouncer

# Docker
docker run -d \
  --name pgbouncer \
  -p 6432:6432 \
  -v /path/to/pgbouncer.ini:/etc/pgbouncer/pgbouncer.ini \
  pgbouncer/pgbouncer
```

### 기본 설정

```ini
# /etc/pgbouncer/pgbouncer.ini

[databases]
mydb = host=localhost port=5432 dbname=mydb

[pgbouncer]
listen_addr = 0.0.0.0
listen_port = 6432
auth_type = md5
auth_file = /etc/pgbouncer/userlist.txt

# 풀링 모드
pool_mode = transaction

# 커넥션 수
max_client_conn = 1000
default_pool_size = 25
reserve_pool_size = 5

# 로그
logfile = /var/log/pgbouncer/pgbouncer.log
pidfile = /var/run/pgbouncer/pgbouncer.pid
```

### 사용자 인증 파일

```bash
# /etc/pgbouncer/userlist.txt
"myuser" "md5password_hash"

# 패스워드 해시 생성
echo -n "passwordmyuser" | md5sum
# 또는
psql -Atq -U postgres -d mydb -c "SELECT concat('\"', usename, '\" \"', passwd, '\"') FROM pg_shadow WHERE usename = 'myuser'"
```

### 시작/중지

```bash
# 시작
pgbouncer -d /etc/pgbouncer/pgbouncer.ini

# 중지
pgbouncer -R -d /etc/pgbouncer/pgbouncer.ini

# 재시작 (연결 유지)
kill -HUP $(cat /var/run/pgbouncer/pgbouncer.pid)

# 상태 확인
psql -h localhost -p 6432 -U pgbouncer pgbouncer
pgbouncer=# SHOW STATS;
pgbouncer=# SHOW POOLS;
pgbouncer=# SHOW SERVERS;
```

## 27.3 풀링 모드

### Session Mode (세션 모드)

```ini
pool_mode = session

# 특징:
# - 클라이언트 연결 시 서버 연결 할당
# - 클라이언트 연결 종료 시 서버 연결 풀로 반환
# - 모든 PostgreSQL 기능 사용 가능
# - 풀링 효과 적음

# 사용 예:
# - Prepared Statements
# - LISTEN/NOTIFY
# - 임시 테이블
```

### Transaction Mode (트랜잭션 모드) ⭐

```ini
pool_mode = transaction

# 특징:
# - 트랜잭션 종료 시 서버 연결 풀로 반환
# - 높은 풀링 효과
# - 가장 일반적

# 제약사항:
# - Prepared Statements 제한적
# - SET 명령 제한
# - 임시 테이블 사용 불가

# 권장: 대부분의 경우
```

### Statement Mode (문장 모드)

```ini
pool_mode = statement

# 특징:
# - 쿼리 하나 실행 후 즉시 반환
# - 가장 높은 풀링 효과
# - 가장 많은 제약

# 제약사항:
# - 트랜잭션 불가
# - 다중 쿼리 불가
# - Prepared Statements 불가

# 사용 예:
# - 읽기 전용 단순 쿼리
```

## 27.4 커넥션 수 설정

### 적정 커넥션 수 계산

```
공식:
max_connections (PostgreSQL) = (CPU 코어 수 × 2) + 디스크 수

예:
- 4 코어 CPU, 1 디스크
- max_connections = 4 × 2 + 1 = 9

PgBouncer:
default_pool_size = max_connections / 애플리케이션 인스턴스 수

예:
- max_connections = 100
- 애플리케이션 인스턴스 = 4
- default_pool_size = 100 / 4 = 25
```

### PgBouncer 설정

```ini
# /etc/pgbouncer/pgbouncer.ini

[pgbouncer]
# 클라이언트 최대 연결 수
max_client_conn = 1000

# 데이터베이스당 서버 연결 수
default_pool_size = 25

# 예약 풀 (대기 시 추가 연결)
reserve_pool_size = 5

# 최대 대기 시간
reserve_pool_timeout = 5

# 서버 연결 수명
server_lifetime = 3600

# 서버 유휴 시간
server_idle_timeout = 600
```

### PostgreSQL 설정

```sql
-- postgresql.conf
max_connections = 100

-- 확인
SHOW max_connections;

-- 현재 연결 수
SELECT count(*) FROM pg_stat_activity;

-- 연결 상태
SELECT
  datname,
  count(*) AS connections,
  max_connections
FROM pg_stat_activity, (SELECT setting::int AS max_connections FROM pg_settings WHERE name = 'max_connections') mc
GROUP BY datname, max_connections
ORDER BY connections DESC;
```

## 27.5 애플리케이션 연동

### Node.js (pg)

```javascript
// PgBouncer 사용
const { Pool } = require('pg');

const pool = new Pool({
  host: 'localhost',
  port: 6432,  // PgBouncer 포트
  database: 'mydb',
  user: 'myuser',
  password: 'mypassword',
  max: 20,  // 애플리케이션 풀 크기
  idleTimeoutMillis: 30000,
  connectionTimeoutMillis: 2000,
});

// 사용
async function getUser(id) {
  const client = await pool.connect();
  try {
    const result = await client.query('SELECT * FROM users WHERE id = $1', [id]);
    return result.rows[0];
  } finally {
    client.release();  // 중요: 반드시 반환!
  }
}

// 트랜잭션
async function transferMoney(fromId, toId, amount) {
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    await client.query('UPDATE accounts SET balance = balance - $1 WHERE id = $2', [amount, fromId]);
    await client.query('UPDATE accounts SET balance = balance + $1 WHERE id = $2', [amount, toId]);
    await client.query('COMMIT');
  } catch (e) {
    await client.query('ROLLBACK');
    throw e;
  } finally {
    client.release();
  }
}
```

### Python (psycopg2)

```python
import psycopg2
from psycopg2 import pool

# 커넥션 풀 생성
connection_pool = psycopg2.pool.ThreadedConnectionPool(
    minconn=1,
    maxconn=20,
    host='localhost',
    port=6432,  # PgBouncer
    database='mydb',
    user='myuser',
    password='mypassword'
)

# 사용
def get_user(user_id):
    conn = connection_pool.getconn()
    try:
        with conn.cursor() as cur:
            cur.execute('SELECT * FROM users WHERE id = %s', (user_id,))
            return cur.fetchone()
    finally:
        connection_pool.putconn(conn)

# 트랜잭션
def transfer_money(from_id, to_id, amount):
    conn = connection_pool.getconn()
    try:
        conn.autocommit = False
        with conn.cursor() as cur:
            cur.execute('UPDATE accounts SET balance = balance - %s WHERE id = %s', (amount, from_id))
            cur.execute('UPDATE accounts SET balance = balance + %s WHERE id = %s', (amount, to_id))
        conn.commit()
    except Exception as e:
        conn.rollback()
        raise
    finally:
        connection_pool.putconn(conn)
```

## 27.7 트러블슈팅

### 문제 1: 연결 대기

```sql
-- 증상
SHOW POOLS;
--  cl_active | cl_waiting | sv_active | sv_idle
-- -----------+------------+-----------+---------
--     100    |     50     |    25     |    0
-- 클라이언트 대기 중!

-- 원인
-- default_pool_size가 너무 작음

-- 해결
# pgbouncer.ini
default_pool_size = 50  # 25 → 50으로 증가
reserve_pool_size = 10

# 재시작
pgbouncer -R /etc/pgbouncer/pgbouncer.ini
```

### 문제 2: Prepared Statement 에러

```
ERROR: prepared statement "stm_1" does not exist

# 원인
# Transaction Mode에서 Prepared Statement 사용

# 해결 1: Session Mode로 변경
pool_mode = session

# 해결 2: 애플리케이션에서 일반 쿼리 사용
# Prepared Statement 대신 파라미터화된 쿼리
```

### 문제 3: 임시 테이블 에러

```
ERROR: relation "temp_table" does not exist

# 원인
# Transaction Mode에서 임시 테이블 사용 불가

# 해결: Session Mode로 변경
pool_mode = session

# 또는: 일반 테이블 사용
CREATE TABLE temp_data_123 (...);
-- 작업 후 삭제
DROP TABLE temp_data_123;
```

## 27.9 대안: pgpool-II

### pgpool-II 특징

```
pgpool-II:
- 커넥션 풀링
- 로드 밸런싱
- 레플리케이션
- 쿼리 캐싱

vs PgBouncer:
- PgBouncer: 가볍고 빠름, 커넥션 풀링만
- pgpool-II: 무겁지만 기능 많음
```

### 기본 설정

```bash
# 설치
sudo apt-get install pgpool2

# 설정
# /etc/pgpool-II/pgpool.conf
listen_addresses = '*'
port = 9999

# 백엔드 서버
backend_hostname0 = 'localhost'
backend_port0 = 5432
backend_weight0 = 1

# 커넥션 풀
num_init_children = 32
max_pool = 4

# 로드 밸런싱
load_balance_mode = on
```

## 27.10 베스트 프랙티스

### 애플리케이션 레벨

```javascript
// ✅ 연결 반환 보장
async function query(sql, params) {
  const client = await pool.connect();
  try {
    return await client.query(sql, params);
  } finally {
    client.release();  // 항상 반환!
  }
}

// ❌ 연결 누수
async function badQuery(sql, params) {
  const client = await pool.connect();
  return await client.query(sql, params);
  // client.release() 없음 → 연결 누수!
}

// ✅ 타임아웃 설정
const pool = new Pool({
  connectionTimeoutMillis: 5000,  // 연결 타임아웃
  idleTimeoutMillis: 30000,        // 유휴 타임아웃
  statement_timeout: 10000,        // 쿼리 타임아웃
});
```

### PgBouncer 레벨

```ini
# 적정 풀 크기

# 타임아웃 설정

query_wait_timeout = 120

# 로그

log_pooler_errors = 1
```

## 핵심 요약

### 커넥션 풀링

```
장점:
- 연결 재사용 → 빠른 응답
- 자원 효율적
- 동시성 향상

단점:
- 설정 복잡성
- 모니터링 필요
```

### PgBouncer 풀링 모드

```
Session Mode:
- 모든 기능 사용 가능
- 풀링 효과 적음

Transaction Mode: ⭐ (권장)
- 높은 풀링 효과
- 대부분의 경우 사용

Statement Mode:
- 최고 풀링 효과
- 제약 많음
```

### 커넥션 수 설정

```
PostgreSQL:
max_connections = (CPU 코어 × 2) + 디스크 수

PgBouncer:
default_pool_size = max_connections / 앱 인스턴스 수

애플리케이션:
pool_size = 적정 수 (보통 10-20)
```
